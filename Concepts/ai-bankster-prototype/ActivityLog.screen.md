# Журнал действий

## 1. Назначение

Прослеживаемость действий с запросами и материалами: без неё инструмент не
допускается к эксплуатации. Экран показывает записи журнала и даёт их выгрузку
уполномоченным сотрудникам (БТ-11.1, БТ-11.3).

**Роль пользователя:** уполномоченный сотрудник (контроль, информационная
безопасность, владелец продукта).
**Права:** доступ к журналу отдельный от доступа к самим материалам (БТ-9).

## 4. Структура контента

Экран-реестр: `.screen--app` на рабочей области, `.dtable--fill` на таблице,
вертикальный ритм 12px. Единственный контентный блок — таблица.

## 5. Таблица «Записи журнала»

**Тулбар:** слева TableFilter с чипом «Применено: 1», справа кнопка настройки
колонок. Заголовка и счётчика у таблицы нет — по решению заказчика (13.09.2026);
число записей за выбранный период остаётся в футере таблицы. Штатное наполнение
`.dtable__toolbar` — заголовок слева, фильтр справа; раскладка «фильтр слева,
настройка справа» повторяет вариант ДС «тулбар над таблицей» (`.dtable-toolbar`),
но остаётся внутри подложки таблицы.

| Ключ | Заголовок | Тип | Ширина | Выравн. | Сортировка |
|---|---|---|---|---|---|
| `date` | Дата | дата | 150px | слева | да, активна по убыванию |
| `time` | Время | текст | 100px | слева | нет |
| `user` | Сотрудник | текст | minmax(0,1.6fr) | слева | да |
| `action` | Действие | текст + иконка | 220px | слева | нет |
| `details` | Объект и подробности | текст | minmax(0,2.2fr) | слева | нет |
| `result` | Результат | Chip | 150px | слева | нет |

**Фиксируемые действия (БТ-11.1)** и их глифы:

| Действие | Глиф |
|---|---|
| Создание запроса | `add` |
| Загрузка файлов | `attach` |
| Подготовка материала | `ai-stars` |
| Выгрузка материала | `download` |
| Предоставление доступа | `user-circle` |
| Удаление запроса | `trash` |
| Вызов из рабочего места | `link-external` |

**Результат** — чипом: `chip--success` «Успешно», `chip--warning` «Полнота
ограничена» / «2 из 3», `chip--error` «Ошибка».

Дата и время разнесены по колонкам: дата в формате `ДД.ММ.ГГГГ` сортируется
рантаймом таблицы, время остаётся справочным значением.

## 6. Поведение

| Триггер | Результат |
|---|---|
| Клик по кнопке сортировки | цикл: нет → по возрастанию → по убыванию → нет |
| Клик «Фильтр» | модалка фильтра `.tfm` с разделами «Общая информация» и «Даты» |
| Клик по разделу в модалке | прокрутка к разделу, раздел помечается текущим |
| Крестик на чипе «Применено» | сброс всех параметров фильтра |
| Клик по шестерёнке | модалка «Настройка таблицы», строит рантайм ДС |
| «Правила хранения» | модалка со сроками хранения и правилами обработки |
| «Выгрузить журнал» | SnackBar: число записей за период, файл промаркирован, сама выгрузка записана в журнал |

## 7. Модальные окна

| id | Заголовок | Ширина | Содержимое | Кнопки подвала |
|---|---|---|---|---|
| `logfilter-scrim` | Фильтр | `--w6` `.tfm` | сотрудник, объект анализа, действие (чекбоксы), период записей (InputDateRange) | «Очистить фильтр», «Применить» |
| `retention-scrim` | Правила хранения и обработки | `--w5` | сроки по видам данных, что фиксируется, обучение моделей и контур обработки | «Понятно» |

**Сроки в модалке (БТ-11.2, БТ-11.4):** записи журнала — 5 лет; запросы и
диалоги — 3 года с последнего обращения; приложенные файлы — вместе с запросом;
удалённые запросы — 30 дней в корзине.

## 10. Доступность

- единственный `h1` — заголовок страницы;
- сортировка объявлена через `aria-sort`;
- у всех кнопок-иконок есть `aria-label`;
- ручка изменения ширины колонки — `role="separator"` с `tabindex`;
- видимого заголовка у таблицы нет, имя области задано на `.dtable`: `role="region" aria-label="Записи журнала"`.

## 11. Скрипт экрана

Сортировка, колонки, настройка колонок, модалки и выпадающие списки живут на
рантаймах ДС. Собственный скрипт делает только якорные переходы по разделам
модалки фильтра (ДС оставляет их потребителю) и сообщение о выгрузке журнала.

## 13. Дефекты ДС, найденные при сборке

Файлы ДС не изменялись. Полный разбор — в `RequestHistory.screen.md`, раздел 15.

| № | Компонент | Симптом | Обход на экране |
|---|---|---|---|
| 1 | Table / TableCell | Колонки не совпадают по вертикали между строками, длинный текст не усекается | Треки `minmax(0,Nfr)` + `.dtable__body .tbl__row { min-width: 100% }` |
| 2 | Pagination | Хук `data-pagination` рисует демо-дефолт независимо от `data-total` | Пагинатор собран разметкой по `patterns.md` |
| 3 | TableFilter | `.tfilter` с `width:100%` выталкивает шестерёнку на вторую строку, когда стоит с ней в одной зоне тулбара | не требуется: фильтр стоит в левой зоне один и берёт ширину по содержимому. Обход остаётся на экране «История и материалы» |
| 4 | Table (тулбар) | Без заголовка и счётчика кнопка настройки колонок встаёт на 6px ниже фильтра | `.dtable__toolbar { align-items: center }` в `<style>` экрана: в ДС зоны выровнены по нижнему краю под двухстрочный заголовок, варианта тулбара без заголовка внутри подложки нет. Центр — как у варианта ДС «тулбар над таблицей» |
| 5 | Tile (сетка полей) | В модалке «Правила хранения и обработки» ряды полей слипались, между колонками тоже не было зазора | `.tile__grid` берёт зазоры из `--tile-gap-row` / `--tile-gap-col`, а их задаёт только тайл; в модалке переменные не определены | `.modal__body > .tile__grid` получает эти переменные = `--space-24` в `<style>` экрана |
