# История и материалы

## 1. Назначение

Перечень запросов пользователя и созданных материалов. Повторное обращение к
запросу должно быть дешевле создания нового: отсюда открывается нить с полным
контекстом, перезапускается подготовка и выгружается любая версия материала.

**Роль пользователя:** сотрудник инвестиционного департамента.
**Права:** по умолчанию видны только собственные запросы и материалы (БТ-4.10, БТ-9.2).

## 7. Поведение

| Триггер | Результат |
|---|---|
| Клик по табу | переключается представление, таблица сохраняет свою сортировку |
| Клик по кнопке сортировки | цикл: нет → по возрастанию → по убыванию → нет; активна максимум одна колонка в таблице |
| Перетаскивание правой границы шапки | изменение ширины колонки, минимум 96px |
| Перетаскивание подписи шапки | изменение порядка колонок |
| Клик по шестерёнке | модалка «Настройка таблицы» (Modal `--w4`), строит рантайм ДС по колонкам шапки |
| Клик «Фильтр» | модалка фильтра `.tfm` (Modal `--w6`) |
| Клик по разделу в модалке фильтра | прокрутка к разделу, раздел помечается текущим |
| Применён фильтр | в баре чип «Применено: N»; крестик чипа сбрасывает фильтр целиком |
| Чеврон рядом с «Фильтр» | меню сохранённых пресетов |
| Выбор строк чекбоксами | появляется панель массовых действий над пагинацией |
| «Открыть» в строке | переход в нить запроса с полным контекстом (БТ-4.3, БТ-4.4) |
| «Перезапустить» в строке | SnackBar: новая версия по прежним вводным, предыдущие сохраняются (БТ-4.5) |
| «Удалить» | подтверждение, затем SnackBar с действием «Отменить» — удаление обратимо (БТ-4.8) |
| «Корзина» в шапке | список удалённых с датой окончательного стирания и кнопкой «Восстановить» |
| «Открыть материал» в строке «Материалов», пункт меню «Открыть материал и версии» | превью материала в модальном окне (раздел 8) |
| «Перейти в нить» в превью | нить запроса с полным контекстом |

фильтра («Применено: 2»), правило описано словами.

## 12. Доступность

- единственный `h1` — заголовок страницы;
- табы — `role="tablist"` / `role="tab"` с `aria-selected`;
- сортировка объявлена через `aria-sort` на ячейке шапки;
- у всех кнопок-иконок есть `aria-label`;
- счётчик выбранных строк — `aria-live="polite"`;
- ручка изменения ширины колонки — `role="separator"` с `tabindex`;
- видимых заголовков у таблиц нет, имена областей заданы на `.dtable`: `role="region"` и `aria-label` «Запросы и диалоги» / «Материалы».

## 13. Скрипт экрана

Сортировка, порядок и ширина колонок, настройка колонок, модалки, меню и
выпадающие списки живут на рантаймах ДС. Собственный скрипт закрывает только:
переключение двух панелей по `data-pane`, счётчик выбранных строк и показ панели
массовых действий, якорные переходы по разделам модалки фильтра (ДС оставляет
их потребителю), сообщения о перезапуске, выгрузке и обратимом удалении.
Скрипт превью материала идёт отдельным тегом сразу за разметкой окна
(`RequestThread.screen.md`, раздел 9).

## 15. Дефекты ДС, найденные при сборке

Файлы ДС не изменялись. Каждый обход описан комментарием в `<style>` экрана.

| № | Компонент | Симптом | Причина | Обход на экране |
|---|---|---|---|---|
| 1 | **Table / TableCell** | Колонки не совпадают по вертикали между строками; длинный текст не усекается, а расширяет строку | У строки прокручиваемой таблицы объявлено `min-width: max-content` (условие работы закрепления колонок). Вместе с резиновыми треками `Nfr` это даёт каждой строке собственную ширину. Воспроизводится и на эталонном экране `Projects/test/FundList.html`: ширины строк 1144…1876px при скроллпорте 1089px | Треки объявлены как `minmax(0,Nfr)`, в `<style>` экрана — `.dtable__body .tbl__row { min-width: 100% }`. Горизонтального скролла у этих таблиц нет, поэтому закрепление колонок ничего не теряет |
| 2 | **Pagination** | Хук `data-pagination` рисует демо-дефолт «1 из 16» независимо от `data-total` / `data-page-size` | `boot()` кладёт значения в плоский объект `{total, page, pageSize}`, а `buildRow()` ждёт их во вложенном `o.pager`. Проверено: `DSPagination.footer({total:8,pageSize:50})` → «1 из 16», `DSPagination.footer({pager:{total:8,pageSize:50}})` → «1 из 1» | Пагинатор собран разметкой по `screen-assembly/references/patterns.md`, хук не используется |
| 3 | **TableFilter** | В одной строке с соседним элементом фильтр забирает всю ширину: шестерёнка или поле поиска уходят на вторую строку | `.tfilter` объявлен с `width: 100%` и рассчитан на всю зону тулбара, хотя штатный состав по `patterns.md` — фильтр + шестерёнка + кнопка действия | В `<style>` экрана — `.hst-tools > .tfilter { width: auto }`: фильтр стоит в строке с поиском |
| 4 | **Table** (тулбар) | Без заголовка и счётчика кнопка настройки колонок встаёт ниже фильтра, а поиск и фильтр не выстраиваются в строку | Зоны `.dtable__toolbar` выровнены по нижнему краю под двухстрочный блок заголовка, левая зона — flex-колонка; варианта тулбара без заголовка внутри подложки в ДС нет | В `<style>` экрана — `.dtable__toolbar { align-items: center }` и обёртка строки `.hst-tools`; центр — как у варианта ДС «тулбар над таблицей» |

Классы находок: №1 и №3 — «правило есть, вход не тот» (Л48), №2 — «правило
записано, кода нет» (Л42).

## 16. Ограничения статического сенсора приёмки

`layout-check.mjs` выдаёт на этом экране одно замечание З2 «сортировка активна
у 2 колонок». Сенсор считает сортировку по всей странице, а на экране две
независимые таблицы в двух представлениях, у каждой своя активная колонка.
Заявленное состояние подтверждается данными: строки обеих таблиц упорядочены по
убыванию даты обновления (требование Б27).
