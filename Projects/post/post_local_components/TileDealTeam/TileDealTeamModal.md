# Модальное окно команды сделки

## Описание

Артефакт тайла «Команда сделки». Не компонент: сам по себе не существует и в
плоском списке кита не числится — живёт подпунктом своего тайла.

Здесь весь состав команды: деск, двенадцать ролей, «Другие участники» и признак
ограниченного доступа. Тайл показывает только шесть строк, поэтому окно — это и
правка, и единственное место, где состав виден целиком.

Ширина — `modal--w7` (1053px на 1920), ровно ширина макета. Поля стоят в штатной
сетке ДС (`.grid12`, поле `.col-4`) в три колонки; собственного CSS раскладки у
окна нет — только переключение режима.

## Состав

Порядок в разметке построчный, он же порядок чтения: сетка заполняется
построчно, а не по колонкам.

| Ряд | Колонка 1 | Колонка 2 | Колонка 3 |
|---|---|---|---|
| 1 | Деск \* | Клиентский менеджер | Сотрудник ПМЗ |
| 2 | Директор | Кредитный инспектор | Сотрудник ПРПА |
| 3 | Региональный директор | Сотрудник Рисков | Сотрудник Юридической службы |
| 4 | Менеджер сделки | Сотрудник Мониторинга | Строительный эксперт |
| 5 | Сотрудник ЦУП | | |

Под сеткой во всю ширину — «Другие участники», ниже — чекбокс «Сделка
ограниченного доступа». Подвал: одна кнопка справа.

| Поле | Чем собрано | Источник значений |
|---|---|---|
| Деск | InputAutocomplete + DropdownList | справочник десков `DEALS_ENUMS.desk` |
| Двенадцать ролей | InputAutocomplete + DropdownList | справочник сотрудников `MOCK_TEAM_ROSTER` |
| Другие участники | InputText во всю ширину | свободный ввод |
| Сделка ограниченного доступа | Checkbox | признак сделки `deal.restricted` |

У каждого поля ввода справа — свои действия: крестик очистки (у заполненного) и
шеврон списка (у тринадцати списков; у «Других участников» шеврона нет, это не
список). Крестик и шеврон стоят рядом — у поля они не взаимоисключающие
(инвариант InputAutocomplete).

## Правила состава и проверки

- **«Другие участники» — не список, а строка.** Сюда вписывают людей **не из
  банка**: справочника для них нет и быть не может. Несколько участников — через
  запятую (заказчик 23.09.2026). Поле легко принять за такой же селект, как
  соседние, — оно им не является и не должно им стать.
- **Рядом с ФИО — табельный номер.** В списке он стоит под именем и показывается
  просто числом, без подписи; когда сотрудник выбран, номер виден в поле за
  именем — «Андреев М.А. 100101» (заказчик 23.09.2026). По нему различают
  однофамильцев: в демо-справочнике для этого есть два разных «Смирнов А.А.».
  У списка десков номера нет — деск не человек.
- **Имя и номер хранятся порознь.** Роль хранит чистое ФИО, её пара
  `<роль>Tab` — номер (`directorTab`, `managerTab` и так далее). Так реестр
  портфеля и тайл, читающие те же поля роли, продолжают показывать имя без
  номера — как на макете. Склейка для показа и разбор обратно — `personValue` и
  `splitPerson` в `TileDealTeamModal.js`: хвостовая группа цифр считается
  номером. Набрали имя руками, не выбрав из списка, — номер остаётся пустым, а
  не подставляется наугад.
- **Деск обязателен всегда**, звёздочка у подписи. «Сохранить» с пустым деском
  не закрывает окно: поле помечается ошибкой (`inp--error` плюс хелпер), фокус
  уходит в него.
- **Остальные роли обязательны по деску.** Какие именно — зависит от выбранного
  деска: у одного одно поле, у другого несколько. При смене деска звёздочки
  переставляются сразу. Конкретные пары — `не решено (23.09.2026)`, у владельца
  продукта; до них в `data/mock-team.js` лежит один демо-случай
  (`MOCK_DESK_REQUIRED`), помеченный как демо. Механика от состава карты не
  зависит: дописываются пары, код не трогается.
- **Заполнять все поля не нужно** — у разных сделок свой обязательный состав.
- **Списки собираются кодом.** Справочник — 36 человек на каждое из тринадцати
  полей; в разметке это больше четырёхсот строк одного и того же списка. Опции
  подставляет `TileDealTeamModal.js`, открытие, клавиатуру и выбор ведёт рантайм
  `DSDropdownList` — своей копии его логики в окне нет.
- **Поля занимают свою колонку целиком.** У `.inp` в ДС зашита ширина `280px`
  («дефолт для доков»), поэтому каждому полю нужен `inp--fullwidth` — без него
  поле не растягивается по колонке и правый край ряда рвётся.
- **Крестик очистки есть у каждого заполненного поля** — обязательная часть
  поля ввода, не опция окна. В разметке его нет намеренно: по правилу ДС
  крестик живёт по значению, и рисует его рантайм `ds-input.js` ровно тогда,
  когда в поле есть значение; нарисованный руками, он висел бы и на пустом
  поле. Зато значение, поставленное **кодом**, рантайм сам не видит —
  присваивание `.value` событий не шлёт, — поэтому `fillEdit` в конце зовёт
  `DSInput.syncAll(scrim)`. Выбор из списка синхронизирует сам DropdownList
  (1.014), звать его в `onSelect` не нужно.
- **Очистка деска снимает звёздочки.** Обязательность ролей считается по
  деску, поэтому окно слушает `input` на поле деска: событие приходит и от
  крестика, и от ручного ввода, и обязательные роли пересчитываются сразу.
- **Прочерк в просмотре — цветом обычного текста** (ReadOnlyField 1.010):
  незаполненная роль — это значение «не назначена», а не подсказка.
- **Кто доступен для какой роли** — `не решено (23.09.2026)`: сейчас каждый
  список показывает весь справочник.

## Состояния

| Состояние | Есть в продукте | Вид |
|---|---|---|
| Правка (`data-mode="edit"`) | да | тринадцать списков, «Другие участники», чекбокс; у каждого заполненного поля — крестик очистки; подвал — «Сохранить» |
| Просмотр (`data-mode="view"`) | да | те же поля и в том же порядке как ReadOnlyField, незаполненное прочерком; признак остаётся чекбоксом, выключенным; подвал — аутлайновая «Закрыть» |
| Ошибка проверки | да | пустой деск при сохранении: поле в `inp--error`, хелпер «Выберите деск — поле обязательное», окно остаётся открытым |
| Загрузка | нет | окно открывается по готовым данным сделки — они уже на странице |
| Сохранение | не решено (23.09.2026) | у ДС есть `modal--saving`; нужно ли оно здесь, зависит от того, ходит ли сохранение на сервер |
| Ошибка сохранения | не решено (23.09.2026) | место под неё в ДС есть — `modal__alert` |

Режим ставит `TileDealTeamModal.js` в момент открытия — по `data-mode` тайла,
который окно открыл. Само окно роль и статус не вычисляет.

**Почему подвал не прячется в просмотре.** Подвал модалки обязателен (правило
Modal). Править в просмотре нечего, поэтому меняется кнопка, а не исчезает
подвал: «Сохранить» — залитая, «Закрыть» — аутлайновая. Заливка обещала бы
действие, которого в просмотре нет; так же сделано у окна КНР
(`TileKNRModal`, 20.09.2026).

**Почему признак остался чекбоксом.** В просмотре его не подменяют читаемой
строкой «Да» / «Нет»: отметка показывает состояние сама, а строка заставляет
прочитать слово и сопоставить его с тем, о чём речь. Выключенный чекбокс — это
и есть вид «смотреть можно, менять нельзя». Поэтому чекбокс стоит рядом с
обоими блоками режимов, а не внутри каждого (решение человека 23.09.2026).

## Права

| Роль | Просмотр | Редактирование |
|---|---|---|
| Финансист ДИД | да | не решено (19.09.2026) |
| Руководитель ЦУП | не решено (23.09.2026) | единственный, кто меняет признак ограниченного доступа |

**Признак ограниченного доступа** видят все роли, а меняет только руководитель
ЦУП — остальным чекбокс выключен (заказчик 23.09.2026). Это право уровня поля, а
не компонента: оно не смешивается с `data-mode` окна и не отменяет правило
«выключенных действий не бывает» — то правило про точки входа в правку, а не про
поля внутри формы. Право приходит снаружи параметром `canEditRestricted`: окно
роль не вычисляет.

Роли «Руководитель ЦУП» в каталоге `IBPHome.ROLES` пока нет — объявлена одна,
«Финансист ДИД». Поэтому на странице сделки чекбокс выключен всегда; оба
состояния показаны в витрине.

## Переполнение

| Случай | Правило |
|---|---|
| Длинное ФИО в поле | значение усекается внутри поля, список показывает его целиком; в просмотре усекает ReadOnlyField с тултипом |
| Длинная подпись роли | «Сотрудник Юридической службы» — самая длинная; переносится до двух строк внутри своей колонки |
| Много внешних участников | «Другие участники» — одна строка ввода на всю ширину окна; длинное перечисление прокручивается внутри поля, в просмотре переносится |
| Длинный список сотрудников | список прокручивается (`ddl--scroll`), ширина — по полю |
| Мало места по высоте | тело окна прокручивается само, шапка и подвал закреплены (правило Modal, до 80vh) |
