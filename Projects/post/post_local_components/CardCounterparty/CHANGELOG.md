# Карточка контрагента — журнал изменений

Формат записи: что изменилось · почему · по какому требованию.

## 0.005 — 21.09.2026

*Требование:* решение человека 21.09.2026 — в статусах сделки, не допускающих правку, окно
КНР открывается в режиме просмотра.

- **В режиме `view` отметка «КНР» выключена** (`disabled` у чекбокса в `render`): видна, но
  не переключается. *Почему:* отметка — правка состава сделки, а в просмотре правка
  невозможна; до этого `view` прятал только кнопку переноса.
- **Режима `locked` нет** — запрет по статусу сделки показывается как `view`.
- **Паспорт — по правилам ДС 1.005** (`rulesVersion`): строка «Правка временно запрещена»
  удалена — правила убрали это состояние из обязательного набора.

## 0.004 — 21.09.2026

*Требование:* третья волна правок человека 21.09.2026.

- **Грип заменён кнопкой переноса** — IconButton M с иконкой `arrow-left-right`, хук
  `data-knr-move`; подпись и подсказку ставит рендер по `opts.moveLabel` (было
  `gripLabel`). *Почему:* карточку больше не перетаскивают — её переносят этой кнопкой или
  двойным кликом (двойной клик обрабатывает потребитель).
- **Подсказку кнопки привязывает рендер** (`DSTooltip.bindAll` по карточке): карточки
  рисуются после загрузки страницы, а `ds-tooltip.js` обходит `[data-tooltip]` только на ней.
- **Состояние «Перенос» (`.is-move`) снято** с витрины и из паспорта.
- **Реквизиты: CRM ID убран, «ЕГК ID» → «ЕПК ID»** — витрина, паспорт, `fixtures.json`.

- «Бэклог» последним разделом; из «Документации» убраны классы и атрибуты.

## 0.002 — 21.09.2026

*Требование:* правки человека 21.09.2026 к окну «Ключевой носитель риска».

- **Грип — элемент ДС `.tile__grip`** (IconButton M 20×20, Tile 1.013) вместо своего `span`
  в 24px; блок грипа из `CardCounterparty.css` удалён. *Почему:* человек попросил грип
  20×20 и уточнил, что размер должен приходить из ДС, чтобы следующая карточка получала его
  из коробки.
- **Риск-метрика — в теле карточки, справа второй колонкой**; реквизиты и чекбокс «КНР» —
  в первой. Колонки — flex-ряд (`.lc-knrm__content`), чтобы у найденного контрагента без
  метрики не оставалось пустой колонки. Открытый вопрос «риск-метрика в слоте действий»
  закрыт.
- **Зазор заголовок ↔ сабхедер 4px** — правило хэдера Card в ДС (Tile 1.013), в компоненте
  ничего не менялось.
- **Новое состояние «Недоступна»** — `opts.disabled` рендера: `aria-disabled="true"`
  (Disabled у Card) плюс `inert`. *Почему:* окно КНР показывает участников сделки другого
  вида недоступными. Режим `view` для этого больше не используется.
- Витрина: образец «Недоступна» и свитч в конструкторе, эталон разметки во вкладке «Код».

## 0.001 — 20.09.2026

Создание компонента. Карточка вынесена из модального окна «Ключевой носитель риска»
(`../TileKNR/TileKNRModal.html`), где была написана девять раз подряд.

- **Фрагмент — `<template>`, а не готовая карточка.**
  *Почему:* карточек на странице много, содержимое у них разное, а через метку подключения
  передаются только `id`, `class`, `state` и `mode`. Поэтому компонент отдаёт эталон
  разметки, а данные приходят из `Projects/post/data/mock-counterparties.js` через
  `CounterpartiesStore` — тот же приём, которым реестр портфеля рисует 50 сделок.
  *Требование:* решение человека 20.09.2026 — «модальное окно тянет из локальных
  компонентов компонент карточки, данные тянутся из файла базы».
- **Варианты** — юрлицо и физлицо; **состояния** — найден и участник сделки.
  *Почему:* риск-метрика, строка ГСЗ и чекбокс «КНР» осмыслены только у участника сделки.
  Это предметное правило, поэтому оно живёт в сторе и в CSS компонента, а не в разметке
  потребителя. *Требование:* правила состава окна, макеты `Uploads/Post _ DEAL _ R&D`.
- **CSS карточки** переехал из `TileKNRModal.css`: сетка полей, чекбокс, грип.
  *Почему:* стиль компонента должен жить с компонентом, иначе правка вида не доезжает до
  второго потребителя. *Требование:* правила локальных компонентов, «Вёрстка и токены».
- **Классы оставлены с историческим префиксом `lc-knrm__`.**
  *Почему:* за них держится скрипт переноса в окне (восемь мест); переименование стоило бы
  правок в жесте без пользы для вида. Записано в «Открытые вопросы» паспорта.
  *Требование:* решение по месту, 20.09.2026.
- Паспорт, `fixtures.json` и витрина по паттерну страниц компонентов ДС — сплиттер с живым
  демо, три таба и якорный TOC.
