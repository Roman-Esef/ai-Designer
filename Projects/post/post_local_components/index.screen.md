# Локальные компоненты Post

## 1. Назначение

Одна точка входа в кит направления: с неё открывается витрина любого локального
компонента. Правила локальных компонентов требуют такую страницу на кит и ту же левую
навигацию в витрине каждого компонента — чтобы переходить между компонентами, не
возвращаясь на обзор.

Страница отвечает на два вопроса: какие компоненты есть у направления и какие из них
уже наполнены, а какие пока заглушки.

## 2. Источник списка

Список **не ведётся руками на странице**. Реестр — `kit.js` (`window.PostKit`):
категории в порядке показа и массив компонентов с полями `id`, `name`, `category`,
`purpose`, `doc`, `state`. Поля повторяют шапку паспортов.

Правила требуют, чтобы список строился по полю `category` паспортов, а не копией в
каждой витрине. Генератора, который читал бы `*.md`, в проекте нет — до него реестр
живёт в одном файле, и правка компонента означает правку строки в нём.

Рисует реестр `kit-nav.js` (`PostKitNav.render`), общий для этой страницы и для витрин
компонентов.

## 3. Раскладка

| Зона | Класс | Устройство |
|---|---|---|
| Левая панель | `.nav.nav--fixed` | NavPanel: `.nav__block` = категория, `.nav__block-label` = её название, `.nav__item` = компонент |
| Крошки | `.crumbs` | один текущий пункт |
| Шапка | `.phead` | `h1.phead__title` «Локальные компоненты Post» |
| Карточки | `.kit-group` > `.grid12` | группа на категорию, внутри карточки `.tile--card.col-4.colw-6` |

Порядок групп задаёт реестр (переиспользуемые первыми, дальше предметные), порядок
внутри группы — по алфавиту видимого названия, как в ДС.

Перестроение — штатная пара `col-N`/`colw-N` плюс последний шаг в одну колонку на
900px. Оба правила имеют специфичность (0,2,0): у правила пары она такая же, и правило
с меньшей проиграло бы.

## 4. Поведение

| Что | Чем сделано |
|---|---|
| Сворачивание панели, пин, тултипы rail | рантайм NavPanel, хук — наличие `.nav` |
| Крошки сворачиваются в «…» | `data-breadcrumbs` |
| Модалка смены роли | `data-modal="role-modal"` на кнопке выхода футера |
| Панель и карточки | `PostKitNav.render(...)` из `kit-nav.js` по реестру `kit.js` |
| Строка пользователя ведёт на хаб | экранный скрипт: `IBPHome.footerHTML(...).replace(...)`, путь `../../../index.html` |

Компонент без витрины — пункт панели выключен (`.nav__item--disabled`) и карточка не
ссылка. Скрывать такие компоненты нельзя: кит тогда выглядит состоящим из одного
наполненного компонента, а их тринадцать.

**Артефакты — второй уровень.** Модальное окно компонента не компонент: в плоском списке
его нет. Компонент с артефактами рисуется штатным аккордеоном NavPanel
(`.nav__item--acc` + `.nav__sub`), свёрнутым по умолчанию; разворачивание даёт рантайм
`ds-nav-panel.js`. На обзорной странице артефакт не карточка — только строка «Артефакты: N»
в карточке своего компонента.

## 5. Открытые вопросы и допущения

1. **Три категории из пяти пусты.** Заполнены «Общие» (карточка контрагента) и «Сделка»
   (13 модулей страницы сделки). «Инструменты», «Отчёты» и «Другое» объявлены и показаны
   с пометкой «пока пусто» — решение человека 20.09.2026: по списку категорий видно, куда
   класть новый компонент. Это состояние направления, а не дефект страницы.
2. **Витрины есть у двух компонентов** — `TileKNR` и `CardCounterparty`. Остальные 12 —
   заглушки без страницы.
3. **Иконка пункта панели одна на все компоненты** (`layout-grid-01`): глифа «локальный
   компонент» в ДС нет, а выдумывать разные иконки компонентам — значит завести
   незаявленную семантику. Вопрос к дизайнеру.
4. **Генератор реестра.** `kit.js` дублирует поля паспортов, и расхождение ничем не
   ловится. В бэклоге правил ДС генератор заявлен; пока сверка глазами на ревью.
