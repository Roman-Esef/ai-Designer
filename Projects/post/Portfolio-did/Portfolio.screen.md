# Текущий портфель ДИД

## 1. Назначение

Реестр сделок направления ДИД: пользователь видит полный список сделок текущего
портфеля, фильтрует его по параметрам сделки, настраивает видимые колонки и
создаёт новую сделку.

**Роль пользователя:** Финансист ДИД
**Права:** просмотр портфеля; сделки с ограниченным доступом видны только при
наличии права (в макете одна строка с «Да»).

## 2. Навигация

| Уровень | Текст | Ссылка |
|---|---|---|
| 1 | Главная | `../mainPage/index.html` |
| 2 (текущий) | Текущий портфель ДИД | — |

Крошка «Главная» и пункт бокового меню «Главная» ведут на главную страницу
(`mainPage/index.html`) — двусторонняя связь: на главной пункт меню и тайл
«Текущий портфель» открывают эту страницу (см. mainPage.screen.md).

Пункт бокового меню в состоянии `nav__item--selected` + `aria-current="page"`:
«Текущий портфель» (группа «Текущий портфель ДИД», иконка `current-depo`).

## 3. Источник данных навигации

Меню панели строится экранным скриптом из `window.IBPHome` (`scripts/ibp-home.js`)
по роли `'Финансист ДИД'` — вызовом `IBPHome.itemsFor(role)`. Пункт
`current-portfolio` помечается selected; пункты с `tile.links` («Корпоративные
запросы», «Отчёты 1C/Navision», «Отчёты для Рисков») рендерятся как
аккордеон-родители `.nav__item--acc`; «Поиск клиентов в ЕПК» (`tile: null`) — обычный
пункт меню без тайла. Строка пользователя в футере — Александров Петр
Константинович, «Финансист ДИД» (вынесена в `IBPHome.footerHTML(role)`).
**В макете** строка пользователя ведёт на хаб проектов (корневой `index.html`,
`aria-label="Хаб проектов"`) — служебный переход, в продукт не переносится.

## 5. Раскладка

Контентная область — 12 колонок, зазор 16px. Единственный блок контента —
таблица на всю ширину. Горизонтального скролла у рабочей области нет —
горизонтальный скролл только внутри тела таблицы (`.tbl--scroll`). Отступ
таблицы от нижней границы экрана — 24px: это нижнее поле контентной области,
собственного `margin-bottom` у таблицы нет (правило каркаса — низ одинаков для
всех типов контента).

**Высота таблицы — правило каркаса** (Layout `.screen--app` + Table `.dtable--fill`):
таблица как единственный/основной блок занимает **всю свободную высоту экрана**
за вычетом полей контента, крошек, шапки страницы и тулбара/фильтра. На рабочей
области стоит `.screen--app` (фикс. вьюпорт `100vh`), на таблице — `.dtable--fill`:
тело таблицы скроллится внутри, крошки/шапка/тулбар/пагинация закреплены.
Вертикальный скролл страницы при этом отсутствует — скроллится только тело таблицы.

| № | Блок | Компонент | Колонок из 12 | Содержимое |
|---|---|---|---|---|
| 1 | Зона тулбара | Table (`.dtable-toolbar`) | 12 | слева TableFilter, справа настройка колонок |
| 2 | Таблица «Сделки» | Table (`.dtable--fill`, headless) | 12 | 23 колонки, без тулбара (сразу шапка), пагинация |

Вертикальный ритм — **12px**: заголовок страницы → зона тулбара → таблица. Это
описанный вариант каркаса (Layout, раздел «Экран-реестр: состав и отступы»), а не
самодеятельность экрана; значение экран задаёт единственной раскладочной строкой
в своём `<style>`: `.screen__content { gap: var(--space-12) }`.

## 6. Таблица «Сделки»

**Источник данных (05.09.2026):** таблицу рендерит скрипт экрана из общей базы
направления, а не статичная разметка:

| Файл | Что | Подключён на этом экране |
|---|---|---|
| `../data/mock-deals.js` | `window.MOCK_DEALS` — 50 сделок (плоские поля таблицы и фильтра) + `window.DEALS_ENUMS` — перечни для фильтра | да |
| `../data/deals-store.js` | `window.DealsStore` — `list()/byId()/exists()/create()/update()/on()`, единая точка доступа к базе | да |
| `../data/mock-deal-trees.js` | `window.MOCK_DEAL_TREES` — дерево продуктов ДИД по сделкам, ключ — `id` | нет (нужно только будущей странице сделки) |

**Ключ колонки (`data-col`).** Каждая содержательная `.th` в шапке (23 колонки)
и каждая ячейка, которую собирает `renderRow`, несут `data-col="<поле сделки>"` —
ключ пишет общий `cellOpen`. Это хук рантайма таблицы: по ключу `DSTable.adoptRow`
сопоставляет ячейку строки, дописанной экраном, с колонкой шапки и приводит
строку к текущей форме колонок — порядок после переноса, треки после ресайза,
ячейка скрытой колонки уходит на склад строки. Инсеты закрепления новой строке
проставляет `tbl-pin.js` (он ловит вставку строки сам). Своего JavaScript под это
экран не пишет: обработчик «Новая сделка» только вставляет строку
(TableCell 2.019, Table 1.016).

Скрипт стоит **после** `ds.js` (нужны `window.DSTable`/`window.DSPagination`,
которые `ds.js` догружает через `document.write`); рантаймы таблицы сами
поднимаются на `DOMContentLoaded` — позже, чем этот синхронный скрипт, поэтому
50 вставленных строк учитываются ими штатно при первом `wire()` (порядок для
`data-sort-rows`, тултипы усечения — без обращения к `rowsChanged()`, он нужен
только для строк, добавленных ПОСЛЕ загрузки страницы — см. Table 1.012).

Плоские поля записи — `id`, `name`, `status`/`statusTsup`/`statusOps`/`statusMon`
(кортежи §7), `restricted`, `desk`, `director`/`manager`/`tsupEmployee`, `knr[]`,
`gsz`, `jointness`, `collateral`, `corpGovernance[]`, `boardRep`, `finTpl`,
`signDate`/`firstDisb`/`endDate`/`repayDate`, `monEntity`, и производные из
дерева продуктов — `mainProductDid`, `productsDidNames[]`, `productsNames[]`,
`balances[]`, `currencies[]`, `isPE`. Производные поля вычислены из
`MOCK_DEAL_TREES` один раз при генерации и заморожены в записи — в проде их
считает бэкенд, реестр не пересчитывает.

**Допущения по форматам** (нет однозначного ответа в ТЗ): `jointness` — строка
из справочника (`DEALS_ENUMS.jointness`: «Совместная»/«Не совместная»);
`corpGovernance` — список строк; `boardRep` — Да/Нет.

**Распределение 50 сделок** покрывает крайние случаи вёрстки: 5 сделок-черновиков
без дат (прочерк во всех трёх датах), сделка с максимально длинным
наименованием, сделка со всеми 4 валютами ДС сразу (RUB/USD/EUR/JPY — больше в
системе не заведено), сделка с 6 балансами, сделка с 4 КНР, инструмент без
транша. 3 сделки — `restricted: Да`, 6 — `isPE: true`.

**Вариант «тулбар над таблицей»** (`.dtable-toolbar` + headless-таблица):
- зона `.dtable-toolbar` — БЕЗ подложки, над таблицей: слева TableFilter (кнопка
  «Фильтр» → `filter-scrim`, чип «Применено: N» — с 05.09.2026 реальный, скрыт при N=0), справа кнопка «Настроить
  колонки» (`ibtn` с глифом `settings` → `cols-scrim`);
- таблица `.dtable--fill` — **headless**: без `.dtable__toolbar`, сразу шапка
  колонок; заголовка «Сделки» и счётчика «128» наверху нет (счётчик остаётся

**Каркас:** `.tbl[data-table]` + `.tbl--scroll`. Шапка и все строки имеют
одинаковый `grid-template-columns` (8px-разделитель, 23 колонки данных,
замыкающий `minmax(8px,1fr)`). Колонки «Номер сделки» и «Наименование сделки»
закреплены (`.th--pinned` / `.tc--pinned`, `aria-pressed="true"` + глиф
`pin-filled` на `th__pin`).

**Закрепление — из коробки (TableCell 2.013, рантайм `tbl-pin.js` в `ds.js`):**
клик по `.th__pin` в шапке закрепляет/открепляет любую колонку (без переноса
в начало). При горизонтальном скролле закреплённые колонки удерживаются у
левого края нативным `position: sticky`; рантайм считает только инсеты
`left`/`right` и пишет их при изменении состава или ширин колонок — на скролл
не подписан. Закреплённые колонки хвостового блока (все колонки правее тоже
закреплены) держатся у правого края; крайний разделитель строки прилипает вместе
с примыкающей закреплённой колонкой и красится в её фон. Закреплённые колонки
перетаскиваются наравне с остальными. Собственного правила смещения у экрана нет.

**Колонка «КНР» и страница сделки.** Реестр подключает `CounterpartiesStore`
(`../data/counterparties-store.js`, с `mock-counterparties.js` и `post-api.js`) после
`deals-store.js`. Стор читает составы, сохранённые в окне КНР на странице сделки (сервер
данных `../server.mjs` или localStorage, контракт — `../data/API.md`), и переносит имена КНР
в `deal.knr` через `DealsStore.update`. Если хранилище ответило позже рендера строк,
экранный скрипт перерисовывает содержимое ячейки «КНР» на событии `change`. Ячейку
он берёт через `DSTable.cell(row, 'knr')`: так находится и ячейка колонки, скрытой
настройкой таблицы.
Фильтр по КНР читает тот же `deal.knr`.

**Ширина «Валюты» — 150px.** Два кода по три символа — ~104px плюс 32px паддингов
ячейки. 44 сделки из 50 несут ровно две валюты, поэтому две валюты видны целиком,
а в «+N» сворачиваются только ячейки с тремя-четырьмя. Свёртку делает рантайм
таблицы (`ds-table.js`) по разметке — два и более чипа в ячейке; экран ничего не
размечает. Смена ширины — один трек в `grid-template-columns` шапки и в константе
`GRID` скрипта экрана.

**Формат значений:** номер сделки — идентификатор, а не величина: выравнивается
по левому краю как текст (`.tc--numbers` в реестре не используется — правый край
и табулярные цифры остаются за суммами и долями); даты — `ДД.ММ.ГГГГ`; пустое
значение — прочерк `—`; валюты — чип на валюту: 3-буквенный код ISO 4217
прописными (`RUB`, `USD`, `EUR`, `JPY`), без символов ₽/$/€/¥ и без «руб.»,
чипы не сжимаются (`.chip--fit` — код показывается целиком, не «R…»);
ФИО — «Фамилия И.О.».

**Усечение и тултип:** все текстовые значения строк несут `.tc__text--truncate` —
одна строка, многоточие по границе колонки. Полное значение показывает тултип по
наведению; он навешивается рантаймом таблицы (`ds-table.js`) на значения ячеек,
подписи колонок и подписи чипов и появляется только тогда, когда текст реально
не помещается. Своей разметки тултипа на экране нет.

**Начальный порядок строк** — по дате подписания по убыванию, как заявляет
`aria-sort="descending"` в шапке «Дата подписания»; сделки без даты (черновики) — в
конце.

**Выбор строк:** не предусмотрен ТЗ (нет колонки чекбоксов и панели массовых
действий).

**Пагинация (реальная, 05.09.2026):** колонтитул собирается скриптом экрана
напрямую через `DSPagination.footer({ info, pager })` (не автопривязкой
`data-pagination` — она не заполняет левый слот) и пересобирается заново при
каждом изменении страницы/размера. Левый слот — `pgn-info` со значением
«Сделок: N» (число сделок, прошедших фильтр; без фильтра — все 50). Размер страницы по
умолчанию — **20** (при 50 сделках — реальные 3 страницы: «1 из 3» → «2 из 3»
→ «3 из 3»); доступны все размеры Pagination (5/10/15/20/50/Все). Строки не
пересоздаются — видимость переключает `hidden` на каждом `.tbl__row` (правило
`.tbl__row[hidden]`, TableCell 2.015): строка видима, если попадает в окно
текущей страницы по своей позиции в актуальном DOM-порядке (учитывает
сортировку — окно считается ПОСЛЕ перестановки строк).

## 7. Статусы

Чипы статусов — `chip chip--s chip--rounded` + тон (**статусные чипы всегда
скруглённые**, правило чипа). Чипы с аватаркой (ЦУП/Operations/Мониторинг)
используют штатный паттерн: `.chip__avatar.av.av--circular` с буквой `Ц`/`O`/`М`.
Аватар тонируется по тону чипа (фон `-mid`, белая буква) — штатное поведение Chip 1.012.
Буквы: ЦУП = «Ц», Operations = «O», Мониторинг = «М».

### Private Equity

Чип-тег `chip chip--s chip--pe chip--fit` с текстом «PE». **PE — флаг-категория, а
не статус:** не скругляется, цвет кастомный по кейсу (правило «теги» в Chip 1.013),
к тон-вариантам чипа не привязан, не сжимается (`.chip--fit` — значение
показывается целиком). Окраска — только токены ДС: фон/обводка
`--st-orange-mid` (StOrange_mid), текст `--text-primary`. Класс `.chip--pe`
задан в собственном `<style>` экрана.

- Основная информация: Номер сделки (numeric), Наименование сделки, КНР — текстовые;

  Балансы сделки — автокомплит-мультивыбор.
- Продукты: Продукты сделки, Продукты ДИД, Основной продукт ДИД — мультивыбор.
- Сроки: Дата подписания, Дата первой выдачи, Дата окончания — `InputDateRange`.
- Команда сделки: Директор, Менеджер, Сотрудник ЦУП — одиночный автокомплит.
- Прочее: Совместность (мультивыбор), Обеспечение (Да/Нет), Корпоративное
  управление (мультивыбор), Представительство в СД (Да/Нет), Фин. расчеты в

**Навигация модалки фильтра.** Вертикальные табы слева — якоря разделов: клик
прокручивает тело модалки к разделу, при прокрутке подсвечивается текущий раздел
(`aria-current`). Рантайма ДС для якорных табов нет — это короткий скрипт экрана по
эталону `DS-IBP/scripts/table-filter.page.js`. Поля выбора — `data-ddl` + `.ddl`-список,
списки строятся из `window.DEALS_ENUMS`; чипы мультивыбора строит экран
(`DSInputKit.makeChip`) и держит в синхроне с галочками списка в обе стороны.

**Модалка «Создание новой сделки».**
- Проверка — на «Сохранить» и повторно на каждой правке поля (`input`).
- Ошибка — тултип на фокусе поля (тип error), текст в хелпер не дублируется.
  Якорь тултипа — `.inp__box` вокруг поля прямо в разметке: автообёртка
  `.tip-anchor` вокруг `input` забрала бы флекс-рост поля. Тултип строится
  вручную (`DSTooltip.make` + `DSTooltip.bind(input, { tip })`).
- Нейтральный хелпер «Только числовые символы» под «Номер сделки» виден и в
  состоянии ошибки: это формат ввода, а не текст ошибки.
- Новая сделка — статусный кортеж Черновик / Черновик / Черновик / На утверждении,
  остальные поля пустые.
- Сброс формы на открытии — `DSModal.bind(trigger, { onOpen })` из скрипта экрана,
  раньше автопривязки `ds-modal.js` (та идёт на `DOMContentLoaded`), поэтому второй
  обработчик не навешивается.

Ключ поля — в `data-sort` кнопки, тип — в `data-sort-type` на `.th`. Порядок строк переставляет рантайм ДС по `data-sort-rows` на `.tbl` — с 05.09.2026 по **всем 50 записям** реестра (не только по видимой странице): все строки стоят в DOM, скрыты только вне текущего окна пагинации; после события `sort` скрипт экрана сбрасывает пагинацию на первую страницу и пересчитывает видимость по новому порядку. Исключение — сортировка, которую рантайм вернул при возврате на страницу (`sort` с `restored: true`): страница остаётся восстановленной, пересчитывается только видимость. С реальным бэкендом атрибут `data-sort-rows` снимается, а сортирует сервер по событию `sort` с тем же ключом |
| Перетаскивание `.th__resize` | изменение ширины колонки, минимум 96px; ширина запоминается на время сессии (см. «Переход на другую страницу») |
| Перетаскивание за `.th__label` | изменение порядка колонок (закреплённые переносятся — класс pin едет с колонкой) |
| Клик по `th__pin` | закрепление/открепление колонки (на макете закреплены «Номер» и «Наименование») |
| Горизонтальная прокрутка тела | закреплённые колонки остаются на месте (sticky) |
| Переход на другую страницу (сделка, главная) и возврат в портфель | реестр открывается там же, где его оставили: колонки в том же порядке, с той же видимостью, закреплением и шириной; та же сортировка; тот же применённый фильтр (поля формы заполнены, чип «Применено: N»); та же страница пагинации и размер страницы; тело прокручено туда же по вертикали и горизонтали. Правки формы фильтра без «Применить» не запоминаются. Всё живёт, пока открыта вкладка браузера, и переживает перезагрузку; в новой вкладке реестр в исходном виде. Колонки, сортировку и скролл хранит рантайм ДС по опции `data-table-persist="post-portfolio-did"` на `.tbl` (Table 1.018), ключи колонок — `data-col`. Страницу, размер страницы и фильтр хранит скрипт экрана (`sessionStorage`, ключ `post.portfolio-did.view`): он ставит их синхронно, до DOMContentLoaded, затем рантайм возвращает колонки, сортировку и последним — скролл. Выборка фильтра пересчитывается по текущим данным `DealsStore`. Если сохранённый фильтр ничего не находит — возврат на EmptyState; сохранённые колонки рантайм применяет, когда таблица снова показана. Ячейку «КНР» экран обновляет через `DSTable.cell`, поэтому скрытая колонка получает свежее значение |

Делает рантайм ДС (`DSTable.adoptRow` + `tbl-pin.js`), хук — `data-col` |

При успехе: `DealsStore.create({id, name})` (статусный кортеж — Черновик, остальные поля пустые), новая строка вставляется первой, `DSTable.wire(tbl).rowsChanged()` включает её в `__dsRowOrder` (участвует в сортировке), пагинация сбрасывается на страницу 1 и пересчитывается, модалка закрывается. При открытии модалки форма и состояние ошибок всегда сбрасываются (`DSModal.bind(trigger,{onOpen})`, перехватывает автопривязку `ds-modal.js`) |
| Выбор значения в поле фильтра | с 05.09.2026 — реально: списки мультивыбора/одиночного выбора перестроены из `window.DEALS_ENUMS` (полный домен, не черновик из нескольких демо-значений); чип добавляется/убирается в поле (`DSInputKit.makeChip`), крестик поля снимает выбор в списке и наоборот; счётчик на вкладке слева (`.tab__badge`) — живой, растёт/падает при каждой правке черновика формы, скрыт при 0 (`.tab__badge[hidden]`, правка Tab 1.010) |
| Крестик в поле фильтра | виден только при значении (рантайм `ds-input.js`); чистит поле, снимает галочки в списке и счётчик вкладки слева — экран сбрасывает своё состояние по событию `ds-input:clear` |
| Клик «Применить» | реальный отбор: `DealsStore.list()` фильтруется по всем активным полям (текст — регистронезависимая подстрока, мультивыбор — вхождение в множество/пересечение массивов, диапазон дат — `parseRuDate` в границах, чекбокс — точное совпадение); пагинация и «Сделок: N» пересчитываются по результату, страница сбрасывается на 1-ю, модалка закрывается. Применённые поля запоминаются на время сессии (см. «Переход на другую страницу»). Чип «Применено: N» в шапке тулбара — число активных полей на момент этого клика (не число найденных строк), создаётся/обновляется только здесь и при «Очистить». Нулевой результат — EmptyState вместо таблицы и колонтитула (см. новую вёрстку `#deals-empty`), а не пустая таблица |
| Клик «Очистить фильтр» / крестик на чипе «Применено: N» / «Очистить фильтр» в EmptyState | сброс всех полей формы и повторное применение (эквивалент «Применить» с пустым черновиком — снова все 50 сделок). Крестик чипа — стандартный `ds-table-filter.js`: убирает чип и шлёт `tfilter:reset` (bubbles) на `.tfilter`, экран слушает это событие для сброса параметров |
