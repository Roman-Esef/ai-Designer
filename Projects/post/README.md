# post — проект направления Post

Экраны направления Post (Operations / финансисты), соответствующие настоящей системе.
Папка `post/` целиком — один проект и один `root` записи в реестре хаба `../../hub.js`
(`id: 'post'`). Черновые экраны и концепты направления агент собирает в `../../Concepts/<Имя>/`.

## Состав

| Папка или файл | Что внутри |
|---|---|
| `mainPage/` | стартовая страница роли: меню и тайлы по каталогу `ibp-home.js` |
| `Portfolio-did/` | экран-реестр «Текущий портфель ДИД» |
| `deal_post/` | страница сделки и её исходные материалы |
| `data/` | общая мок-база: сделки (`mock-deals.js` + `DealsStore`), контрагенты и состав участников сделок (`mock-counterparties.js` + `CounterpartiesStore`), адаптер хранения `post-api.js` и контракт API `API.md` |
| `post_local_components/` | локальные компоненты направления — тайлы, их модалки и прочие модули |
| `assemble.mjs` | ассемблер модульных страниц: источник с метками → собранный `*.preview.html` |
| `server.mjs` | локальный сервер: статика репозитория + API данных (`data/API.md`); база — `data/db/`, в git не идёт |

Экраны лежат **на одном уровне**, папок под роль нет. Копии страниц под каждую роль не
делаются: различия ролей закрываются сменой состояний одной страницы. Механизм такой смены
пока не спроектирован.

Глубина экрана — `post/<экран>/`, поэтому ДС подключается как `../../../DS-IBP/ds.css` и
`../../../DS-IBP/scripts/ds.js`, а строка пользователя в футере меню ведёт на
`../../../index.html`.

## Какой файл открывать

| Экран | Открывать двойным кликом |
|---|---|
| Главная | `mainPage/index.html` |
| Текущий портфель ДИД | `Portfolio-did/Portfolio.html` |
| Сделка | `deal_post/Deal.preview.html` — **собранный**, не `Deal.html` |

Страница сделки модульная: `deal_post/Deal.html` — это источник, он держит перечень тайлов
метками `<ds-include>`, а разметку тайлов вшивает ассемблер. После правки любого модуля или
источника:

```bash
node Projects/post/assemble.mjs
```

Почему сборка, а не рантайм ДС `ds-include.js`, и как устроены модули — в
`post_local_components/README.md`.

### С сервером данных

Правки, которые должны сохраняться, — сейчас это состав участников и КНР сделки — пишутся
в базу локального сервера:

```bash
node Projects/post/server.mjs
```

Затем страницы открываются по адресу сервера, например
`http://127.0.0.1:8787/Projects/post/Portfolio-did/Portfolio.html` (сделка —
`…/deal_post/Deal.preview.html`). Без сервера, двойным кликом, всё работает так же, но
правки сохраняются только в этом браузере (localStorage). Сбросить базу —
`node Projects/post/server.mjs --reset`.

Серверу нужен только Node 16+ (тот же, на котором работает сборка), зависимостей нет.
В другой контур он переезжает вместе с репозиторием; база сохранённых правок
(`data/db/`) в git не идёт, поэтому там она начинается с мок-данных.

## Данные

`data/` — единственная точка доступа к данным для всех экранов направления: таблица
портфеля и страница сделки читают один и тот же `window.DealsStore`, поэтому правила
валидации, уникальности и тоны статусных чипов (`DealsStore.statusTone`) живут в одном
месте. Состояние сделок — только в памяти вкладки.

Состав участников сделки и её КНР — `window.CounterpartiesStore`. Его правки сохраняются
через адаптер `PostApi` (`data/post-api.js`): в базу сервера данных или, без него, в
localStorage. Так сохранённый на странице сделки состав виден и в тайле «КНР», и в колонке
«КНР» реестра. Контракт — `data/API.md`; настоящий бэкенд реализует его же, и тогда меняется
только адаптер.
