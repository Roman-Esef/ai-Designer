# API данных направления Post

Контракт между страницами направления и хранилищем данных. Сейчас его исполняет
локальный сервер `../server.mjs`; настоящий бэкенд реализует тот же контракт, и
тогда меняется только адаптер `post-api.js` — страницы и сторы остаются как есть.

## Кто с кем говорит

```
страница ─▶ CounterpartiesStore (counterparties-store.js) ─▶ PostApi (post-api.js) ─▶ API
```

- Страницы и компоненты зовут только стор.
- Стор зовёт только `PostApi`.
- `PostApi` выбирает режим один раз, при загрузке страницы:

| Режим | Когда | Куда пишется |
|---|---|---|
| `server` | страница открыта по http(s), и `GET /api/post/participants` ответил 2xx | база сервера |
| `local` | страница открыта двойным кликом (`file://`) или с сервера без этого API | `localStorage` браузера, ключ `ibp.post.participants` |

В режиме `local` правки видны только в этом браузере. Консоль сообщает об этом один раз.

## Состав участников сделки

Запись о сделке хранит только ссылки на базу контрагентов (`mock-counterparties.js`):

```json
{ "members": ["ul-11", "ul-2"], "knr": ["ul-2"], "updated": "2026-09-21T09:30:18.175Z" }
```

| Поле | Что это |
|---|---|
| `members` | id контрагентов — участников сделки, в порядке добавления |
| `knr` | те из участников, кто отмечен ключевым носителем риска; подмножество `members` |
| `updated` | время сохранения, ISO 8601; ставит сервер |

Если сделку не сохраняли, записи о ней нет. Тогда стор собирает начальный состав из поля
`knr` сделки в реестре (`mock-deals.js`). Имена КНР для таблицы портфеля стор тоже
вычисляет из базы контрагентов, поэтому хранятся только id.

## Эндпоинты

| Метод и путь | Ответ |
|---|---|
| `GET /api/post/participants` | `200` — `{ "<номер сделки>": запись, … }`; только сохранённые сделки |
| `GET /api/post/participants/:dealId` | `200` — запись; `404` — сделку не сохраняли |
| `PUT /api/post/participants/:dealId` | тело `{ members, knr }` → `200` `{ ok: true, updated }` |
| `DELETE /api/post/participants` | `204` — база очищена (для показов) |

**Проверки при записи** (`400` с `{ error }`):

- номер сделки и id контрагентов — `[A-Za-z0-9_-]`, от 1 до 32 символов;
- `members` и `knr` — массивы без повторов, не больше 500 записей;
- каждый id из `knr` есть в `members`.

Тело больше 64 КБ — `413`. Другие методы — `405`.

## Поиск контрагентов (для настоящего бэкенда)

В прототипе этого эндпоинта **нет**: база контрагентов — мок-файл `mock-counterparties.js`
на фронте, поиск выполняет `CounterpartiesStore.search`, и работает он одинаково с сервером
и без него. Ниже — контракт, по которому поиск пойдёт на настоящий бэкенд. Тогда адаптер
получает метод `PostApi.search`, а стор зовёт его вместо поиска по мок-базе.

| Метод и путь | Ответ |
|---|---|
| `GET /api/post/counterparties?kind=ul&name=&inn=&kpp=&ogrn=&kio=&dealId=` | `200` — массив юрлиц |
| `GET /api/post/counterparties?kind=fl&parentId=&inn=&birthDate=&passport=&phone=&dealId=` | `200` — массив физлиц |

Запись ответа — в форме базы: `id`, `kind`, `name`, `subheader`, `parentId` (у физлица),
`fields`, `gsz`, `risk`, `contacts`.

Правила — те же, что у стора сейчас:

- заполненные параметры соединяются по «И»; ни одного — `400`, поиск не выполняется;
- `name` — подстрокой, без учёта регистра, кавычек и разницы ё/е; коды (ИНН, КПП, ОГРН, КИО,
  паспорт, телефон) — подстрокой по цифрам; `birthDate` — точно, `ДД.ММ.ГГГГ`;
- участники сделки `dealId` в результат не попадают;
- физлица ищутся только среди физлиц юрлиц — участников сделки `dealId`; `parentId` сужает
  поиск до одного из них.

## Локальный сервер

```bash
node Projects/post/server.mjs              # http://127.0.0.1:8787/
PORT=9000 node Projects/post/server.mjs    # другой порт
node Projects/post/server.mjs --reset      # очистить базу и выйти
```

- Раздаёт статику от корня репозитория. Скрытые папки (`.git`, `.opencode`) не отдаёт.
- Слушает только `127.0.0.1`.
- База — `Projects/post/data/db/participants.json`; папка в `.gitignore`.
- Запись атомарная, запросы на запись выполняются по очереди.

Страница по серверу: `http://127.0.0.1:8787/Projects/post/Portfolio-did/Portfolio.html`.
