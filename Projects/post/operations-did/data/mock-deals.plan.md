## 1. Файл данных (реестр): `Projects/post/operations-did/data/mock-deals.js`

- Отдельный JS-файл (не JSON): грузится `<script src>`, работает при двойном клике
  (`file://`, путь ASCII). Общий для направления: портфель и будущая страница сделки
  подключают его относительным путём (`../data/mock-deals.js`).
- Экспортирует:
  - `window.MOCK_DEALS` — массив 100 сделок;
  - `window.DEALS_ENUMS` — перечни статусов по 4 колонкам, дески, балансы,
    продукты ДИД/продукты (для переиспользования в фильтре и на странице сделки).
- Данные генерируются **детерминированно** (генератор внутри файла: пулы имён/десков/
  балансов/продуктов + сид) — компактно, легко править, одинаковый вывод при каждом
  открытии.

### Схема сделки (единая для таблицы и страницы)

Плоские поля (23 колонки таблицы) + расширение для страницы сделки:

| Группа | Поля |
|---|---|
| Идентификация | `id` (номер сделки, число), `name` (наименование) |
| Статусы | `status`, `statusCup`, `statusOps`, `statusMon` — значения из перечней ТЗ, согласованные кортежи |
| Доступ | `restricted` (Да/Нет) |
| Команда сделки | `desk`, `director`, `manager`, `cupEmployee` |
| Контрагенты | `knr` (массив — несколько КНР) |
| Описание сделки | `gsz`, `finCalcInTemplate`, `jointness` (Совместность), `collateral` (Обеспечение Да/Нет), `corpGovernance` (список), `boardRep` (Представительство в СД) |
| Сроки | `dateSigned`, `dateFirstDraw`, `dateEnd`, `dateRepayment` (дата погашения для «Погашена») |
| Дерево продуктов ДИД | `productsDid[]` → `products[]` → `instruments[]` (имя, валюта, баланс, `isPE`) → `tranches[]` |
| Производные (для таблицы) | `mainProductDid`, `productsDidNames`, `productsNames`, `balances`, `currencies`, `isPE` |

**Производные поля храним явно** (таблица не считает агрегаты); дерево — только для
страницы сделки. Избыточность осознанная для мока (в проде плоское считается из дерева
на бэкенде) — зафиксировать комментарием в файле.

### Статусы — согласованные кортежи (из ТЗ)

Тон-маппинг остаётся в экране (данные UI-агностичны: статус = строка).

| Комбинация | status (сделка) | statusCup (Ц) | statusOps (O) | statusMon (М) |
|---|---|---|---|---|
| Черновик | Черновик | Черновик | Черновик | На утверждении |
| Ожидает подтверждения | Ожидает подтверждения | Ожидает подтверждения | Ожидает подтверждения | На утверждении |
| Корректировка | Корректировка | Корректировка | Корректировка | На утверждении |
| Ввод изменений | Ввод изменений | Ввод изменений | Ввод изменений | — |
| Подтверждение изменений | Подтверждение изменений | Подтверждение изменений | Подтверждение изменений | — |
| Активная (ГК СБИ) | Активная | Утверждена | На сопровождении | На мониторинге ГК СБИ |
| Активная (ПАО Сбербанк) | Активная | Утверждена | На сопровождении | На мониторинге ПАО Сбербанк |
| Погашена | Погашена | Погашена | Погашена | Погашена |
| Ожидает назначения ответственного | Ожидает подтверждения | Ожидает назначения ответственного | Ожидает подтверждения | На утверждении |

Дополнительно по мониторингу (статусы-стадии передачи, встречаются в «Активная»-процессе):
«Ожидает передачи на мониторинг», «Направлена на передачу», «Передана» и варианты
«Изменения …» — охватываются при доработке генератора.

### Допущения по форматам (пометить в файле данных и screen.md)

## 2. `Portfolio.html` — таблица рендерит из реестра

- Экранный скрипт строит **100 строк** из `MOCK_DEALS`:
  - чипы статусов с аватарками (Ц/O/М), тот же тон-маппинг, что согласован ранее
    (Черновик→`chip--dark`, Ожидает/Подтверждение→`chip--warning`,
    Корректировка/Ввод изменений→`chip--info`, Активная/Утверждена/На сопровождении→
    `chip--success`, Погашена→`chip--error`, PE→`chip--warning`);
  - чип PE, чипы валют, числа (`.tc--numbers`), даты `ДД.ММ.ГГГГ`, бинарные Да/Нет;
  - «Ограниченный доступ» — большинство «Нет», часть «Да».
- **Пагинация**: `Показывать строк: 50` → 2 страницы по 50, реальное переключение
  (маленький экранный скрипт — это модель данных, рантайм ДС её не даёт).
- Появится **вертикальный скролл страницы** + **горизонтальный** внутри `.dtable__body`
  (23 колонки шире экрана).
- Счётчик «128» заменится на фактический «100»; пагинация «1–8 из 128» →
  «1–50 из 100» / «51–100 из 100».
- Данные UI-агностичны: тон-маппинг и форматы — в экранном скрипте, не в данных.
