# Список фондов

## 1. Назначение

Реестр фондов модуля «ИБП: Фонды и активы» — точка входа банкира/аналитика в
работу с базой фондов (100–150+, рост до 1000). Задача экрана: быстро найти
фонд, оценить приоритет и активность (новости, взаимодействия), не уходя на
отдельную карточку — через инлайн-предпросмотр справа. Раздел ТЗ 4.1
(«Список фондов → Фильтр → Выбор фонда → Карточка фонда») начинается здесь.

**Роль пользователя:** инвестиционный аналитик, банкир (coverage / relationship manager)
**Права:** чтение всей базы фондов; создание, изменение приоритета, архивирование — по роли (в ТЗ права по ролям не детализированы, см. «Открытые вопросы», п. 1)

## 3. Верхняя панель модуля (топбар)

Не часть ТЗ 6.1 напрямую — реализует раздел 9 ТЗ («Layout системы»: верхняя
панель поиска/уведомлений на всю ширину) и допущение №1 задания. Компонента
«TopBar» в ДС нет (Layout.md описывает только NavPanel + крошки + контент),
раскладка собственная на токенах.

| Элемент | Значение | Компонент / класс |
|---|---|---|
| Название модуля | ИБП: Фонды и активы | `.topbar__brand`, глиф `funds` |
| Глобальный поиск | плейсхолдер «Глобальный поиск: фонды, активы, идеи…» | `.inp.inp--s`, глиф `search` |
| Уведомления | счётчик 6 | `.badge-anchor` + `ibtn--neutral ibtn--m` (глиф `mail`, см. допущение №3) + `.badge--xs.badge--accent` |

**Технический момент (не для повторной проверки на других экранах без явного
решения):** `.nav` в ДС жёстко закреплён `position:fixed;top:0;height:100vh`
(`styles/nav-panel.css`), `.screen > .crumbs` — `position:sticky;top:0`
(`styles/layout.css`). Чтобы топбар не перекрывался панелью и не создавал
пустую полосу при скролле, на этом экране (только для связки «есть
`.topbar`») переопределены `top`/`height` `.nav` и `top` `.crumbs`, плюс
`padding-top` у `.nav-layout` — без правки файлов ДС, через более специфичный
селектор `.topbar ~ .nav-layout …`. См. допущение №3.

Дополнительно (правка 27.08.2026, приёмка): `.screen` внутри `.nav-layout`
наследует свой `min-height:100vh` (`styles/layout.css`), ничего не знающий про
56px топбара — вместе с `padding-top` у `.nav-layout` это давало документ выше
вьюпорта на 56px без причины. Добавлена точечная поправка
`.topbar ~ .nav-layout .screen { min-height: calc(100vh - 56px); }`.

Поле глобального поиска в топбаре сужается на **обычном `@media (max-width:
1320px)`**, не на `@container screen`: именованный контейнер `screen`
(`styles/layout.css:34-35`) создаётся на `.screen`, а `.topbar` в разметке
идёт раньше `.nav-layout` и потомком `.screen` не является — `@container
screen` на `.topbar__search` не сработал бы никогда (поймано на приёмке
27.08.2026). К тому же `.topbar` растянут на весь вьюпорт независимо от
состояния nav-панели (rail/drawer меняют ширину `.screen`, не топбара) —
поэтому смысловым триггером сужения здесь и должна быть ширина окна, а не
ширина контентной области.

## 6. Таблица «Фонды»

**Тулбар:** заголовок «Фонды», счётчик записей (138), локальный поиск
(название/бенефициар), TableFilter (кнопка «Фильтр» + чип «Применено: N»),
кнопка настройки колонок, кнопка «Экспорт».

| Ключ | Заголовок | Тип | Ширина | Выравн. | Сортировка | В фильтре |
|---|---|---|---|---|---|---|
| `select` | — | чекбокс | 44px | центр | нет | нет |
| `name` | Название | текст, ссылка | 2.2fr | слева | да, активна по возрастанию | да, через локальный поиск |
| `type` | Тип | иконка + текст | 1.3fr | слева | да | да, множественный выбор |
| `priority` | Приоритет | Chip (тон по значению) | 132px | слева | да | да, множественный выбор |
| `beneficiary` | Бенефициар | текст | 1.6fr | слева | да | да, текстовый фильтр |
| `contacts` | Контакты | группа Avatar + тултип на каждом | 104px | слева | нет | нет |
| `news` | Новости | IconButton + Badge-счётчик | 96px | центр | нет | нет |
| `assets` | Активы | IconButton, открывает панель справа | 72px | центр | нет | нет |
| `history` | История | IconButton, тултип с датой последней встречи | 72px | центр | нет | нет |
| `actions` | Действия | ContextMenu (⋮) | 76px | центр | нет | нет |

**Порядок колонок изменён относительно ТЗ.** В ТЗ 6.1: Название, Бенефициар,
Тип, Контакты, Приоритет, Новости, Активы, Взаимодействия. На экране
Приоритет перенесён сразу после Типа, перед Бенефициаром — колонка триажа
(на какие фонды смотреть в первую очередь) должна стоять рядом с
идентификатором, а не после контактов (`layout-composition`, «Порядок
колонок» — по убыванию значимости для решения). Обоснование сверено с
разметкой (совпадает).

**Формат значений:** приоритет — Chip, тон по значению из справочника (не
числовая шкала, см. ниже); даты в тултипах — `ДД.ММ.ГГГГ`; пустое значение
счётчика новостей — Badge не рисуется, остаётся просто иконка.

**Приоритет — качественное значение справочника, не проценты:**

| Значение | Chip |
|---|---|
| Приоритет 1 | `chip--s chip--error` (красный) |
| Приоритет 2 | `chip--s chip--warning` (жёлтый) |
| Приоритет 3 | `chip--s chip--success` (зелёный) |

Соответствует разделу 5.3 ТЗ дословно; шкала/проценты не придуманы.

**Выбор строк:** есть (multi-select). При выборе появляется панель массовых
действий (`.pgn-bulk`): «Экспорт выбранных», «Изменить приоритет»,
«Архивировать». На мокапе выбраны 2 строки (демонстрация состояния).

**Текущая строка предпросмотра:** отдельное состояние `.tbl__row--focus` (не
чекбокс) — обозначает, какая строка показана в правой панели. См. допущение
№5: в TableCell нет отдельного «активного»-состояния под мастер-детейл,
переиспользован класс `--focus`.

**Быстрые действия / контекстное меню (⋮):** «Открыть карточку фонда»,
«Добавить встречу», «Запустить анализ идеи», «Изменить приоритет»,
разделитель, «Архивировать» (danger). Реализует «быстрые действия» из
UX-особенностей 6.1 через общий глобальный элемент 5.2 (⋮ у каждой сущности),
отдельных всегда видимых иконок действий, кроме ⋮, на строке нет.

**Пагинация:** 50 строк на странице, переключатель размера страницы, счётчик
диапазона (1 из 3 при 138 записях).

## 7. Панель предпросмотра фонда (правая, инлайн-preview)

Реализует «inline preview (правая панель)» из UX-особенностей 6.1 и правую
зону «Layout системы» (раздел 9 ТЗ). Обновляется при выборе строки в
таблице (описание поведения — раздел 8). На мокапе показана сводка по строке
«РВК — Российская венчурная компания» (текущая строка).

| Блок | Компонент | Содержимое |
|---|---|---|
| Заголовок | `h2` + ContextMenu (⋮) | название фонда, действия |
| Чипы | Chip ×2 | приоритет, тип фонда |
| Профиль | Tile `--headless`, ReadOnlyField ×4 + 1 на всю ширину | бенефициар, активов в портфеле, непрочитанных новостей, последнее взаимодействие, описание (`.tile__grid-full`) |
| Контакты | Tile + Entity `--s` ×3 | аватар, роль, имя, кнопка звонка |
| Быстрые действия | Button ×2 | «Открыть карточку фонда» (accent), «Добавить встречу» (outline) |

Поля профиля — в одну колонку: ширина панели (по умолчанию ~27% рабочей
области, ограничена сплиттером 55–85% для таблицы) даёт ячейку уже 240px,
что по `layout-composition` — единственный случай, когда одна колонка
корректна.

**Второе состояние панели — «Активы фонда» (правка 27.08.2026, приёмка).**
Клик по иконке `folder` в столбце «Активы» строки таблицы (ТЗ 6.1, колонка
«Активы | 📁 (сайдбар)») переключает правую панель на список активов
выбранного фонда. Экран статичен (не кликабельный прототип), поэтому оба
состояния панели отрисованы явно, а не одно вместо другого: профиль — внутри
сплитпейна (см. выше), состояние «Активы фонда» — отдельным блоком
`.fund-assets-alt` сразу под сплитпейном, с чипом «Альтернативное состояние
панели» и подписью, объясняющей триггер.

| Блок | Компонент | Содержимое |
|---|---|---|
| Подпись | Chip `--info` + текст | помечает блок как альтернативное, не постоянно видимое состояние |
| Заголовок | `h2` | «Активы фонда: <название>» |
| Список активов | Tile + Entity `--s` × 4 | ведущая иконка `folder`, Header = «Отрасль · Год», Label = название актива, постфикс = объём, IconButton `chevron-right` — переход в карточку актива |
| Счётчик | `.tile__title-add` + Badge `--text` | «24» — сколько всего активов в портфеле (показаны 4 из 24, по аналогии с сокращённым списком контактов) |
| Действие | Button `--outline` | «Все активы фонда» — переход на экран 6.3 в контексте этого фонда |

Поля взяты по колонкам экрана «Список активов» (ТЗ 6.3): Название, Год,
Объём, Отрасль — без Фонда/Новостей/Истории/Идеи, потому что это уже контекст
одного выбранного фонда, а не весь реестр активов. Полный экран 6.3 не
собирался — вне объёма этой задачи.

| Триггер | Результат |

| Клик по иконке «Активы» в строке | правая панель переключается на список активов этого фонда (сайдбар, по ТЗ «📁 (сайдбар)»); оба состояния отрисованы явно — профиль по умолчанию (`.fund-preview` в сплитпейне) и состояние «Активы фонда» отдельным блоком `.fund-assets-alt` под сплитпейном, с явной подписью и чипом «Альтернативное состояние панели» (правка 27.08.2026, приёмка) |

| Клик по кнопке «Изменить приоритет» (строка/масс.) | по ТЗ не описан результат — открытие инлайн-редактора или модалки не уточнено, см. «Открытые вопросы», п. 2 |
| Прокрутка тела таблицы | шапка таблицы остаётся на месте (липкая) |
| Перетаскивание сплиттера между таблицей и панелью | меняется ширина таблицы/панели, 55–85%, двойной клик — сброс к 73% |
| Сужение окна браузера до 1320px | поле глобального поиска в топбаре сужается 340px → 240px (`@media (max-width: 1320px)`, не `@container screen` — топбар не является потомком `.screen`, см. раздел 3) |

## 14. Доступность

- `<main>` для контентной области, `<nav aria-label="Хлебные крошки">`, `<nav aria-label="Главное меню">`;
- заголовок страницы — единственный `h1`; заголовок панели предпросмотра — `h2`;
- сортировка колонки объявлена через `aria-sort`;
- у всех кнопок-иконок есть `aria-label`, включая ⋮ в каждой строке и в панели;
- группа аватаров в таблице имеет общий `aria-label` со списком имён, отдельные аватары — `aria-hidden` (имя дублируется тултипом только для зрячих пользователей);
- сплиттер — `role="separator"`, `aria-orientation`, `aria-valuemin/max/now`, фокусируем, управляется стрелками;
- контраст — не ниже WCAG AA (обеспечивается токенами ДС).
