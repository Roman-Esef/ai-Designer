# Скилл: Ревизор целостности страниц ДС (линтер)

**Роль:** ревизор. Ищешь тихие ошибки — те, что не видны на скриншоте: забытый парный CSS, ссылку на несуществующий токен, нарушенный контракт разделов, рассинхрон `index.html` / `ds-nav.js` / спек.
**Когда:** перед `check_design_system` и `ready_for_verification` — на каждом новом компоненте, каждой правке компонента, каждом новом экране.
**Вход:** пути страниц, которые ты создал или правил. **Выход:** отчёт линтера + починенные BLOCKER'ы.

Единственный источник истины о целостности — отчёт линтера. **Страницу для перепроверки не читать** (ни целиком, ни «по-быстрому глазами»): всё, что можно посчитать кодом, считает код.

---

## Шаг 1 · Статический аудит (1 вызов `run_script`)

```js
const src = await readFile('scripts/ds-lint.js');
const { run } = new Function('readFile', 'ls', src + ';return dsLint;')(readFile, ls);
log(await run(
  ['pages/atoms/Badge.html'],                    // страницы, которых касалась правка
  { changed: ['pages/atoms/Badge.html'] }        // те же пути, если файл правился в этот заход
));
```

Опции: `changed` — включает C3 (сверку даты «Обновлено» с сегодняшней); `today: 'ДД.ММ.ГГГГ'` — переопределить дату (B3 «вне шкалы 4» тоже печатается только для страниц из `changed` — на старых страницах это чистый шум); `global: false` — не гонять глобальные правила (A3/B6/D3/D4), если страниц много и они уже проверены.

Пустой список страниц = только глобальные правила по проекту.

## Шаг 2 · Живые проверки (1 вызов `eval_js`, страница открыта)

```js
(() => {
  const r = getComputedStyle(document.documentElement);
  const used = [...new Set([...document.documentElement.outerHTML.matchAll(/var\(\s*(--[\w-]+)\s*[),]/g)].map(m => m[1]))];
  const nav = document.querySelector('.ds-nav'), toc = document.querySelector('.ds-toc'), main = document.querySelector('main');
  return {
    emptyTokens: used.filter(t => !r.getPropertyValue(t).trim()),                                    // E1
    nav: nav ? getComputedStyle(nav).position : 'НЕТ', toc: toc ? getComputedStyle(toc).position : 'НЕТ', // E2
    blueLinks: [...document.querySelectorAll('a')].filter(a => /rgb\(0,\s*0,\s*238\)/.test(getComputedStyle(a).color)).length, // E3
    overflow: main ? main.scrollWidth - main.clientWidth : null,                                     // E4
    emptyGen: [...document.querySelectorAll('main [id]')].filter(n => !n.children.length && !n.textContent.trim() && !n.matches('input,textarea,canvas,img,svg,hr,br')).map(n => n.id).slice(0, 8), // E6
    // E7/E8 — усечение проверяется по факту, а не по классам: линтер видит правильную
    // разметку, а на экране контент всё равно вылезает. clipper — ближайший предок,
    // который режет по горизонтали, и умеет ли он прокручиваться.
    ...(() => {
      const clipper = (el) => {
        for (let p = el.parentElement; p && p !== document.body; p = p.parentElement) {
          const ox = getComputedStyle(p).overflowX;
          if (ox !== 'visible') return { el: p, scrollable: ox === 'auto' || ox === 'scroll' };
        }
        return null;
      };
      return {
        cellBleed: [...document.querySelectorAll('.tc, .th')].map(c => {              // E7
          const box = c.getBoundingClientRect();
          const over = [...c.querySelectorAll('*')].reduce((m, n) => {
            const ns = getComputedStyle(n), r = n.getBoundingClientRect();
            if (!r.width || ns.position === 'absolute' || ns.position === 'fixed') return m;
            return Math.max(m, r.right - box.right, box.left - r.left);
          }, 0);
          return over > 1 ? Math.round(over) + 'px · ' + c.className + ' · «' + c.textContent.trim().slice(0, 30) + '»' : null;
        }).filter(Boolean).slice(0, 6),
        rowBleed: [...document.querySelectorAll('.tbl__row')].map(row => {            // E8
          const cl = clipper(row);
          if (!cl || cl.scrollable) return null;
          const over = row.getBoundingClientRect().width - cl.el.clientWidth;
          return over > 1 ? Math.round(over) + 'px за ' + (cl.el.className || cl.el.tagName) : null;
        }).filter(Boolean).slice(0, 4)
      };
    })()
  };
})()
```

Норма: `emptyTokens: []`, `nav`/`toc` — `fixed` или `sticky` (не `static`, не `НЕТ`), `blueLinks: 0`, `overflow ≤ 4`, `emptyGen: []`, `cellBleed: []`, `rowBleed: []`. E5 (ошибки консоли) — `get_webview_logs`.

Три первых пункта — прямое следствие инцидента с `ds-toc.css`: скрипт отработал, стиля нет, ссылки браузерно-синие, панель в потоке. Любой из них поймал бы его.

**E7/E8 — локальный инструмент, не часть ревью-флоу.** Обе проверки требуют открытой страницы, а запуск браузера по скрипту в контуре компании не согласован (`.opencode/rules/ds-rules.md` §9) — как и `docs-split.mjs verify`, они применяются только там, где браузер есть. Обязательный эквивалент без рендера — блокеры **Б24/Б25** сенсора `layout-check.mjs`: помещается ли значение в свою колонку (эвристика ~7px на символ body-s) и не шире ли строка контентной области при отсутствии горизонтального скролла. Ревью-флоу опирается на них, E7/E8 — точнее, но необязательны.

**E7/E8 — почему замер, а не разбор причин (04.09.2026).** За один день усечение в таблицах сломалось тремя разными способами: обёртка рантайма тултипа (`.tip-anchor` без `min-width: 0`), сам Chip (то же), и `min-width: max-content` на всех `.tbl__row`, из-за которого доля-трек (`fr`) разворачивался по содержимому. Разметка во всех трёх случаях была правильной — статический линтер её пропускал, находились дефекты только скриншотом и замером `getBoundingClientRect`. E7 и E8 меряют результат и потому не зависят от причины: **E7** — содержимое ячейки вылезло за её границы (соседняя ячейка непрозрачна и обрежет его без многоточия); **E8** — строка шире контейнера, который её режет и НЕ прокручивается (хвост колонок физически недостижим). Абсолютно позиционированные потомки в E7 не считаются: ручка `.th__resize` и инструменты шапки выходят за границу ячейки намеренно. Обе проверки прогнаны откатом каждого из трёх фиксов — ловят все три, на починенной ДС молчат.

## Что делать с отчётом

- **BLOCKER** — починить до `ready_for_verification`. Механическое (счётчик, забытый `@import`, битая ссылка, пропущенная строка в реестре) — молча. Смысловое (нет обязательного раздела, нативная таблица вместо `.tbl`) — починить и назвать одной строкой в ответе.
- **WARN** — починить, если правка очевидна и локальна; иначе одна строка пользователю.
- **INFO** — не чинить, положить пунктом в раздел «Бэклог» страницы (имя раздела ровно такое, синонимы ловит C5).
- Чистый прогон — одна строка `DS-LINT: чисто`. Ничего не пересказывать, повторно не гонять «на всякий случай».
- Правку делать точечно (`grep` → `str_replace_edit`), по номеру правила и его тексту — без чтения страницы целиком.

## Как расширять

Разобрал инцидент — тем же заходом дописывай класс ошибки в линтер, иначе он повторится.

1. Новая проверка = одна ветка в `pageChecks` (или в `globalChecks` для проектных правил) в `scripts/ds-lint.js` + строка в таблицу выше.
2. **Исключение — «анатомия компонента урезана вместо взятой целиком» (класс F5).** Для этого класса код не пишется заново на каждый инцидент: следующий компонент с обязательными «всегда есть в DOM» узлами (кнопка/блок, которые режим только показывает/прячет CSS-ом, но не порождает) добавляется ОДНОЙ строкой в реестр `ANATOMY_CONTRACTS` в начале `scripts/ds-lint.js` — `{ name, when, require: [[regex, имя узла], …] }`. Общий проверяющий код один для всех записей реестра.
3. Формулировка — машинный признак, а не «посмотреть, нормально ли выглядит».
4. Первый цикл новая проверка живёт как **WARN**; повышается до BLOCKER после подтверждения на реальных страницах.
5. Потолок — ≤ 25 активных правил: новая вытесняет неактуальную.
6. Подавление ложных срабатываний — в белые списки в начале файла (`SVG_OK`, `HEX_OK`, `HEX_ALLOW`, `CSS_NOT_IN_BUNDLE`, `CLASS_IGNORE`, `SKIP_ALL`, `CONTRACT_DIRS`, `REGISTRY_DIRS`), **каждое с комментарием почему**.

`scripts/ds-lint.js` — не браузерный скрипт: на страницах не подключается, запускается только через `new Function` из `run_script`.

## Группа P — гейт парности «документация = код»

Отдельный прогон, страницы не нужны:

```js
const src = await readFile('scripts/ds-lint.js');
const { run } = new Function('readFile', 'ls', src + ';return dsLint;')(readFile, ls);
log(await run([], { global: false, parity: true }));
```

| Код | Что ловит | Уровень |
|---|---|---|
| P1 | Класс из code-fence сниппета в `specs/_cheatsheet.md` или `specs/<Имя>.md`, которого нет ни в одном `styles/*.css` | BLOCKER |
| P2 | Класс в `class="…"` экрана `pages/screens/*.html`, не объявленный ни в ДС, ни в локальном `<style>` экрана | WARN |
| P4 | Класс, который рантайм вешает через `className = '…'` (`scripts/*.js`, inline-`<script>` страниц, `index.html`), отсутствует в CSS. Исключены JS-хуки и локальные классы витрин из инлайн-`<style>` | BLOCKER |
| P3 | Класс из код-панели (`<code>` внутри `scripts/*.page.js`, inline-`<script>` страниц и `index.html`) отсутствует в CSS — страница предлагает скопировать несуществующий класс | BLOCKER |

Игнорируются: утилитарные классы документации (`CLASS_IGNORE`) иклассы состояний `is-` / `js-` / `has-`, которые вешает JS. P4 дополнительно не считает находкой: рантаймы, чьи стили лежат в shadow DOM самого скрипта (`SHADOW_RUNTIMES`, сейчас `image-slot.js`), и корневой BEM-блок, у которого в CSS описаны элементы (`.tfm` при наличии `.tfm__sec`) — имя блока задаёт пространство имён, собственного правила ему не нужно.

Три типовых корня находки P1: (1) композиционный CSS лежит в инлайн-`<style>` страницы-витрины, а не в `styles/` — лечится экстракцией; (2) сниппет обещает модификатор там, где вариант является базой (`chip--readonly`, `inp--m`) — класс убирается из сниппета, в блок чит-шита добавляется строка «база, модификатора нет»; (3) в сниппете чужое имя (`.avatar` вместо `.av`) — сверить с CSS покомпонентно.

D7 (версия и дата страницы = поля спеки) проверяется и вне реестров — `pages/rnd/*` в том числе.

- **Пересчёт K1–K3/K5 скриптом (W5, 13.08.2026)** — 26 компонентов пересчитаны программно из реального CSS (не переоценены руками): K2 по наличию `:is(svg,[data-icon])`, K1 по `:checked`/`:disabled`/`[aria-*="true"]`, K3 по ≥2 признакам `text-overflow:ellipsis`/`min-width:0`/`line-clamp`/`overflow-wrap`, K5 по ссылке на реально существующий `scripts/ds-*.js`. Скрипт только повышает `part`/`no` до `ok` при прямом совпадении с определением критерия, никогда не понижает и не трогает `na` — ложных «ok» из совпадения паттерна без семантики (напр. неверно классифицированный K1) следует перепроверять глазами при следующем разборе компонента.
- **D8: чит-шит без инвариантов/отсылки к спеке** (13.08.2026, RulesAudit W4) — 27 блоков не содержали «**Инварианты:**» (выведены из CSS/страницы каждого компонента, не скопированы), 29 блоков не содержали отсылку к полной спеке. Оба случая закрыты сплошным проходом; правило добавлено в линтер, чтобы новый/правленый блок не регрессировал молча.
- **P4 и локальная раскладка экрана** (12.08.2026): классы, объявленные в `<style>` страницы-экрана и навешиваемые её же скриптом `<имя>.screen.js`, сиротами не считаются. Линтер собирает локальные стили экранов в `localDoc` наравне со страницами компонентов; до правки `.pf-grid` и `.pf-th-tools` давали ложные BLOCKER P4.
- **Классы из ревью 02-Deal-v3** (12.08.2026) — разобраны в аудите правил (страница удалена 20.08.2026), правила линтера — волна W5:
  - `.chip__info` с `aria-haspopup="dialog"` без слоя `.pop` в документе — композиция RiskMetric собрана наполовину: выглядит нормально, не работает.
  - `<i data-icon>` внутри внутреннего слота компонента (`.cb__mark`, `.rb__mark`, `.sw__knob`) — анатомия перевёрстана, глиф получает дефолтные 24px и распирает слот.
  - ряд из двух и более `.tile` без `align-items:stretch` — высоты разъедутся (инвариант `Tile.md`, «Размеры»).
  - `.tabs` горизонтальный без обёртки переполнения (`.tabs-scroll` / `.tabs-overflow`) — ряд вылезает за контейнер.
