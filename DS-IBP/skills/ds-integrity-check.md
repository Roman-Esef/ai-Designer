# Скилл: Ревизор целостности страниц ДС (линтер)

**Роль:** ревизор. Ищешь тихие ошибки — те, что не видны на скриншоте: забытый парный CSS, ссылку на несуществующий токен, нарушенный контракт разделов, рассинхрон `index.html` / `ds-nav.js` / спек.
**Когда:** в конце захода — на каждом новом компоненте, каждой правке компонента, каждом новом экране. Сдавать работу можно только с чистым отчётом.
**Вход:** пути страниц, которые ты создал или правил. **Выход:** отчёт линтера + починенные BLOCKER'ы.

Единственный источник истины о целостности — отчёт линтера. **Страницу для перепроверки не читать** (ни целиком, ни «по-быстрому глазами»): всё, что можно посчитать кодом, считает код.

---

## Шаг 1 · Статический аудит (одна команда в терминале)

```
node scripts/ds-lint-cli.mjs pages/atoms/Badge.html     # страницы, которых касалась правка
node scripts/ds-lint-cli.mjs pages/atoms/*.html         # несколько страниц / маска
node scripts/ds-lint-cli.mjs                            # без аргументов — только глобальные правила
node scripts/ds-lint-cli.mjs --parity                   # гейт парности (группа P, ниже)
```

Запускать из корня ДС, пути — относительные от него. Код выхода: 1 при наличии BLOCKER, иначе 0.
Переданные страницы автоматически считаются изменёнными: включается C3 (сверка даты «Обновлено» с сегодняшней), а B3 («вне шкалы 4») печатается только для них — на старых страницах это чистый шум.

Обычно достаточно `node scripts/ds-check.mjs <страница>` — единый гейт, который сам вызывает линтер и, для страниц на docs-split, структурную проверку и проверку живости (`MAINTAINING.md`, «Проверка: чем гонять»).

## Шаг 2 · Живые проверки (необязательные: нужна страница, открытая в браузере)

Выполняются в консоли браузера на открытой странице. В рабочем контуре этот шаг пропускается (см. абзац про E7/E8 ниже и `.opencode/rules/ds-rules.md` §9) — обязательная часть флоу целиком статическая.

**Поведение рантайма браузера не требует.** Пропуск шага 2 касается геометрии (что где отрисовалось), а не логики. Правка `scripts/ds-*.js` проверяется прогоном в чистом JS-DOM (`linkedom`, ставится в скратчпад вне репозитория — это библиотека, а не браузер, §9 не нарушается): `parseHTML` реальной страницы → загрузить рантаймы через `new Function('window','document','CustomEvent','Event', src)` → `dispatchEvent` → сверить DOM. **Грузить все рантаймы страницы, без заглушек:** они дописывают разметку внутрь чужих слотов, и дефект живёт именно в связке — сортировка `ds-table.js` считала значением ячейки текст вместе с копией, которую туда кладёт `ds-tooltip.js` (уроки Л33, Л34 в `.opencode/skills/screen-review/references/lessons.md`). Прогон с заглушенным соседом проходит и ничего не значит.

```js
(() => {
  const r = getComputedStyle(document.documentElement);
  const used = [...new Set([...document.documentElement.outerHTML.matchAll(/var\(\s*(--[\w-]+)\s*[),]/g)].map(m => m[1]))];
  const nav = document.querySelector('.ds-nav'), toc = document.querySelector('.ds-toc'), main = document.querySelector('main');
  return {
    emptyTokens: used.filter(t => !r.getPropertyValue(t).trim()),                                    // E1
    nav: nav ? getComputedStyle(nav).position : 'НЕТ', toc: toc ? getComputedStyle(toc).position : 'НЕТ', // E2
    blueLinks: [...document.querySelectorAll('a')].filter(a => /rgb\(0,\s*0,\s*238\)/.test(getComputedStyle(a).color)).length, // E3
    overflow: main ? main.scrollWidth - main.clientWidth : null,                                     // E4
    emptyGen: [...document.querySelectorAll('main [id]')].filter(n => !n.children.length && !n.textContent.trim() && !n.matches('input,textarea,canvas,img,svg,hr,br')).map(n => n.id).slice(0, 8), // E6
    // E9 — держатся ли закреплённые колонки при горизонтальном скролле. Замер идёт в том же
    // синхронном такте, что и сдвиг scrollLeft: компоновщик скролл уже применил, а JS ещё не
    // выполнялся — нативный sticky даёт 0, любое JS-удержание отстаёт на весь сдвиг (это и
    // есть кадр, который на трекпаде виден как дрожание). scrollLeft возвращается на место.
    pinHold: (() => {
      const room = (b) => b.scrollWidth - b.clientWidth;
      // .tbl--scroll и .dtable__body бывают вложены друг в друга: берём ту, что реально
      // прокручивается (при равном запасе — внешнюю), иначе одна таблица даст два отчёта
      const boxes = [...document.querySelectorAll('.tbl--scroll, .dtable__body')].filter((b, _, all) =>
        !all.some(o => o !== b && (o.contains(b) || b.contains(o))
          && (room(o) > room(b) || (room(o) === room(b) && o.contains(b)))));
      return boxes.flatMap(box => {
        const pins = [...box.querySelectorAll('.tbl__row')].slice(0, 2)
          .flatMap(r => [...r.children].filter(c => c.matches('.tc--pinned, .th--pinned, [data-pin-side]')));
        if (!pins.length || room(box) < 8) return [];   // держать нечего: закреплённых нет или таблица влезла
        const tag = '.' + (box.className.split(/\s+/)[0] || box.tagName), out = [];
        const loose = pins.filter(p => getComputedStyle(p).position !== 'sticky');
        if (loose.length) out.push(tag + ' · position: ' + getComputedStyle(loose[0]).position
          + ' у ' + loose.length + '/' + pins.length + ' закреплённых ячеек — держит не sticky');
        const D = 400, was = box.scrollLeft, step = was + D <= room(box) ? D : -Math.min(D, was);
        const base = pins.map(p => p.getBoundingClientRect().left);
        box.scrollLeft = was + step;
        const moved = box.scrollLeft - was;
        const drift = pins.map((p, i) => Math.round(p.getBoundingClientRect().left - base[i])).filter(d => Math.abs(d) > 1);
        // перекрытие: в центре закреплённой ячейки нарисована ЧУЖАЯ ячейка ТОЙ ЖЕ строки;
        // внешний хром (липкий футер пагинации, шапка) не считается — он перекрывает законно
        const covered = pins.filter(p => {
          const r = p.getBoundingClientRect();
          if (r.top < 0 || r.bottom > innerHeight || r.width < 4) return false;
          const hit = document.elementFromPoint(r.left + r.width / 2, r.top + r.height / 2);
          return hit && hit !== p && !p.contains(hit) && p.parentElement.contains(hit);
        });
        box.scrollLeft = was;
        if (drift.length) out.push(tag + ' · ' + drift.length + '/' + pins.length
          + ' закреплённых уехали на ' + drift[0] + 'px при сдвиге ' + moved + 'px');
        if (covered.length) out.push(tag + ' · закреплённую перекрывает «' + covered[0].className + '» — z-index');
        return out;
      });
    })(),
    // E7/E8 — усечение проверяется по факту, а не по классам: линтер видит правильную
    // разметку, а на экране контент всё равно вылезает. clipper — ближайший предок,
    // который режет по горизонтали, и умеет ли он прокручиваться.
    ...(() => {
      const clipper = (el) => {
        for (let p = el.parentElement; p && p !== document.body; p = p.parentElement) {
          const ox = getComputedStyle(p).overflowX;
          if (ox !== 'visible') return { el: p, scrollable: ox === 'auto' || ox === 'scroll' };
        }
        return null;
      };
      return {
        cellBleed: [...document.querySelectorAll('.tc, .th')].map(c => {              // E7
          const box = c.getBoundingClientRect();
          const over = [...c.querySelectorAll('*')].reduce((m, n) => {
            const ns = getComputedStyle(n), r = n.getBoundingClientRect();
            if (!r.width || ns.position === 'absolute' || ns.position === 'fixed') return m;
            return Math.max(m, r.right - box.right, box.left - r.left);
          }, 0);
          return over > 1 ? Math.round(over) + 'px · ' + c.className + ' · «' + c.textContent.trim().slice(0, 30) + '»' : null;
        }).filter(Boolean).slice(0, 6),
        rowBleed: [...document.querySelectorAll('.tbl__row')].map(row => {            // E8
          const cl = clipper(row);
          if (!cl || cl.scrollable) return null;
          const over = row.getBoundingClientRect().width - cl.el.clientWidth;
          return over > 1 ? Math.round(over) + 'px за ' + (cl.el.className || cl.el.tagName) : null;
        }).filter(Boolean).slice(0, 4)
      };
    })()
  };
})()
```

Норма: `emptyTokens: []`, `nav`/`toc` — `fixed` или `sticky` (не `static`, не `НЕТ`), `blueLinks: 0`, `overflow ≤ 4`, `emptyGen: []`, `cellBleed: []`, `rowBleed: []`, `pinHold: []`. E5 (ошибки консоли) — смотреть вкладку Console браузера.

Три первых пункта — прямое следствие инцидента с `ds-toc.css`: скрипт отработал, стиля нет, ссылки браузерно-синие, панель в потоке. Любой из них поймал бы его.

**E7/E8/E9 — локальный инструмент, не часть ревью-флоу.** Все три проверки требуют открытой страницы, а запуск браузера по скрипту в контуре компании не согласован (`.opencode/rules/ds-rules.md` §9) — как и `docs-split.mjs verify`, они применяются только там, где браузер есть. Обязательный эквивалент без рендера — блокеры **Б24/Б25** сенсора `layout-check.mjs`: помещается ли значение в свою колонку (эвристика ~7px на символ body-s) и не шире ли строка контентной области при отсутствии горизонтального скролла. Ревью-флоу опирается на них, E7/E8 — точнее, но необязательны. У E9 обязательный эквивалент без рендера — статическое правило **B10**: оно ловит ту же поломку по коду рантайма ДС, но не видит экранные `<script>` и инлайн-обработчики.

**E7/E8 — почему замер, а не разбор причин (04.09.2026).** За один день усечение в таблицах сломалось тремя разными способами: обёртка рантайма тултипа (`.tip-anchor` без `min-width: 0`), сам Chip (то же), и `min-width: max-content` на всех `.tbl__row`, из-за которого доля-трек (`fr`) разворачивался по содержимому. Разметка во всех трёх случаях была правильной — статический линтер её пропускал, находились дефекты только скриншотом и замером `getBoundingClientRect`. E7 и E8 меряют результат и потому не зависят от причины: **E7** — содержимое ячейки вылезло за её границы (соседняя ячейка непрозрачна и обрежет его без многоточия); **E8** — строка шире контейнера, который её режет и НЕ прокручивается (хвост колонок физически недостижим). Абсолютно позиционированные потомки в E7 не считаются: ручка `.th__resize` и инструменты шапки выходят за границу ячейки намеренно. Обе проверки прогнаны откатом каждого из трёх фиксов — ловят все три, на починенной ДС молчат.

**E9 — пара к статическому правилу B10 (04.09.2026).** B10 ловит причину в рантайме ДС (геометрия, посчитанная на событии `scroll`), E9 меряет результат на живой странице и потому не зависит ни от причины, ни от того, чей это код: экранные `<script>` и инлайн-обработчики линтер не обходит вовсе. Приём: сдвинуть `scrollLeft` и снять `getBoundingClientRect()` **в том же синхронном такте**, не отдавая кадр. Это ровно то состояние, в котором браузер рисует кадр при инерционном скролле трекпада: компоновщик новый offset уже применил, JS-обработчик ещё не выполнялся. Нативный `position: sticky` в этом такте даёт 0, любое JS-удержание — весь сдвиг целиком. Три ветки: держит не `sticky` (разбор причины, дёшево), уехали на N px при сдвиге M px (замер результата), закреплённую перекрывает соседняя ячейка той же строки (`elementFromPoint` в центре ячейки — сбитый `z-index`). Внешний хром (липкий футер пагинации, шапка) в перекрытие не засчитывается: он закрывает прокрученную строку законно, а первая редакция проверки на этом давала ложняк на коротком вьюпорте. Таблица, которая целиком влезла в порт, молчит — держать нечего; случай «строку сжали вместо прокрутки» остаётся за E7/E8, дублировать его здесь незачем. Проверено тремя откатами на «Текущем портфеле ДИД»: возврат JS-удержания через `transform` на `scroll` — ловится обеими ветками (`position: static у 6/6`, `6/6 уехали на -400px при сдвиге 400px`), снятый приоритет отрисовки — третьей, починенная ДС молчит на четырёх размерах окна (1280×700, 1600×400, 1600×500, 1900×900).

## Что делать с отчётом

- **BLOCKER** — починить до сдачи работы. Механическое (счётчик, забытый `@import`, битая ссылка, пропущенная строка в реестре) — молча. Смысловое (нет обязательного раздела, нативная таблица вместо `.tbl`) — починить и назвать одной строкой в ответе.
- **WARN** — починить, если правка очевидна и локальна; иначе одна строка пользователю.
- **INFO** — не чинить, положить пунктом в раздел «Бэклог» страницы (имя раздела ровно такое, синонимы ловит C5).
- Чистый прогон — одна строка `DS-LINT: чисто`. Ничего не пересказывать, повторно не гонять «на всякий случай».
- Правку делать точечно (`grep` → замена найденного фрагмента), по номеру правила и его тексту — без чтения страницы целиком.

## Как расширять

Разобрал инцидент — тем же заходом дописывай класс ошибки в линтер, иначе он повторится.

1. Новая проверка = одна ветка в `pageChecks` (или в `globalChecks` для проектных правил) в `scripts/ds-lint.js` + строка в таблицу выше.
2. **Исключение — «анатомия компонента урезана вместо взятой целиком» (класс F5).** Для этого класса код не пишется заново на каждый инцидент: следующий компонент с обязательными «всегда есть в DOM» узлами (кнопка/блок, которые режим только показывает/прячет CSS-ом, но не порождает) добавляется ОДНОЙ строкой в реестр `ANATOMY_CONTRACTS` в начале `scripts/ds-lint.js` — `{ name, when, require: [[regex, имя узла], …] }`. Общий проверяющий код один для всех записей реестра.
3. Формулировка — машинный признак, а не «посмотреть, нормально ли выглядит».
4. Первый цикл новая проверка живёт как **WARN**; повышается до BLOCKER после подтверждения на реальных страницах.
5. Потолок — ≤ 25 активных правил: новая вытесняет неактуальную.
6. Подавление ложных срабатываний — в белые списки в начале файла (`SVG_OK`, `HEX_OK`, `HEX_ALLOW`, `CSS_NOT_IN_BUNDLE`, `CLASS_IGNORE`, `SKIP_ALL`, `CONTRACT_DIRS`, `REGISTRY_DIRS`), **каждое с комментарием почему**.

`scripts/ds-lint.js` — не браузерный скрипт и не исполняемый сам по себе: на страницах не подключается, ждёт хелперы `readFile`/`ls`. Запускать только через обёртку `scripts/ds-lint-cli.mjs` (она даёт хелперы через `node:fs`) или через гейт `scripts/ds-check.mjs`.

## Группа P — гейт парности «документация = код»

Отдельный прогон, страницы не нужны:

```
node scripts/ds-lint-cli.mjs --parity
```

| Код | Что ловит | Уровень |
|---|---|---|
| P1 | Класс из code-fence сниппета в `specs/_cheatsheet.md` или `specs/<Имя>.md`, которого нет ни в одном `styles/*.css` | BLOCKER |
| P2 | Класс в `class="…"` экрана `pages/screens/*.html`, не объявленный ни в ДС, ни в локальном `<style>` экрана | WARN |
| P4 | Класс, который рантайм вешает через `className = '…'` (`scripts/*.js`, inline-`<script>` страниц, `index.html`), отсутствует в CSS. Исключены JS-хуки и локальные классы витрин из инлайн-`<style>` | BLOCKER |
| P3 | Класс из код-панели (`<code>` внутри `scripts/*.page.js`, inline-`<script>` страниц и `index.html`) отсутствует в CSS — страница предлагает скопировать несуществующий класс | BLOCKER |

Игнорируются: утилитарные классы документации (`CLASS_IGNORE`) иклассы состояний `is-` / `js-` / `has-`, которые вешает JS. P4 дополнительно не считает находкой: рантаймы, чьи стили лежат в shadow DOM самого скрипта (`SHADOW_RUNTIMES`, сейчас `image-slot.js`), и корневой BEM-блок, у которого в CSS описаны элементы (`.tfm` при наличии `.tfm__sec`) — имя блока задаёт пространство имён, собственного правила ему не нужно.

Три типовых корня находки P1: (1) композиционный CSS лежит в инлайн-`<style>` страницы-витрины, а не в `styles/` — лечится экстракцией; (2) сниппет обещает модификатор там, где вариант является базой (`chip--readonly`, `inp--m`) — класс убирается из сниппета, в блок чит-шита добавляется строка «база, модификатора нет»; (3) в сниппете чужое имя (`.avatar` вместо `.av`) — сверить с CSS покомпонентно.

  **Почему правило структурное, а не адресное.** Первая редакция искала виновных — классы, которые где-то в репозитории действительно переключают атрибутом. Разметочный признак (тег с `class` и голым `hidden`) поймал 1 случай из 6: все реальные дефекты рантаймовые. Признак «файл присваивает `.hidden` и упоминает класс» дал 49 находок с очевидными ложняками (`.modal__head`, `.inp__field`) — элемент почти всегда получают через переменную или чужую функцию, а не селектором в точке присваивания, и без межфункционального анализа связь класса с `.hidden` не восстановить. Поэтому правило не ищет виновных, а закрывает возможность (доктрина `ds-rules.md` §9 «что нельзя измерить — делаем структурно невозможным»): корень компонента, объявивший `display`, обязан рядом объявить и `[hidden]`. Цена соблюдения — одна строка на компонент.
  Проверено откатом фикса: с убранным `.chip[hidden]` правило называет `.chip`, с возвращённым — молчит про него и продолжает показывать непочиненный `.chiplist` в том же файле. Три корня внесены в `HIDDEN_PAIR_OK` с причиной (`.screen`, `.nav-layout` — каркасы страницы, существуют в единственном экземпляре; `.chart-host` — слот, скрывают контейнер-потребитель). Долг закрыт в тот же день: пары проставлены всем 80 корням в 44 файлах одним заходом, правило поднято с INFO до WARN. Проверено дымовым прогоном по всем 57 страницам ДС — базовый `display` компонентов на месте, `hidden` скрывает и снимается без остатка.
- **B10 — геометрия, посчитанная на событии `scroll` (04.09.2026)**: в реестре «Текущий портфель ДИД» закреплённые колонки дрожали при горизонтальном скролле на MacBook — уезжали вместе с контентом и возвращались на место, циклично, пока идёт скролл. На Windows дефект не воспроизводился вовсе. Причина: `tbl-pin.js` удерживал колонки через `transform: translateX`, пересчитывая его в обработчике `scroll`. Скролл применяет компоновщик браузера, и новый offset попадает в кадр РАНЬШЕ, чем выполнится JS-обработчик, — коррекция физически не может успеть в тот же кадр. Дискретное колесо мыши это скрывает (правка успевает в паузу между щелчками), непрерывные дельты трекпада с инерционным докрутом показывают ошибку на каждом кадре подряд. Усугубляли два места: `requestAnimationFrame` внутри хендлера (ещё кадр задержки) и `getBoundingClientRect()` по всем ячейкам шапки на каждый кадр (forced reflow). Починка: удержание переведено на нативный `position: sticky`, рантайм считает только инсеты `left`/`right` и пишет их по `columnpin`/`columnreorder`/resize/ResizeObserver шапки (TableCell 2.013). Попутно опровергнута предпосылка, на которой держалась JS-реализация: `position: sticky` работает и для колонок grid-раскладки — проверено на стенде и на экране, держатся и многоколоночный левый блок, и хвостовой правый. Правило проверено откатом фикса: возвращённый scroll-хендлер ловится, на починенной ДС молчит; шесть легальных записей (плавающие слои Tooltip, Popover, DropdownList, Menu, DatePicker, rail-подписи NavPanel) внесены в `SCROLL_GEOMETRY_OK` с причиной — им пересчёт при скролле обязателен, CSS-эквивалента нет.
