# Генератор панели и реестра

`scripts/ds-registry.js` сканирует файлы проекта продукта и строит машинный реестр
`registry.json`. `admin.html` в этой папке — человеческая витрина поверх него: сам не
хранит данных, просто читает `registry.json` рядом с собой.

## Как использовать в проекте продукта

1. Скопировать `templates/admin/admin.html` в корень проекта продукта (рядом с `_ds/`).
   Поправить путь до стилей: `../../ds.css` → `_ds/<папка ДС>/ds.css`, так же для
   `icons-data.js`/`ds-icons.js`.
2. Сгенерировать реестр — `run_script` в проекте продукта:

   ```js
   const src = await readFile('_ds/<папка ДС>/scripts/ds-registry.js');
   const { build } = new Function('readFile', 'ls', src + ';return dsRegistry;')(readFile, ls);
   const reg = await build({ ls, readFile, rulesVersion: '<версия LocalComponents.html в ДС>' });
   await saveFile('registry.json', JSON.stringify(reg, null, 2));
   ```

3. Открыть `admin.html`.

## Когда перегенерировать

После любой правки паспорта компонента (`kit/components/<Имя>/<Имя>.md`) или документа
экрана (`screens/<id>.md`). Реестр не редактируется руками никогда — расхождение это
не потерянная правка, а сигнал, что реестр устарел.

## Что попадает в «Расхождения»

Компонент без паспорта · пустое обязательное поле паспорта или документа экрана ·
незаполненные строки таблиц в теле паспорта (остался шаблон) · экран ссылается на
несуществующий компонент · требование упомянуто, но файла `requirements/<БТ>.md` нет ·
паспорт заполнен по устаревшей версии правил (`rulesVersion`) · экран без парного
`.frag.html` · компонент, на который не ссылается ни один экран.

## Что генератор НЕ проверяет (пока)

- Содержимое полей `fields`/`sources`/`roles`/`states`/`overflow` в теле паспорта —
  только факт, что раздел не остался пустым шаблоном.
- Существование документов базы знаний (`knowledge`) — библиотека внешняя, реестр её
  не читает, только собирает ссылки.
- Компоненты `ds:`, реально существующие в ДС — список компонентов ДС в реестр пока
  не передаётся.
