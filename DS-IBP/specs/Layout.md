> Спека для быстрого контекста. Источник истины — CSS-файл и страница. При изменении обновляй эту спеку и блок в specs/_cheatsheet.md.

## Назначение
Правила построения любого экрана продукта: из каких зон складывается страница, какие у зон размеры и поля, что скроллится, а что залипает. Все экраны — стартовая с навигационными тайлами, реестр с таблицей, карточка сущности — строятся по одному каркасу: панель навигации слева, рабочая область справа, внутри рабочей области зона крошек над контентной областью.

## Инварианты
- Между панелью навигации и рабочей областью отступа нет — шов вплотную; отступ слева резервирует сам `.nav-layout` (56px в rail/drawer, 320px в fixed).
- Между зоной крошек и контентной областью отступ 8px — контент начинается через 8px под крошками (у контентной области `padding-top: 8px`, токен `--layout-pad-top`).
- Поля контентной области — 8px сверху, 24px слева и справа, 24px снизу. Другого значения полей у экрана нет: полноэкранных режимов, снимающих боковые поля, в продукте нет.
- Зона крошек — 44px и поля 24px по бокам — принадлежит компоненту Breadcrumbs, экран их не задаёт и не переопределяет.
- Крошки и контент выровнены по одной вертикали: поля зоны крошек совпадают с полями контентной области.
- Контентная область резиновая; на узком окне раскладка перестраивается по брейкпоинтам (блоки меняют число колонок и переходят один под другой), горизонтального скролла нет. **У экрана горизонтального скролла не бывает никогда** — адаптивная вёрстка закладывается при проектировании, а не постфактум; объект, выходящий за границу экрана, — баг. Исключение — контейнер, у которого скролл заложен в собственной раскладке: тело таблицы или отдельный тайл (не сама рабочая область). Шаги считаются от ширины рабочей области, а не окна: `.screen` объявлен размерным контейнером (`container-type: inline-size; container-name: screen`), экран пишет `@container screen (max-width: …)`. Причина — закрепление панели сужает контент на 216px без изменения вьюпорта: это общее для всех страниц, панель можно закрепить на любом экране. Общих для ДС значений пока нет, шаги задаёт экран (карточка сделки: 1560 / 1240 / 900px). Порог базово задаётся на уровне экрана; для экранов, где ширина контентной области меняется отдельно (растягиваемая правая панель), может понадобиться свой порог от ширины именно контентной области — точная формулировка правила не зафиксирована, см. бэклог страницы.
- Вертикальный ритм экрана-реестра — **12px**, а не 24px: заголовок страницы → зона тулбара (`.dtable-toolbar`) → таблица стоят плотнее, потому что это одна связка «что показываем — как отобрано — данные». Значение задаёт экран одной строкой `.screen__content { gap: var(--space-12) }` — единственная раскладочная строка экрана-реестра и единственное разрешённое отклонение от ритма 24px.
- У стартовой страницы контентная область содержит один блок — сетку групп, поэтому зазор блоков не работает ни разу: весь видимый ритм — 16px зазора сетки (`--grid-gutter`), одинаковый по горизонтали и по вертикали. Экран для этого ничего не пишет.
- Нижнее поле 24px одинаково для всех типов контента. Собственного отступа под таблицей нет: добавочный `margin-bottom` у `.dtable` — ошибка, из-за него таблица перестаёт совпадать по низу с тайлами и карточками.
- Крошки залипают у верхней кромки (`position: sticky`), скроллится только контент.
- Панель навигации со страницей не скроллится: `position: fixed; height: 100vh`; внутри у списка пунктов (`.nav__list`) собственный скролл, верхний блок и подвал панели неподвижны.
- Колоночная сетка не дублируется в layout.css — это `.grid12` + `.col-N` из Spacing (12 колонок, зазор 16px).

## Диагностика
- «Крошки и заголовок страницы стоят на разных вертикалях» → у зоны крошек или контентной области переопределены поля; должно быть 24px и там, и там
- «Между крошками и контентом зазор не 8px» → у `.screen__content` переопределён `padding-top` (должен быть `var(--space-8)`) или у `.crumbs` задан `margin-bottom` (должен быть 0)
- «При скролле крошки уезжают вверх» → `.crumbs` не прямой ребёнок `.screen` (правило sticky навешено на `.screen > .crumbs`)
- «Контент прижат к панели навигации» → потерян `.nav-layout` вокруг панели и рабочей области
- «На узком шаге группы стартовой страницы остались в 2 колонки вместо одной» → правило третьего шага написано ниже по специфичности, чем правило пары (`.grid12 > [class*="colw-"]`, (0,2,0)); писать его с той же специфичностью и ниже по файлу
- «Под таблицей отступ больше 24px» → у `.dtable` (или контентной области) задан лишний `margin-bottom`; нижнее поле даёт каркас, своего отступа у таблицы нет
- «На реестре между заголовком, фильтром и таблицей 24px» → экран не задал `.screen__content { gap: var(--space-12) }`

## Ключевые правила (из разделов страницы)
- **Использование** — Каркас обязателен для любого экрана продукта. Экран решает состав контента, каркас — зоны и поля. Единственное исключение — страницы вне приложения (логин, ошибка), где панели навигации и крошек нет.
- **Анатомия** — Три зоны: NavPanel (`.nav`, слева, фиксирована) · зона крошек (`.crumbs`, 44px, залипает) · контентная область (`.screen__content`, поля 24px). Обёртки: `.nav-layout` (панель + рабочая область), `.screen` (рабочая область).
- **Варианты** — По режиму навигации: rail (56px), drawer (оверлей поверх rail-отступа), fixed (320px, контент ужимается). По контенту: стартовая страница (`.grid12`, группа `.col-3 colw-6`), таблица во всю ширину контентной области, карточка сущности. Крошки есть всегда, кроме Дашборда. **По высоте вьюпорта**: обычный (`.screen`, страница растёт под контент и скроллится) и **app-shell** (`.screen--app`: рабочая область фиксирована на высоту вьюпорта, `height:100vh; overflow:hidden`, контентная область `min-height:0`) — для экранов, чей главный блок — таблица на всю свободную высоту (`.dtable--fill`, см. Table).
- **Стартовая страница (состав и отступы)** — Шапки страницы нет, заголовок несёт каждая группа; контентная область содержит один блок — сетку групп. Зона крошек (44px) на главной без трейла: одна крошка, она же текущая страница. Сетка — `.grid12` (12 резиновых колонок, зазор 16px), группа — `.col-3 colw-6` (4 группы в ряд), внутри группы заголовок H5 Strong и тайлы NavTile (ширина от колонки, высота от 190px) с тем же зазором 16px. Фоновая иллюстрация — `cover`, `opacity .6`, за контентом. Перестроение — три шага (4 → 2 → 1 группы в ряд, пороги главной 1700 / 900px): первые два даёт штатная пара `.col-N`/`.colw-N`, третий экран дописывает своим правилом. Рабочая область обычная, без `.screen--app`: страница скроллится.
- **Экран-реестр (состав и отступы)** — Порядок блоков фиксирован: зона крошек (44px, залипает) → 8px → шапка страницы `.phead` (40px без подзаголовка, высота Button M) → 12px → зона тулбара `.dtable-toolbar` (32px, без подложки: слева TableFilter, справа настройка колонок) → 12px → таблица `.dtable--fill` на весь остаток высоты → 24px нижнее поле. Внутри таблицы — липкая шапка колонок, скроллящееся тело, закреплённый футер пагинации (56px); экран их высоты не считает. Свободная высота таблицы при вьюпорте 900px: 900 − 44 − 8 − 40 − 12 − 32 − 12 − 24 = 728px. Фильтр и настройка колонок живут в зоне тулбара, а не в шапке страницы: в шапке — действия над сущностями («Новая сделка»), в зоне тулбара — управление выборкой; счётчик записей не дублируется в заголовке и остаётся в футере пагинации.
- **Высота главной таблицы** — Если на странице одна таблица (или она — основной контентный блок), она занимает **всю свободную высоту экрана** за вычетом отступов контента, крошек, шапки страницы и тулбара/фильтра таблицы: на `.screen` ставится `.screen--app`, на таблицу — `.dtable--fill`; тело таблицы скроллится внутри, крошки/шапка/тулбар/футер закреплены. Если над/под таблицей есть тайлы — случай разбирается индивидуально, но, как правило, таблица всё равно занимает всю оставшуюся высоту (с учётом тайлов) — та же `.screen--app` + `.dtable--fill`.
- **Размеры** — Отступ панели: 56px / 320px (fixed). Зона крошек: высота 44px, padding 16/24/12. Контентная область: padding 8px 24px 24px. Вертикальный ритм блоков контента: 24px; у экрана-реестра — 12px; у стартовой страницы виден зазор сетки 16px. Шапка страницы: 40px без подзаголовка. Зона тулбара реестра: 32px.
- **Контент** — Заголовок страницы — PageHeader, первый блок контентной области. У экрана-реестра порядок блоков не выбирается: шапка → зона тулбара → таблица. Далее блоки в один поток с зазором 24px; последний заканчивается полем 24px — закреплённого снизу подвала действий в продукте нет. Горизонтальная структура — сетка `.grid12`, вертикальная — шкала Spacing.
- **Поведение** — Скроллится только контент; крошки залипают; панель фиксирована на высоту вьюпорта, её список прокручивается сам. Переключение режима панели меняет отступ слева чистым CSS (`:has()`), контент ужимается. На узком окне раскладка перестраивается по брейкпоинтам, горизонтального скролла нет.
- **Состояния** — Собственных нет: каркас статичен, состояния принадлежат вложенным компонентам.
- **Доступность** — Ориентиры: `<nav aria-label="Главное меню">`, `<nav aria-label="Хлебные крошки">`, `<main>` для контентной области. Порядок в DOM = порядок чтения: панель → крошки → контент.
- **Типографика** — Не применимо: каркас текста не содержит.
- **Цвета** — Фон рабочей области и зоны крошек — `--bg-page`; фон панели — `--bg-mainmenu`; поверхности контента (тайлы, таблицы) — `--bg-tile`.

## Для разработчиков (выжимка)

### Точные размеры (redline)
Таблица рендерится на странице через getComputedStyle на живом каркасе. Значения — токены в `styles/layout.css` (`--layout-*`), `styles/nav-panel.css`, `styles/breadcrumbs.css`.

### Разметка · HTML (эталонная реализация ДС)

```
<div class="nav-layout">
  <nav class="nav nav--rail" aria-label="Главное меню">…</nav>
  <div class="screen">
    <nav class="crumbs" aria-label="Хлебные крошки" data-breadcrumbs>
      <li class="crumbs__item"><a class="link link--muted" href="/">Главная</a></li>
      <li class="crumbs__item crumbs__item--current"><span class="crumbs__current" aria-current="page">Коды RWA</span></li>
    </nav>
    <main class="screen__content">
      <header class="phead">…PageHeader…</header>
      <div class="grid12"><section class="col-3">…</section></div>
    </main>
  </div>
</div>
```

### Справочник классов и атрибутов

| Класс/атрибут | Назначение |
|---|---|
| `.nav-layout` | Обёртка панели и рабочей области; резервирует отступ слева по режиму панели (NavPanel) |
| `.screen` | Рабочая область: колонка, `min-height:100vh`,, фон `--bg-page` |
| `.screen > .crumbs` | Зона крошек: sticky у верхней кромки, `z-index:3`, фон `--bg-page` |
| `.screen__content` | Контентная область: `padding: 8px 24px 24px`, колонка с зазором 24px |
| `.screen--app` | Вариант app-shell: фикс. вьюпорт (`height:100vh; overflow:hidden`), `.screen__content` — `min-height:0`; для главной таблицы на всю высоту |
| `.grid12` / `.col-N` | Колоночная сетка (Spacing): 12 колонок, зазор 16px |
| `--layout-pad-top` / `--layout-pad-x` / `--layout-pad-bottom` / `--layout-crumbs-h` / `--layout-block-gap` | Токены каркаса: 8px / 24px / 24px / 44px / 24px |
| `.dtable-toolbar` + `.dtable--fill` | Блоки экрана-реестра (Table): зона тулбара 32px над таблицей и таблица на остаток высоты; ритм между блоками 12px задаёт экран |
