> Спека для быстрого контекста. Источник истины — CSS-файл и страница компонента. При изменении компонента обновляй эту спеку и блок в specs/_cheatsheet.md.

## Назначение
Ряд табов **второго уровня** — навигация по подразделам внутри раздела, выбранного на первом уровне. Сегменты лежат в общем треке, но, в отличие от SegmentControl, высота трека равна высоте сегмента: выбранный подраздел закрашен акцентом от края до края, обводки трека вокруг него не остаётся. Три размера — M 40, S 32, XS 24 — в пару к размеру первого уровня.

## Инварианты
- **Не самостоятельный компонент.** `.subtabs` применяется только на экране, где есть ряд табов первого уровня (`.tabs--horiz` с `.tab`), и размещается как содержимое выбранного таба первого уровня — под его рядом. Одиночный `.subtabs` без первого уровня — дефект: механика заливки сама по себе не сообщает, что уровень подчинённый, и экран читается как один уровень навигации с необычным видом. Охраняется правилом B14 линтера.
- **Ёмкость 2–5 пунктов, переполнения нет by design.** Трек не переносится (`flex-wrap: nowrap`) и не скроллится; ни скролла со стрелками, ни меню «Ещё» у компонента не будет. Ряд шире контейнера — сигнал, что раздел разбит неверно, а не случай для рантайма. Нужно 6+ подразделов — второй уровень собирается на Tab (`.tab--s` + `.tabs--bare`), где переполнение решено.
- **Роль навигационная, несмотря на сегментированный вид:** `role="tablist"` / `role="tab"` + `aria-selected`, а не `radiogroup` SegmentControl. Семантика идёт от задачи, а не от формы.
- **Размер не крупнее первого уровня.** Рекомендованный выбор — шаг вниз по общей с Tab шкале (`.tab--m` 40 → `.subtabs--s` 32, `.tab--s` 32 → `.subtabs--xs` 24): различимость уровней держится на двух признаках сразу, размере и механике выделения. Равный размер допустим, когда второй уровень — главный переключатель экрана. Второй уровень **крупнее** первого — инверсия иерархии и запрещён. Правило держится текстом и приёмкой: линтер его не стережёт (решение 11.09.2026, механизируемо — в бэклоге).
- **Базовый размер — S.** Бареный `.subtabs` без модификатора = 32 px: базовый размер компонента тот, что стоит в паре с базовым первым уровнем `.tab--m`. Это отличается от Tab и SegmentControl, где корень по умолчанию M, — там M и есть их собственный базовый случай.
- **Иконок нет.** Ориентации и тонов тоже: второй уровень обязан оставаться однообразным, иначе начинает конкурировать с первым.
- **Начертание подписи не меняется при выборе.** Вес выделения несёт заливка; смена начертания меняла бы ширину сегмента, и ряд «прыгал» бы при каждом переключении.
- Корень компонента объявляет парное `[hidden] { display: none }` — соглашение ДС, правило B11 линтера.
- Disabled-сегмент помечается `aria-disabled="true"`, а не нативным `disabled`: иначе он выпадает из roving-порядка (как у Tab, RulesAudit W1).

## Ключевые правила (из разделов страницы)
- **Использование** — Переключает подразделы одного раздела («Сделка» → «Общая информация» / «Условия» / «Документы» / «История»). Обязательный контекст — ряд первого уровня на том же экране. Одиночный ряд переключения вьюх — это Tab; выбор значения параметра (период, единицы) — SegmentControl.
- **Анатомия** — Общий трек, внутри которого сегменты лежат вплотную. Форму крайним сегментам задаёт трек: он скруглён и подрезает заливку через `overflow: hidden`, поэтому у первого и последнего углы скруглены, а у средних края прямые. Отдельного элемента-индикатора нет — выбранный сегмент красится сам. Разделитель 1 px между соседними невыбранными гаснет у выбранного, у его правого соседа и вокруг наведённого.
- **Варианты** — Одна ось: счётчик. Счётчик — реальный атом Badge в варианте `.badge--neutral`: светлая плашка читается и на треке, и на акцентной заливке, поэтому цвет счётчика не меняется ни в одном состоянии. Размер плашки идёт за размером ряда и задаётся классом самого Badge в разметке (`.badge--xs` в M, `.badge--xxs` в S и XS) — перекрывать габариты чужого компонента из `sub-tab.css` нельзя.
- **Размеры** — Три: M 40 / `--type-body-m` / паддинг 16 / зазор 8; S 32 / `--type-body-s` / 12 / 6; XS 24 / `--type-body-xs` / 8 / 4. Высота трека равна высоте сегмента во всех трёх — паддинга у трека нет ни в одном. M и S совпадают с размерным рядом Tab: компоненты стоят в паре, и шаг вниз возможен только при общей шкале. Скругление принадлежит треку: `--radius-control` (8) в M и S, `--radius-control-s` (6) в XS; сегменты не скруглены вовсе. Размерный класс ставится **на трек** (`.subtabs--m|--s|--xs`), а не на сегмент.
- **Контент** — Короткая подпись подраздела и опциональный числовой счётчик. Иконок нет: иконка добавляет вес, которого уровню не положено, и съедает ширину трека. Подпись не усекается и не переносится (`white-space: nowrap`) — ряд из длинных подписей просто становится шире, и это сигнал сократить подписи. Тултипа усечения нет, потому что нет усечения.
- **Поведение** — Клик и клавиатура — из рантайма `ds-tabs.js` (хук `data-subtabs`). Ничего измеряемого в компоненте нет: индикатор не двигается, ширина не пересчитывается, шрифтовые метрики на раскладку не влияют. Трек залит полупрозрачным `--st-system-light`, поэтому «темнит» подложку; компонент рассчитан на белую поверхность `--bg-tile`, на сером `--bg-page` границы ряда читаются слабее.
- **Состояния** — Default · Hover = Focus · Selected · Selected + Hover · Disabled. Отдельного состояния нажатия (Active) нет, как и у Tab: заливка держится как hover, пока курсор не покинет сегмент. Счётчик цвет не меняет ни в одном состоянии.
- **Доступность** — `role="tablist"` с обязательным `aria-label`, называющим раздел первого уровня («Подразделы раздела «Сделка»»); сегмент — `role="tab"` с `aria-selected`. Roving tabindex: в таб-последовательности только выбранный сегмент. Выбор передан заливкой, а не только цветом подписи — 1.4.1 выполняется. **Принятое отступление:** белая подпись на `--primary` даёт 2.91:1 при норме 4.5:1 (1.4.3) — ровно то же, что у `.btn--accent` и `.chip--primary-solid`; это свойство акцентного тона ДС, вопрос ведётся в общем бэклоге и решается на уровне токена. `--primary-dark` (#007A6D) даёт 5.24:1 и остаётся готовым решением.
- **Типографика** — SB Sans Text, Regular во всех состояниях включая выбранное (вес выделения несёт заливка, иначе ряд «прыгал» бы по ширине). Подпись: M `--type-body-m` (16/20), S `--type-body-s` (14/16), XS `--type-body-xs` (12/16). Счётчик: M `--type-body-s`, S и XS `--type-body-xs`. letter-spacing 0 во всех.
- **Цвета** — Трек `--st-system-light` (Swamp_400 16 %), разделитель `--border-primary`. Невыбранный — `--text-secondary`, при наведении `--text-primary` + заливка `--primary-bg`. Выбранный — заливка `--primary`, подпись `--text-on-dark`; выбранный + наведение — `--primary-dark`. Disabled — `--text-inactive`. Счётчик — Badge neutral, от состояния сегмента не зависит.

## Диагностика
- «Ряд второго уровня выдавливает раскладку / вылезает за контейнер» → пунктов больше пяти. Переполнения у компонента нет by design — либо сократить состав раздела, либо собирать второй уровень на `.tab--s` + `.tabs--bare`
- «Два ряда навигации читаются как один уровень» → размеры совпали. Это допустимо, но различимость держится тогда на одной механике выделения — взять шаг вниз: `.tab--m` → `.subtabs--s`, `.tab--s` → `.subtabs--xs`
- «Подразделы весят больше, чем раздел» → второй уровень крупнее первого, инверсия иерархии. Запрещено правилом пары; линтер это не ловит, сверять размеры на приёмке
- «Отключённый подраздел выпадает из клавиатурной навигации» → должен быть `aria-disabled="true"`, не атрибут `disabled`
- «Фокусное кольцо не видно на выбранном сегменте» → ожидаемо перекрашено: `--primary` на `--primary` невидим, на выбранном кольцо `--text-on-dark`
- «Границы ряда почти не видны» → трек полупрозрачный; на `--bg-page` и внутри тайлов тональный шаг мал — класть ряд на белую плашку `--bg-tile`

## Для разработчиков (выжимка)

### Разметка · HTML (эталонная реализация ДС)

```
<!-- ряд первого уровня обязателен: без него второй уровень не применяется -->
<div class="tabs tabs--horiz" role="tablist" data-tabs aria-label="Разделы сделки">
  <button type="button" class="tab tab--m tab--selected" role="tab" aria-selected="true" tabindex="0">
    <span class="tab__label">Сделка</span>
  </button>
  <button type="button" class="tab tab--m" role="tab" aria-selected="false" tabindex="-1">
    <span class="tab__label">ЦУП</span>
  </button>
</div>

<!-- второй уровень; размер — шаг вниз от первого: .tab--m → .subtabs--s -->
<div class="subtabs subtabs--s" role="tablist" data-subtabs aria-label="Подразделы раздела «Сделка»">

  <button type="button" class="subtab" role="tab" aria-selected="true" tabindex="0">
    <span class="subtab__label">Общая информация</span>
  </button>

  <button type="button" class="subtab" role="tab" aria-selected="false" tabindex="-1">
    <span class="subtab__label">Документы</span>
    <!-- опциональный счётчик — реальный Badge, вариант neutral -->
    <span class="badge badge--neutral badge--xxs">12</span>
  </button>

  <!-- отключённый — aria-disabled, не нативный disabled -->
  <button type="button" class="subtab" role="tab" aria-selected="false" tabindex="-1" aria-disabled="true">
    <span class="subtab__label">История</span>
  </button>
</div>
```

### Рантайм ДС — `scripts/ds-tabs.js`

Общий рантайм Tab, SegmentControl и SubTab: roving tabindex, навигация
стрелками (← → и ↑ ↓), Home / End, активация выбора на месте, пропуск
отключённых. `subtabs()` отличается от `tabs()` только тем, чего в нём **нет**:
переполнения и подскролла выбранного. Индикатор не измеряется — выбранный
сегмент красит CSS по `[aria-selected]`.

Подключение — opt-in атрибутом на контейнере (чтобы рантайм не «оживлял»
статичные примеры состояний в витрине):

```
<div class="subtabs subtabs--s" role="tablist" aria-label="Подразделы" data-subtabs>…</div>
```

API: `DSTabs.subtabs(el, opts)`; возвращает `{ el, items(), select(elOrIndex), value(), refresh() }`,
`opts.onChange(index, el)` — коллбэк смены выбора. Обход всех хуков — `DSTabs.wireAll(root)`.

### Поведение · псевдокод (framework-agnostic)

```
// 0. ПРЕДУСЛОВИЕ: ряд второго уровня рендерится только внутри выбранного таба
//    первого уровня. Компонент без первого уровня не собирается.

// 1. Клик/Enter/Space по сегменту → снять aria-selected со всех, поставить на текущий,
//    tabIndex текущего = 0, у остальных = -1 (roving tabindex)

// 2. Клавиатура на [role="tablist"] — активация НА МЕСТЕ:
//    ArrowRight/ArrowDown → следующий доступный (зациклено)
//    ArrowLeft/ArrowUp    → предыдущий доступный (зациклено)
//    Home / End           → первый / последний доступный

// 3. Hover = Focus — единый визуальный слой, отдельного pressed нет

// 4. Разделители — производная от состояния соседей: линия скрыта у первого
//    сегмента, у выбранного, у соседа справа от выбранного и вокруг наведённого

// 5. Disabled: aria-disabled="true" (НЕ нативный disabled), pointer-events:none, tabIndex=-1

// 6. Переполнения НЕТ: ни скролла, ни меню «Ещё»
```
