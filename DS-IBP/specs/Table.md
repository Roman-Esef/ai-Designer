> Спека для быстрого контекста. Источник истины — CSS-файл и страница компонента. При изменении компонента обновляй эту спеку и блок в specs/_cheatsheet.md.

## Назначение
Контейнер-организм таблицы/реестра: Toolbar (заголовок + счётчик + фильтр/действия) + прокручиваемое тело с липкой шапкой + Footer (Pagination). Table не рисует содержимое строк — колонки и ячейки собираются из TableCell; постраничная навигация и панель массовых действий — из Pagination (`.pgn-bulk`, уже существует в `pagination.css`, ранее не документирована ни на одной странице).

## Инварианты
- Корень компонента объявляет парное `[hidden] { display: none }`: браузерное правило имеет специфичность (0,0,0) и приходит из UA-стиля, а `display` компонента — (0,1,0) и перебивает его, из-за чего атрибут `hidden` молча перестаёт работать. Соглашение ДС от 05.09.2026, охраняется правилом B11 линтера.
- Table добавляет только обёртку/Toolbar/липкую шапку с тенью при вертикальном скролле/Loading-Empty — строки и ячейки строит TableCell, панель массовых действий и пагинация — Pagination. Теней-градиентов по левому/правому краю при горизонтальном скролле нет (убраны 27.08.2026).
- Состояния Disabled у таблицы нет — строку/ячейку недоступной не делают, только тонируют/скрывают отдельные действия.
- Тень липкой шапки появляется только когда тело реально проскроллено (`--scrolled`), не постоянно.
- Loading блокирует только тулбар-действия и инструменты шапки (resize/tools), не всю таблицу — строки показывают skeleton через TableCell.
- Тултип на усечённом тексте — общее поведение таблицы, а не разметка экрана: `ds-table.js` сам навешивает его на значения ячеек, подписи шапки и подписи чипов, и показывает только когда текст реально не помещается.
- Сортировка красит шапку из коробки: по клику `ds-table.js` меняет глиф стрелки (через `data-icon`, инлайн-SVG рантайм не пишет), `aria-sort`, `aria-label` кнопки и класс `.th--sorted` на колонке. Экран своего кода на это не пишет и глиф руками не переставляет.
- Стартовое направление сортировки рантайм читает из разметки (`aria-sort` у `.th`), поэтому цикл продолжается с того состояния, которое нарисовано на экране, а не начинается заново с `asc`.
- Шапка определяется структурно — строка, содержащая `.th`. Так её узнаёт рантайм (`ds-table.js`, `ds-table-settings.js`): без этого шапка вела бы себя как строка данных (получала бы `.tbl__row--focus` по клику и попадала бы в «выбрать все»).
- **Внутри `.dtable__body` строка шапки ОБЯЗАНА нести `.tbl__row--head`** — на нём держится липкая шапка (`position: sticky` с 1.013). Раньше класс был необязательным маркером; вне `.dtable__body` он по-прежнему не требуется — там липнуть не от чего.
- Липкая шапка стоит на СТРОКЕ, не на ячейках. `.th` — grid-элемент строки (`.tbl__row { display: grid }`), и блок-контейнер его `position: sticky` — сама строка: по вертикали ячейке ходить негде. По горизонтали то же правило работает именно потому, что строка шире скроллпорта (`min-width: max-content`) — поэтому закрепление колонок не ломалось и дефект вертикали не всплывал (инцидент: портфель ДИД, 05.09.2026).
- Порядок строк рантайм меняет только по опции `data-sort-rows` — это механизм макета (значения берутся из DOM). Реестр с пагинацией сортирует сервер: атрибут не ставится, экран слушает событие `sort` и запрашивает отсортированную страницу.

## Диагностика
- «Тень под шапкой видна без скролла» → нужен класс `.dtable--scrolled`, навешиваемый по факту scrollTop>0
- «Таблица выглядит disabled целиком» → у Table такого состояния нет, приглушать нужно точечно (тулбар/инструменты)
- «Тень/градиент у края таблицы при горизонтальном скролле, едет с колонками» → это остатки удалённого `.dtable__edge`; убрать элемент из разметки, у Table таких теней больше нет
- «Клик по стрелке сортировки ничего не делает» → проверить `data-table` на `.tbl`; если он есть, значит глиф не перерисовывается — внутри `.th__sort` должен лежать слот `<i data-icon="…">`, кнопка с готовым `<svg>` рантайму не по зубам
- «Строки не переставляются, хотя стрелка меняется» → это норма: порядок строк — опция `data-sort-rows` на `.tbl`. Без неё рантайм только шлёт событие `sort`
- «Сортировка перепутала даты/числа» → колонка распозналась как текст; проставить тип явно — `data-sort-type="date|number|text"` на `.th`
- «Стрелка меняется, а строки стоят на месте» → значение ячейки не разбирается как дата/число, ключ выходит `NaN` у всех строк и сравнение вырождается в ноль. Причина обычно в лишнем тексте внутри ячейки (например копия значения в `.tip`); лечится явным `data-sort-value` на `.tc`
- «Клик по пустому месту шапки подсвечивает её как строку» → рантайм старше 1.010: раньше шапка отличалась только по классу `tbl__row--head`, которого разметка не ставила
- «Шапка уезжает вверх при вертикальном скролле тела» → на строке шапки нет `.tbl__row--head`: с 1.013 липкость держит правило `.dtable__body .tbl > .tbl__row--head`, а не `.th` (ячейке некуда двигаться внутри своей строки)

## Ключевые правила (из разделов страницы)
- **Использование** — любой список записей, которому нужен скролл, липкая шапка, счётчик, фильтр или массовые действия. Короткий фиксированный список без прокрутки — Entity/ReadOnlyField, без веса Table. Table — сама себе контейнер (фон/рамка/радиус); внутри Tile — вариант `--headless`, чтобы не дублировать рамку.
- **Анатомия** — Toolbar (опц.) → тело (шапка sticky + строки TableCell) → Footer (опц., Pagination). Вариант «тулбар над таблицей»: зона `.dtable-toolbar` (без подложки) стоит НАД `.dtable`, таблица — без собственного тулбара (headless: сразу шапка).
- **Варианты** — Toolbar включаемый; липкая шапка не отключаема (пока есть вертикальный скролл тела); массовые действия — часть Footer, требуют его включения; горизонтальный скролл + закрепление колонок — свойство TableCell; Table поверх скролла ничего не рисует (теней по краям нет). Изменение ширины колонки доступно всегда и из коробки — ручка `.th__resize` в каждой `.th` (кроме разделителей), скрипт `scripts/tbl-resize.js` входит в `scripts/ds.js`; отключаемой опции нет. Перетаскивание колонок — тоже всегда из коробки: перенос за подпись шапки, скрипт `scripts/tbl-reorder.js` входит в `scripts/ds.js` (исключаются только разделители; закреплённые переносятся — класс pin едет с колонкой, маркер не нужен). Прочая настройка колонок — стандартная модалка **«Настройка таблицы»** (Modal `--w4`): её собирает рантайм `scripts/ds-table-settings.js` (в `ds.js`) по хуку `data-table-settings` на кнопке-шестерёнке, читая колонки из шапки таблицы; поддерживает видимость, порядок (перетаскивание за drag-иконку, линия вставки `--primary`), **мультизакрепление** и отложенное применение («Отменить»/«Применить» справа, снимок колонок на открытие). Такую же структуру открывает кнопка настройки и в демо-странице. Сохранённые фильтры — кнопка «Фильтр» становится Split Button с меню пресетов (см. TableFilter). **Вариант «на всю высоту» (`.dtable--fill`)** — таблица — основной контент экрана и занимает всю свободную высоту (минус крошки/шапка/тулбар), тело скроллится внутри (тулбар/футер закреплены). Требует фиксированной высоты родителя: `.screen--app` на рабочей области (см. Layout). Использование: единственная таблица страницы/реестра; если над/под таблицей есть тайлы — кейс индивидуальный, но по умолчанию таблица всё равно заполняет оставшуюся высоту. **Вариант «тулбар над таблицей» (`.dtable-toolbar`)** — зона фильтра и настроек вынесена из таблицы: контейнер `.dtable-toolbar` БЕЗ подложки стоит над `.dtable`, слева — TableFilter, справа — кнопка настройки колонок; таблица при этом headless (без `.dtable__toolbar`, сразу шапка — ни заголовка, ни счётчика). Вертикальный ритм варианта — 12px: заголовок страницы → зона → таблица (задаёт экран).
- **Размеры** — не применимо: своей шкалы нет, высота строки и паддинги ячеек — TableCell, высота ряда — Pagination. Table фиксирует только паддинги Toolbar (16/20px) и Footer (0/20px по бокам). Высота контейнера по умолчанию — по контенту; вариант `.dtable--fill` растягивает таблицу на свободную высоту родителя (flex-цепочка `flex:1; min-height:0` у контейнера и тела, тело — скролл-контейнер).
- **Размеры · Радиус скругления** — Радиус только у внешней обёртки. обёртка — 12px (--radius-xl) · строка и ячейка — 0.
- **Контент** — заголовок короткий + счётчик без подписи рядом; пустое состояние — иллюстрация `empty-folder` + заголовок 3–5 слов + одно пояснительное предложение + опц. действие, текст различается для «нет данных» и «ничего не найдено»; загрузка — скелетон-строки с тем же числом колонок, что у реальных данных.
- **Поведение · колонка действий** — если у таблицы есть выделенная колонка «Действие», её кнопки (IconButton neutral S) видны всегда, не по hover строки (в отличие от `.tc__hidden` у TableCell — там действия надстройка над контентом, здесь единственное содержимое ячейки). Если есть массовое удаление в `.pgn-bulk`, то же действие обязательно продублировано на уровне отдельной строки в колонке действий.
- **Поведение** — липкая шапка (`.th{position:sticky;top:0}`, тень-разделитель при `scrollTop>0`); горизонтальный скролл тела без теней-градиентов по краям (скрытый контент обозначает скроллбар); переход в режим массового действия по счётчику выбранных строк (`.pgn-bulk` показывается/скрывается, `.pgn-row` не пропадает); Loading/Empty подменяют только тело, Toolbar/Footer остаются; на узких экранах вторичные действия тулбара — в MenuButton.
- **Состояния** — Default / Loading / Empty. Disabled у контейнера нет (как у TableCell).
- **Доступность** — landmark не свой; заголовок — обычный уровень заголовка по контексту страницы, не `h1`; счётчик выбранных строк — `aria-live="polite"`; загрузка — `aria-busy="true"` на контейнере; иллюстрация пустого состояния — `aria-hidden="true"`.
- **Типографика** — заголовок тулбара `--type-h5-strong` (как Tile); счётчик/вспомогательный текст `--type-body-s`; заголовок пустого состояния `--type-body-m-strong`.
- **Цвета** — фон/рамка/радиус контейнера `--bg-tile`/`--border-light`/`--radius-xl`; тень липкой шапки `--border-primary`; строки/шапка — токены TableCell; ряд массового действия — токены Pagination.

Таблица, к которой применяется настройка, находится по контексту (кнопка внутри `.dtable` или в `.dtable-toolbar` перед `.dtable`), либо явно — `data-table-settings="<селектор .tbl>"`. Структура модалки (одинакова во всех таблицах):

```
.modal-scrim (портал) > .modal.modal--w4

  .modal__body   → p.col-desc «Выберите столбцы для отображения»
```

### Поведение · псевдокод (framework-agnostic)
- **Липкая шапка**: тело `overflow:auto`; шапка `position:sticky;top:0`, фон непрозрачный. `scrollTop>0` → тень-разделитель под шапкой (box-shadow, не border).
- **Горизонтальный скролл**: тело просто `overflow-x:auto`, теней-градиентов по краям Table не рисует — скрытые колонки обозначает скроллбар.
- **Массовые действия**: считать выбранные строки; 0→N показывает `.pgn-bulk` над `.pgn-row` (не заменяя её); N→0 скрывает.
- **Loading/Empty**: подменяют только тело; Toolbar/Footer остаются доступны.
- **Ширина колонки**: ручка `.th__resize` в каждой `.th`; drag/клавиши ← → пересчитывают трек `grid-template-columns` всех строк, минимум 96px. Логика — общий `scripts/tbl-resize.js` (в составе `ds.js`), делегирование на document, инициализации на экране не требует.
- **Сортировка**: клик по `[data-sort]` крутит `none → asc → desc → none`. Рантайм красит шапку сам — глиф (`arrow-up-down` / `arrow-narrow-up` / `arrow-narrow-down` через `data-icon`), `aria-sort`, `aria-label` и `.th--sorted`; активна максимум одна колонка, остальные сбрасываются в `none`. Стартовое направление читается из `aria-sort` в разметке. Наружу уходит событие `sort` на `.tbl` с `{ column, dir }`, где `column` — значение `data-sort` (ключ поля данных). Императивно — `DSTable.wire(tbl).sort(column, dir)`.
- **API `wire()`**: возвращает `{ el, selected(), sort(column, dir), refresh(), rowsChanged() }`. `refresh()` — чекбокс шапки + тултипы усечения, состав строк не менялся. `rowsChanged()` — то же плюс переустановка `__dsRowOrder`: звать после того, как потребитель добавил/удалил `.tbl__row` мимо рантайма (реестр дописал новую строку) — без этого `data-sort-rows` не увидит добавленную строку при следующей сортировке, потому что порядок для сортировки зафиксирован один раз при `wire()`.
- **Порядок строк**: опция `data-sort-rows` на `.tbl` — рантайм переставляет строки сам. Значение берётся из ячейки по индексу колонки: сначала `data-sort-value` на `.tc` (явное машиночитаемое значение — им же удобно отдавать ISO-дату или число, когда показывается форматированный текст), иначе `.tc__text` и подписи чипов, иначе текст ячейки без узлов `[role="tooltip"]`. Голый `textContent` ячейки не годится: `ds-tooltip.js` кладёт рядом со значением копию текста, и оно удваивается. Тип — `data-sort-type` на `.th` (`date` — `дд.мм.гггг` · `number` — с пробелами/NBSP и запятой · `text` — `localeCompare` по русской раскладке), иначе определяется по первому непустому значению. Пустое (`—`, пусто) и нераспознанное всегда внизу независимо от направления. Дерево: сортируются корни, поддерево едет следом за своим корнем. `dir = none` возвращает исходный порядок разметки. **Это механизм макета** — данные читаются из DOM, поэтому с пагинацией сортировалась бы только видимая страница; реестр на бэкенде атрибут не ставит, а слушает `sort` и запрашивает отсортированную страницу.
- **Порядок колонок**: drag за подпись шапки (порог 4px) переставляет колонку к ближайшей границе между центрами; исключены только разделители (закреплённые переносятся — класс pin едет с колонкой, `tbl-pin.js` пересчитывает удержание). Логика — общий `scripts/tbl-reorder.js` (в составе `ds.js`), делегирование на document, инициализации на экране не требует; событие `columnreorder` на `.tbl` с `{from, to}`.
- **Настройка таблицы (модалка)**: хук `data-table-settings` на кнопке-шестерёнке. При открытии рантайм делает снимок колонок (читает из шапки), строит модалку `--w4` и работает с копией: родительский чекбокс → видимость всех (indeterminate при частичном), `data-visible` → видимость одной, `data-pin` → мультизакрепление, drag за `col-item__drag` → порядок (линия `--primary`). Таблица не меняется до «Применить»; «Применить» применяет снимок-копию (перестановка/скрытие-показ/закрепление реальных колонок, синхронизация `.th__pin` в шапке, событие `columnsettings`), «Отменить»/Escape/клик по скриму — закрытие без применения. Повторная работа с таблицей заменяет inline-SVG не пишет (правило «не инлайнить SVG»), глифы `pin`/`pin-filled`/`drag-dots` — через `data-icon`.
