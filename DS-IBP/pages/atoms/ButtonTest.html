Button Test

Кнопка инициирует действие. Три типа, три размера, состояния Default / Hover / Active / Disabled, лоадер и режим Fullwidth. Модификатор Тон (--error / --warning / --success / --info) комбинируется с любым типом — Error для деструктивных действий (диалог подтверждения удаления), остальные тоны переиспользуются в Alert и SnackBar. Текст кнопок набран токенами Button M / S / XS (SB Sans Screen).

Использование

Тип кнопки отражает вес действия. На одной области экрана — только один Accent; рядом с ним второстепенные действия — Outline, третичные — Transparent. Справа от текста может быть либо шеврон (кнопка-меню), либо иконка — но не одновременно.

Анатомия

Кнопка может содержать иконку слева и/или справа от текста, и/или сам текст. Иконки допускаются с обеих сторон одновременно.

Варианты

Оси конфигурации компонента — каждая описана отдельным подразделом.

Type

Свойство Type определяет общий вид кнопки: Accent, Outline, Transparent.

Тон

Модификатор, а не отдельный тип — комбинируется с Accent / Outline / Transparent и меняет цвет на токены одного из четырёх тонов палитры Situative: Error, Warning, Success, Info. Те же самые кнопки переиспользуются в Alert и SnackBar — тон кнопки совпадает с тоном компонента. Error — тон для деструктивного действия в диалоге подтверждения (например «Удалить» в confirm-модалке, см. Modal); класс .btn--danger сохранён как алиас .btn--error для обратной совместимости. Не применяйте тон к обычному «Удалить» в подвале формы — там кнопка остаётся Transparent, деструктивность подтверждает отдельный диалог, а не цвет.

Кнопка с меню (chevron)

Если кнопка содержит шеврон — она открывает контекстное меню. Клик по самой кнопке только показывает меню; действия выполняются исключительно по пунктам меню. Справа может быть либо шеврон, либо иконка — но не одновременно. Нажмите, чтобы открыть.

Fullwidth

Кнопки со свойством Fullwidth заполняют весь контейнер: боковые паддинги убираются, контент центрируется. Кнопки, содержащие только иконку, не растягиваются.

Размеры

Три размера. Ширина зависит от контента, высота фиксирована.
M — 40 · кнопки в модальных окнах  ·  S — 32 · в таблицах, на тайлах  ·  XS — 24 · фильтры и экшены на одном уровне с фильтром.

Контент

Текст кнопки — короткая глагольная формулировка действия. Ширина кнопки следует за текстом, поэтому правило одно: короче текст — лучше.

  • Глагол действия: «Применить», «Скачать PDF», «Создать копию» — 1–3 слова, без точки в конце.
  • Без переноса и обрезки: текст набирается в одну строку (white-space: nowrap). Если не помещается — сокращайте формулировку, а не кнопку.
  • Sentence case: заглавная — только первая буква и имена собственные.
  • Текст стабилен: при переходе в Loader формулировка не меняется.
  • Icon-only: кнопке без текста обязателен aria-label с названием действия.

Поведение

Правила поведения: позиционирование, переполнение, анимация, адаптивность.

Loader

Сообщает, что идёт процесс, вызванный кликом. На время процесса кнопка переходит в Disabled. Если в кнопке есть иконка — лоадер заменяет её (при иконках с обеих сторон заменяется левая). Если иконок нет — лоадер появляется слева от текста и увеличивает ширину. В IconOnly иконка заменяется лоадером. Нажмите на любую кнопку, чтобы увидеть.

С иконкой
Только текст
Иконки с двух сторон
IconOnly

hasLoader=Yes удерживает кнопку в Disabled, пока процесс не завершится.

Состояния

Default, Hover, Active, Disabled — для каждого типа.

Доступность

Кнопка — нативный <button type="button">: Enter и Space работают из коробки. Фокус — outline: 2px var(--primary) с отступом 2px, только по :focus-visible. Disabled задаётся атрибутом disabled. В состоянии Loader кнопка не интерактивна (pointer-events: none) — дополнительно ставьте aria-busy="true" и держите её disabled до конца процесса. Icon-only обязана иметь aria-label. Кнопка с шевроном получает aria-haspopup="menu" и aria-expanded; меню — role="menu" с пунктами role="menuitem", Esc закрывает меню и возвращает фокус на кнопку. Спиннер замедляется при prefers-reduced-motion.

Поведение · псевдокод (framework-agnostic) 
// 1. Loader — спиннер занимает место ЛЕВОЙ иконки:
//    есть левая иконка → заменить её на .spin (правая иконка/шеврон остаются)
//    нет левой иконки → вставить спиннер перед .btn__label (ширина кнопки растёт)
//    icon-only → заменить иконку на спиннер
// На время загрузки: .btn--loading + disabled + aria-busy="true";
// текст кнопки не меняется, по завершении вернуть исходный состав.

// React: loading — просто пропс, состав рендерится декларативно:
leftSlot = loading ? Spinner : iconLeft

// 2. Кнопка-меню (шеврон):
//    клик по кнопке ТОЛЬКО открывает/закрывает меню — действие не выполняет
//    действия выполняются исключительно по пунктам меню
//    клик вне меню и Esc — закрывают; aria-expanded синхронизируется
//    при открытом меню шеврон поворачивается на 180° (transform .15s ease)
//    справа либо шеврон, либо иконка — никогда оба (шеврон имеет приоритет)

// 3. Состояния hover/active — чистый CSS (:hover/:active);
//    классы .is-hover/.is-active существуют только для спецификаций в документации.

Это не готовый сниппет для вставки — алгоритм, который нужно реализовать поверх вашего стека (рабочий референс на vanilla JS — функции makeBtn, attachLoader и makeDropdown в коде этой страницы).

Сводка расхождений

Итог сравнения ДС IBP ↔ сторибук ibp-ui-kit по кнопке и всей палитре, и план перехода на их семантику.

Где сходимся

  • Базовые цвета — primary, text-on-dark, text-inactive, disabled, tertiary, border: семантика и значения совпадают 1:1.
  • Тон Error — все 6 токенов совпадают; Success — все 4; базовый тон Warning совпадает, базовый тон Info расходится (см. §2), подложки Warning/Info совпадают.
  • Статус-палитра — 40 из 45 (всё, кроме StPrimary). Rate — 8 из 8.
  • Типографика кнопки — ButtonM / ButtonS / ButtonXS = наш M / S / XS (16/24 · 14/20 · 12/16).
  • Высоты и паддинги — 40/32/24 px и горизонтальные паддинги 16/12/8 (md/sm/xs) совпадают.
  • Радиус 8 px (наш M/S = их md) и 6 px (наш XS = их sm по значению).
  • Прозрачности — alpha-токены (6% / 3% / 50% / St-миды) совпадают по значению.

Где расходимся

1. Схема имён

  • У нас — CSS-переменные kebab-case (--primary-dark), у них — объектная нотация theme.palette.Primary.PrimaryDark. Семантика в основном та же, читается по-разному.

2. Реальные расхождения значений (8)

  • --primary-dark — наш #007A6D ↔ их emerald[700] #0A7D6D.
  • --primary-light — наш #58DCCC ↔ их emerald[300] #82CDC6.
  • --warning-dark — наш #C68400 ↔ их amber[800] #FF8F00.
  • --warning-light — наш #FFE54C ↔ их amber[400] #FFCA28.
  • --info — наш #1E88E5 ↔ их lightBlue[600] #039BE5 (наш hex совпадает с их InfoBlue, blue[600]).
  • --info-dark — наш #01579B ↔ их lightBlue[800] #0277BD.
  • --link-dark — наш #007A6D ↔ их emerald[700] #0A7D6D.
  • --link-light — наш #B8D6D3 (emerald[200]) ↔ их emerald[300] #82CDC6.

3. Структурные расхождения

  • Размеры: у нас 3 (M/S/XS), у них 4 — есть ещё lg (48 px) и радиус xs 4 px. Наш S (32 px) — радиус 8 px, у их sm (32 px) — 6 px.

    Наша кнопка · 3 размера

    Высота 40/32/24 · радиус M/S — 8px, XS — 6px

    Их кнопка · 4 размера

  • Производные --btn-*: у нас color-mix (10% / 18% / 45%), у них нет — hover = PrimaryBG (alpha 6%), active (Accent) = PrimaryLight сплошным, active (Outline/Transparent) — без заливки.
  • Secondary bg — инверсия имён: наш --secondary-bg (30%) = их SecondaryBGDark, наш --secondary-bg-light (15%) = их SecondaryBG.
  • Иконки: размер S 18 ↔ 16 px; зазор 8/6/4 ↔ 6/4/4; icon-only паддинг 8/6/4 ↔ 10/8/4.

  • Типографика XS: их xs-кнопка рендерит ButtonS (14/20); ButtonXS (12/16) существует, но кнопкой не используется.
  • Disabled (Outline/Transparent): наш текст — --text-inactive , у них — Disabled.Disabled .
  • Chart: наши 12 --chart-* (произвольные hex) ↔ их 9 Chart-токенов (CGreen…CBlue) — полный рассинхрон.
  • Наш lightBlue[800] = [900] = #01579B (дубль), у них 800 = #0277BD, 900 = #01579B.

4. Только у нас (нет в сторибуке)

  • --btn-hover-bg / --btn-active-bg / --btn-pale (производные color-mix).
  • --st-primary-* (5), --bgtable-pinned-* (3), --bgtable-row-focus-hover.
  • --chart-* (12) — вся наша Chart-палитра.

5. Только у них (нет у нас)

  • Размер lg (48 px), типографика ButtonL (24/32) и ButtonXS как отдельный стиль, радиус xs 4 px.
  • Палитра Product (7 токенов: PGreen…PGreyLight), InfoBlue, TextBlack, TextOnTertiary, BGPageLinearEnd, BGSecondaryLight.
  • Deprecated-статусы S* (6: SGrey, SGreyLight, SRed, SRedLight, SEmerald, SEmeraldLight) — отмечены у них как удаляемые.
  • Chart-палитра (9 токенов).

Как перейти на семантику сторибука

  • 1. Принять их схему имён за канон. Завести слой-алиасов в нашем CSS (алиас --sb-primary-dark = наш --primary-dark) или переименовать токены в их нотацию — чтобы имена в макетах и в коде совпадали дословно.
  • 2. Синхронизировать 8 расходящихся значений и починить дубль lightBlue 800/900 (наш 800 → #0277BD).
  • 3. Докомпоновать недостающее: размер lg (48 px), ButtonL, ButtonXS как отдельный стиль, радиус xs 4 px, палитру Product.
  • 4. Решить судьбу «только у нас»: --btn-* — заменить на их PrimaryBG / PrimaryLight; --chart-* — перейти на их 9 Chart-токенов; --st-primary-* — убрать или согласовать; --bgtable-pinned-* — добавить к ним.
  • 5. Маппинг-таблицу (эта страница) держать источником истины и пополнять при добавлении токенов; после синхронизации перенести её в раздел Colors.
