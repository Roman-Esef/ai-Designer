Spinner

Круговой индикатор загрузки неопределённой длительности: стоит там, где нужен компактный самодостаточный признак «идёт процесс» — рядом с текстом, вместо контента области или поверх неё. Семь тонов, четыре размера, опциональная подпись и блокирующий оверлей.

Использование

Используйте Spinner, когда:

  • длительность процесса заранее неизвестна, а сам процесс — секунды, не минуты (сохранение формы, ожидание ответа сервера, обновление списка);
  • нужен компактный самодостаточный индикатор рядом с текстом или вместо иконки — без бара, под который пришлось бы выделять отдельную полосу в разметке;
  • нужно заблокировать конкретную область экрана на время обновления, не трогая остальной интерфейс — режим Оверлей.

Не используйте Spinner, если доля выполнения известна — линейный индикатор с реальным значением (value) даёт пользователю больше информации, чем «просто крутится»; см. ProgressBar. Круговой индикатор с процентом внутри (например, для аватара или миниатюры файла) — отдельная задача, она в бэклоге ProgressBar, а не форма этого компонента: Spinner всегда неопределённый и не несёт числового значения. Для загрузки внутри кнопки не собирайте Spinner отдельно — состояние .btn--loading уже включает свой спиннер, см. Buttons. Если под загрузкой уже известна структура будущего контента (карточка, строка таблицы), предпочтительнее сохраняющий разметку скелетон-паттерн — самостоятельного компонента Skeleton в ДС пока нет (см. «Бэклог»).

Анатомия

Один элемент с двухцветной обводкой: неподвижный трек и вращающийся сегмент-индикатор. Подпись — опциональный слот рядом или под кольцом, не часть самого кольца.

  • Трек — неподвижное кольцо на всю окружность, нейтральный --border-light независимо от тона
  • Индикатор — вращающийся сегмент кольца (обрыв обводки сверху), цвет = тон
  • Подпись — опционально, рядом или под кольцом; общий текстовый слот, не завязан на LabelHelper

Варианты

Оси конфигурации компонента — каждая описана отдельным подразделом.

Тон

Шесть тонов на локальных статусных токенах — тот же набор, что у ProgressBar, плюс Inverse для использования на тёмных и цветных заливках, где нейтральный трек на --border-light потерялся бы.

Состав

Голое кольцо, кольцо с подписью (в строку или столбиком) и блокирующий оверлей поверх контента области.

Размеры

Четыре размера — от инлайн-использования рядом с мелким текстом до акцентного индикатора в оверлее. Толщина кольца растёт вместе с диаметром, чтобы пропорция не «истончалась» на крупных размерах. Значения ниже измерены на живом экземпляре.

Контент

  • Подпись — короткая фраза о процессе в процессе, а не статичный ярлык: «Сохранение…», «Загрузка данных…», «Обновление списка…»; глагол в форме процесса (на «-ние»/«-ка»), не инфинитив и не результат.
  • Не указывайте в подписи процент или счётчик — Spinner неопределённый по смыслу; если он появился, значит нужен ProgressBar, а не Spinner с текстом-заглушкой.
  • Подпись оверлея — так же кратка, но может уточнять область: «Обновление таблицы…», «Применение фильтра…» — пользователь должен понимать, что именно блокировано, а не весь экран.
  • Без подписи — aria-label обязателен на самом кольце (см. «Доступность»), даже когда текстового слота нет визуально.

Поведение

Правила анимации, позиционирования оверлея и адаптивности под системные настройки.

Вращение

  • Постоянное вращение на transform: rotate(), не через пошаговое изменение угла из JS — анимация не должна зависеть от кадров основного потока.
  • Компонент не имеет состояния «остановлено» и не принимает значение — он либо показан (идёт процесс), либо убран из DOM/скрыт, когда процесс завершился.
  • prefers-reduced-motion: длительность цикла увеличивается вдвое (0.8с → 1.6с), а не отключается — полное исчезновение вращения убрало бы единственный сигнал «идёт процесс».

Оверлей — блокирующий режим

  • .spin-overlay позиционируется position:absolute; inset:0 — родительский контейнер обязан иметь position:relative (или иной контекст позиционирования), иначе оверлей растянется на ближайшего позиционированного предка, а не на нужную область.
  • Фон оверлея — лёгкая вуаль поверх --bg-page (82% непрозрачности): контент под ней остаётся угадываемым, в отличие от тёмного --modal-scrim у Modal, который блокирует весь экран визуально и по смыслу.
  • Оверлей не является модальным диалогом: фокус не перехватывается, Esc не закрывает — под ним нет действия пользователя, только ожидание.
  • z-index оверлея локальный (относительно родителя), не часть общей шкалы модалок/тостов/меню ДС — он не должен и не может перекрыть их.

Состояния

У самого индикатора одно состояние — он либо показан и вращается, либо не показан. Ниже — типовые контексты применения, а не состояния в смысле Hover/Active.

Доступность

  • Корневой элемент несёт role="status", не role="progressbar" — у Spinner нет числового значения, которое требовали бы aria-valuenow/min/max.
  • Если рядом нет видимой подписи — обязателен aria-label на кольце («Загрузка», «Сохранение…»); с подписью кольцо получает aria-hidden="true", а роль и подпись несёт обёртка .spin-group.
  • Оверлей — role="status" + aria-live="polite" на обёртке, чтобы скринридер объявил и начало, и конец блокировки области (после её удаления из DOM).
  • Тон не несёт самостоятельного смысла статуса (в отличие от ProgressBar) — Spinner всегда означает «идёт процесс», выбор тона — это только адаптация под фон, а не сигнал успеха/ошибки.
  • Анимация уважает prefers-reduced-motion (см. «Поведение»); компонент не интерактивен и не входит в таб-порядок.

Типографика

Само кольцо не содержит текста. Подпись рядом с кольцом и подпись оверлея набираются гарнитурой SB Sans Text на разных начертаниях.

Цвета

Трек — всегда нейтральный --border-light, кроме тона Inverse, где он строится полупрозрачным поверх --text-on-dark. Индикатор — базовый цвет локальной статусной рампы, тот же набор токенов, что у тонов ProgressBar.

//    Если появилось известное значение, это ProgressBar, не Spinner.

// 2. Вращение — только transform: rotate(360deg) в CSS-анимации, не через
//    покадровое обновление угла из JS: анимация не должна зависеть от того,
//    свободен ли основной поток в момент кадра.

// 3. Показ/скрытие: компонент монтируется на время процесса и размонтируется
//    (или скрывается) по его завершении — у него нет самостоятельного состояния
//    "остановлено", в отличие от ProgressBar, где Complete/Empty — валидные состояния.

// 4. Оверлей: перед монтированием .spin-overlay убедиться, что ближайший

//    родитель выше по дереву (иначе оверлей растянется не туда).
//    aria-live="polite" на оверлее объявляет и начало, и конец блокировки —
//    второе объявление сработает, только когда оверлей реально удалён из DOM,
//    а не просто скрыт через visibility/opacity.

// 5. prefers-reduced-motion: animation-duration ×2, не отключение анимации.

БэклогПредложение

Компонент закрывает индикатор неопределённой длительности. Смежные задачи, которые сознательно не входят в эту версию:

  • Skeleton — самостоятельный переиспользуемый примитив (строки/блоки + шиммер), который сохраняет разметку будущего контента вместо Spinner/оверлея. Сейчас шиммер существует только как локальный .modal__skeleton внутри Modal — не переиспользуемый компонент. См. общий бэклог ДС (раздел «Недостающие компоненты», P2).
  • Круговой ProgressBar с известным значением — кольцо с процентом внутри (аватары, миниатюры файлов, виджеты дашборда). Другая задача и другая разметка: у Spinner нет значения по определению. Уже описано в бэклоге ProgressBar.
  • Составной Upload-индикатор с отменой/повтором — carточка загрузки файла с действиями. Требует состояний ошибки — отдельный организм поверх Spinner/ProgressBar, не расширение этого компонента.
