Задача: сделать несколько концептов интерфейса под одну задачу и дать их
сравнить. Текстовые спеки, не HTML.

Источник ТЗ: $ARGUMENTS

Если аргумент — путь к файлу, прочитай его. Если это описание словами — работай
по нему. Если аргумент пустой — спроси, где взять ТЗ, и остановись.

Запусти маршрут «Спроектируй концепты»:

1. Разбери ТЗ сам; при необходимости запусти `ux-researcher` (если задача
   касается целей и сценариев пользователей).
2. Загрузи скиллы `concept-design`, `ds-lookup` и `layout-composition`; выпиши,
   что из ДС уже покрывает задачу.
3. Уточни у пользователя (если не задано): какие уровни спектра и сколько
   концептов. По умолчанию — три: A + B + C.
4. Для каждого уровня — спека `Projects/test/<Имя>.concept-<A|B|C>.md` по
   шаблону из `concept-design`. Каждый выход за ДС помечен `[ПРЕДЛОЖЕНИЕ]` и
   собран в секции «Предложения к расширению ДС».
5. Покажи пользователю сводку: чем концепты различаются, какие предложения
   вынесены, какие доменные пробелы требуют вопроса.
6. Дождись выбора концепта и решений по предложениям (утвердить / отклонить /
   уточнить). Дальше — маршрут «Собери экран», передав `screen-builder`
   дословно путь к ТЗ, путь к выбранному концепту, список утверждённых и
   отклонённых предложений.

Файлы ДС (`DS-IBP/`) не трогать. Концепты — только текстовые спеки, HTML на этой
фазе не собирается.
