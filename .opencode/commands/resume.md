Задача: продолжить работу, начатую в прошлой сессии.

Имя задачи: $ARGUMENTS

1. Прочитай `Projects/test/<Задача>.handoff.md`. Имя не задано или файла
   нет — перечисли `Projects/test/*.handoff.md` (только имена и строку
   «Статус») и спроси, какую задачу продолжить. Остановись.
2. Прочитай **только** файлы из раздела «Читать первыми». Остальное — по мере
   надобности, точечно (ds-rules §3, §13).
3. Возьми из раздела «Этапы» текущий этап (`→`). Загрузи инструктаж **только
   этого этапа** — состав печатает
   `node .opencode/skills/session-plan/tooling/ctx-budget.mjs --stages`.
   Скиллы соседних этапов не грузи: этап платит только за своё.
4. Пересчитай смету этапа теми же аргументами, что записаны в разделе «Смета».
   `ВЕРДИКТ: РАЗБИТЬ` — не начинай этап, сначала предложи пользователю разбить
   его дальше.
5. Если с даты handoff файлы задачи могли меняться — прогони
   `lessons-cli gate --dry`: он покажет, что изменилось со снимка.
6. Ответь пользователю коротко:
   - **Где остановились** — текущий этап, статус и последний вердикт проверок;
   - **Смета этапа** — строка `ВЕРДИКТ:` из пункта 4;
   - **Открытые вопросы** — из handoff, списком;
   - **Предлагаю начать с** — следующий шаг из handoff.
7. Жди подтверждения. Решения из handoff не пересматривай без просьбы
   пользователя — они уже приняты.
8. Этап закончен — `/handoff` (статус этапа `→` переезжает на следующий) и
   сессия закрывается. Следующий этап — новая сессия.
