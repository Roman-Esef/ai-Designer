# Поиск по дизайн-системе IBP

## Правило экономии

Экономия контекста — **средство, а не цель**. Цель — корректный экран с первого
раза. Ошибка, найденная на приёмке или человеком, стоит дороже, чем спека,
прочитанная вовремя: её приходится диагностировать, объяснять, править и
перепроверять — это в разы больше токенов, чем сэкономлено. Поэтому:

> **Сэкономил токены и ошибся — задача экономии НЕ выполнена.**
> Сомневаешься в размере, варианте или составе — читай спеку. Это дешевле.

В репозитории есть файлы, которые нельзя читать целиком:

| Файл | Размер | Что делать вместо |
|---|---|---|
| `DS-IBP/scripts/icons-data.js` | 671 KB, одна строка | никогда не открывать; имена глифов — `DS-IBP/specs/Icons.md` |
| `DS-IBP/specs/_cheatsheet.md` | ~170 KB | читать по одному блоку компонента |
| `DS-IBP/pages/**/*.html` | 40–70 KB каждая | не читать; всё нужное есть в спеке |
| `DS-IBP/styles/*.css` | — | целиком не читать; **точечный `grep` по классу — можно и нужно**, когда чит-шит и спека расходятся или когда значение подозрительное |

## Чит-шит — не истина в последней инстанции

Чит-шит собирается руками и **может расходиться со спекой и с CSS**. Такое
уже случалось: в блоке NavPanel бургер был `ibtn--s`, а спека и расчёт оси в
`DS-IBP/styles/nav-panel.css` требуют `ibtn--m`; в блоке DatePicker сниппет давал
`btn--s` при том, что проза того же блока строкой выше говорила XS
(оба исправлены 26.08.2026 — но гарантии, что расхождений не осталось, нет).

Порядок старшинства при конфликте: **CSS компонента → полная спека → чит-шит**.
Заметил расхождение — не выбирай молча «что покрасивее»: возьми старший
источник и **сообщи о расхождении в отчёте**, чтобы чит-шит починили.

## Три команды

### 1. Какие вообще есть компоненты

```bash
grep -n "^## " DS-IBP/specs/_cheatsheet.md
```

Отдаёт список всех компонентов с номерами строк. ~50 строк, дёшево.

Альтернатива с версиями и зависимостями — `cat DS-IBP/specs/_index.md`.

### 2. Разметка и классы одного компонента

```bash
sed -n '/^## Tile$/,/^## /p' DS-IBP/specs/_cheatsheet.md
```

Подставь нужное имя вместо `Tile`. Отдаёт 20–40 строк: CSS-файл, зависимости,
оси конфигурации, инварианты, полный список классов, готовый DOM-сниппет,
типовые ошибки.

Разметку из сниппета копируй **дословно** — включая размерные модификаторы
(`--m`, `--xs`), теги слотов и порядок элементов. Менять в ней можно только
тексты и модификаторы, перечисленные в блоке «Оси».

Если `sed` в среде нет: возьми номер строки из команды 1 и прочитай файл
инструментом `read` с `offset` = этот номер и `limit` = 45.

### 3. Полная спека — обязательные триггеры

```bash
cat DS-IBP/specs/Tile.md
```

6–12 KB. **Жёсткого лимита на число прочитанных спек нет** — читай столько,
сколько нужно, чтобы не гадать. Но есть список случаев, когда чит-шита
заведомо НЕ достаточно и спека обязательна:

| Триггер | Почему чит-шита мало |
|---|---|
| У компонента **два и более варианта под разные смыслы** (ProgressBar обычный vs `--floating`, Chip fill vs outline, Tile обычный vs accordion) | В чит-шите они лежат рядом как примеры; правило выбора — в спеке, раздел «Использование» |
| Компонент — часть **каркаса экрана** (NavPanel, Layout, Breadcrumbs, PageHeader) | Их размеры завязаны на расчёты в CSS (оси, сетки); ошибка в модификаторе ломает выравнивание всего экрана |
| Нужно **сложное поведение**: позиционирование, переполнение, клавнавигация, точные размеры (redline) | Чит-шит даёт разметку, не поведение |
| Собираешь **композицию** (RiskMetric = Chip+Popover, Split-кнопка, Select) | Половина композиции выглядит нормально и не работает |
| Сниппет чит-шита **противоречит прозе того же блока** или твоим ожиданиям | Это признак расхождения — см. раздел выше |

### 4. Развилка «какой вариант взять» — не решается на глаз

Если у компонента несколько вариантов и ты не нашёл явного правила выбора:

1. Открой полную спеку, раздел **«Использование»** — правило почти всегда там.
2. Нет и там — **это пробел ДС**. Выбери вариант, который буквально подписан
   под твой случай (`aria-label`, подпись в примере, название поля в сниппете),
   и **пометь выбор как допущение в отчёте**.
3. Никогда не выбирай вариант по признаку «выглядит интереснее». Варианты в
   этой ДС различаются смыслом, а не нарядностью.

**Пример ошибки (реальный, 26.08.2026):** в чит-шите ProgressBar два примера —
обычный и `--floating` с `aria-label="Вероятность сделки"`. Сборщик поставил
`--floating` на поле «Прогресс», а «Вероятность сделки» отрисовал голым
текстом. Подпись в примере прямо называла назначение варианта — её не прочли.

## Иконки

Все 247 имён глифов — одной строкой в `DS-IBP/specs/Icons.md`:

```bash
grep -o "^[^#].*" DS-IBP/specs/Icons.md | tail -1 | tr '·' '\n' | grep -i "arrow"
```

или просто `cat DS-IBP/specs/Icons.md` (файл 16 строк).

Правила:

- на экране иконка ставится только как `<i data-icon="имя"></i>`;
- имени нет в списке — иконки в ДС нет, спроси, не подставляй похожую;
- глиф не видно по имени: если сомневаешься, что именно нарисовано, — спроси
  или выбери очевидное (`edit`, `trash`, `filter`, `search`, `close`,
  `chevron-down`, `more-dots`, `download`, `star`, `plus` → `add`).

## Токены

| Что нужно | Где смотреть |
|---|---|
| Цвета | `grep -n "^  --" DS-IBP/styles/colors.css` |
| Типографика (`--type-*`, классы `.ds-*`) | `sed -n '/^## Ключевые/,/^## /p' DS-IBP/specs/Typography.md` |
| Отступы, шкала `--space-*`, сетка `.grid12`/`.col-N` | `sed -n '/^## Spacing/,/^## /p' DS-IBP/specs/_cheatsheet.md` |
| Радиусы | `grep -n "radius" DS-IBP/styles/radius.css` |
| Тени | `grep -n "shadow" DS-IBP/styles/elevation.css` |

Ищешь конкретный токен по имени — `grep -rn "имя-токена" DS-IBP/styles/`.

Токена нет — **спроси**. Не подставляй `#hex`, не считай «примерно как рядом».

## Проверка «есть ли такой компонент»

```bash
grep -in "имя" DS-IBP/specs/_index.md
```

Нет в `_index.md` — компонента в ДС нет. Это стоп-сигнал: сообщи человеку,
что не хватает, и предложи, из чего это можно было бы собрать. Не собирай
подмену из `div` с ручными стилями.

## Частая путаница в именах

| Ищешь | На самом деле называется |
|---|---|
| Карточка, панель, блок | **Tile** |
| Шапка страницы, титул | **PageHeader** |
| Хлебные крошки | **Breadcrumbs** |
| Таблица (обёртка, тулбар, футер) | **Table** |
| Строка и ячейка таблицы, шапка колонки | **TableCell** |
| Фильтр над таблицей | **TableFilter** |
| Модальное окно, диалог | **Modal** |
| Боковое меню | **NavPanel** |
| Поле только для чтения | **ReadOnlyField** |
| Статус, тег, метка | **Chip** (счётчик — **Badge**) |
| Пустое состояние | **EmptyState** |
| Уведомление в углу | **Toast** / **SnackBar** |
| Плашка на странице | **Alert** |
