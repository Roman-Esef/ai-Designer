# Приёмка экрана

Проверка идёт по файлу `Projects/test/<Имя>.html` и по
`<Имя>.screen.md`. Вердикт один: **PASS** или **NEEDS-WORK**. Любой невыполненный
пункт группы «Блокеры» даёт NEEDS-WORK.

## Быстрая механическая проверка

**Сначала прогони статический сенсор** (без браузера, заменяет скриншотную
проверку — см. ds-rules.md §9):

```bash
node .opencode/skills/screen-review/tooling/layout-check.mjs <путь к <Имя>.html> [--width 1920]
```

Он кодирует часть блокеров этого чек-листа и геометрию composition-review
(токены из `DS-IBP/styles/*.css`, эвристика ширины символа). **Какие именно
проверки реализованы — спроси сам сенсор:**

```bash
node .opencode/skills/screen-review/tooling/layout-check.mjs --rules
```

Перечислять состав здесь прозой нельзя: копия разъезжается с кодом (урок Л43).
Всё, чего в выводе `--rules` нет, проверяется по таблицам ниже вручную.

Вердикт FAIL — дефекты уже
сформулированы с номерами строк; переноси их в отчёт. Замечания (WARN) и
оценки («проверить вручную») — проверь глазами по исходнику.

Grep-команды ниже — для точечной проверки того, что сенсор не покрыл
(семантика: выбор иконки по смыслу, порядок скриптов, живость компонентов).

Эти команды находят большую часть дефектов за один проход:

```bash
F=Projects/test/ИмяЭкрана.html

grep -n "<svg"            $F   # должно быть пусто — иконки только <i data-icon>
grep -n "#[0-9a-fA-F]\{3,6\}" $F   # должно быть пусто — цвета только токенами
grep -n "rgb(\|rgba("     $F   # должно быть пусто
grep -n "DS-IBP/styles/"         $F   # должно быть пусто — подключается только DS-IBP/ds.css
grep -n "DS-IBP/scripts/ds-"     $F   # должно быть пусто — подключается только ds.js
grep -c "DS-IBP/ds.css"          $F   # ровно 1
grep -c "DS-IBP/scripts/ds.js"   $F   # ровно 1
grep -n "\.\./\.\./[^D]"  $F   # пути только ../../DS-IBP/ (два уровня + DS-IBP)
grep -n "Lorem\|TODO\|XXX\|здесь будет\|заглушк" $F   # должно быть пусто
grep -n "₽\|[$]\|€\|¥\|руб\." $F   # должно быть пусто — валюта только 3-буквенным кодом ISO 4217 (RUB/USD/EUR/JPY), редполитика

# --- изобретённое вместо готового (Б14, Б16) ---
grep -n "grid-column: *span" $F      # так и должна задаваться ширина тайла
grep -n "\.[a-z-]*\(half\|full\|col[0-9]\) *{" $F   # свои классы ширины — блокер
grep -n "\.tile-row *{\|\.tile-row[^+]*margin" $F   # свой зазор между рядами — блокер

# --- вариант компонента под смысл поля (Б17) ---
grep -n "pbar--floating" $F          # рядом должно стоять «вероятность»/«скор», не «прогресс»

# --- собственный CSS не переопределяет состояния компонента (Б21) ---
grep -nE "(button|a|input)\.[a-z_-]+ *\{" $F   # тег+класс компонента — проверь, что не перебивает --selected/--disabled/:hover

# --- сброс body и док-классы (Б22, Б23) ---
grep -n "body\s*{" $F                         # должен быть body { margin: 0 } — иначе UA-дефолт 8px (рамка+скролл)
grep -nE "class=\"[^\"]*\b(desc|tight|panel|masthead|lead|eyebrow|claim|note|bullets|rules|guide|subhead)\b" $F   # док-классы на экране — мертвы (нет в ds.css)
```

Проверка имён иконок: выпиши все `data-icon="…"` и сверь со списком в
`DS-IBP/specs/Icons.md`.

```bash
grep -o 'data-icon="[^"]*"' $F | sort -u
```

Каждое имя обязано встречаться в `DS-IBP/specs/Icons.md`. Не встречается — блокер.

## Проверка живости: работает ли макет

Экран не бумажный — штатное поведение компонентов ДС должно работать. Смотри,
какие компоненты есть в разметке, и требуй их хуки:

```bash
grep -c "class=\"tbl\""        $F   # есть таблица?
grep -c "data-table"           $F   # → должен быть хук
grep -c "modal-scrim"          $F   # есть модалка?
grep -c "data-modal"           $F   # → должен быть триггер
grep -c "tile--accordion"      $F ; grep -c "tile__toggle"   $F
grep -c "class=\"tabs\|segctrl" $F ; grep -c "data-tabs\|data-segctrl" $F
grep -c "riskmetric"           $F   # риск-метрика — только data-riskmetric
grep -c "data-popover"         $F
```

Компонент есть, хука нет — блокер Б13. Полная таблица соответствий —
`.opencode/skills/screen-assembly/references/runtime-hooks.md`.

Обратная проверка: `grep -n "<script" $F` — тегов должно быть один-два.
`ds.js` обязателен; второй допустим только под данные конкретного экрана.
Самописный обработчик того, что уже умеет рантайм ДС (открытие модалки,
сворачивание тайла, переключение табов), — блокер.

### Хук стоит — это ещё не значит, что поведение работает (Л32–Л34)

`grep` выше проверяет разметку, а не поведение. Сортировка таблицы прожила
в репозитории мёртвой при полностью правильной разметке: рантайм искал класс,
которого нет нигде в ДС. Поэтому ключевое поведение экрана **прогоняется**:

```bash
# один раз на машину, в скратчпад (НЕ в репозиторий): npm i linkedom
node <тест>.mjs   # parseHTML(экран) → загрузить рантаймы → dispatchEvent('click') → сверить DOM
```

`linkedom` — чистый JS-DOM, не браузер: запрет §9 `ds-rules.md` на скриптовый
браузер он не нарушает, в репозиторий ничего не попадает.

Два правила прогона, без которых он бесполезен:

1. **Грузить ВСЕ рантаймы, которые есть на странице, без заглушек.** Рантаймы
   ДС дописывают разметку внутрь чужих слотов — `ds-tooltip.js` кладёт в ячейку
   копию значения, и `textContent` ячейки перестаёт быть значением. Дефект
   существует только в связке; тест с заглушкой проверяет несуществующую
   страницу (Л33, Л34).
2. **Сверять состояние ПОСЛЕ клика, а не факт клика:** глиф, класс состояния,
   `aria-*` и — если поведение меняет данные — порядок/состав узлов.

Человеку остаётся только то, что действительно требует рендера: пиксели, тени,
скролл, фактический overflow. Это называется явно; «не проверяется» пишется
только про то, что пробовали проверить.

## Каскад CSS и живость — общие правила для любых страниц

Эти проверки добавлены по итогам реальных приёмок (29.08.2026): статическая
чистота разметки не гарантирует, что компонент отрисуется так, как задумано.

| # | Проверка |
|---|---|
| К1 | **Класс-модификатор не переопределяет `display` панелей.** `.splitpane--app` (`splitter.css`) переводит `.splitpane__a/b` в `display:block` и ломает flex-раскладку (нет скролла, центрирования, якорей). На страницах с кастомной flex-раскладкой панелей `.splitpane--app` — блокер; панели должны получать `display:flex!important` |
| К2 | **`segctrl` в flex-колонке не растянут.** `align-items:stretch` (по умолчанию) растягивает сегмент-контрол на всю ширину — серый трек уходит за сегменты. Требуется `align-self:flex-start` (иначе трек «как у табов») |
| К3 | **Скролл и якоря реально работают** — не «по разметке». Скролл-контейнер обязан быть ограничен по высоте (`flex:1; min-height:0; overflow-y:auto`); панель, растянутая на контент (`scrollHeight == clientHeight` у скролл-контейнера), — признак сломанной flex-цепочки |
| К4 | **«Файл ДС изменён» — не по одному mtime.** Дата файла может быть старше/новее сессии без правок (например, запись в навигацию добавлена до начала работ). Сверяй содержимое и контекст задания, прежде чем объявлять блокер «файл ДС тронут» |
| К5 | **Не объявлять «мёртвое» до чтения `*.page.js` страницы.** Кнопки-копирования (`data-copy-target`), контролы конструктора, редлайны часто оживляет page.js страницы (`initCopy`, `initPlayground`). Сначала найди обработчик в page.js — потом вердикт |
| К6 | **Порядок скриптов важен.** Рантаймы (`ds-*.js`) → `page.js` → общий слой (`docs-split.js`). Если общий/страничный скрипт подключён раньше рантайма и читает его состояние в момент события — читает устаревшее. Переключение панелей по `data-`-атрибуту кнопки — норм, по `aria-selected` в клике — подозрительно |
| К7 | **`@import` по `file://` не считается подключением.** Стиль «подключается через `@import` из pg-kit.css» — НЕ достаточное подключение для страниц, открываемых двойным кликом. Нужны явные `<link>` на странице |
| К8 | **Подпись свитча в конструкторе статична — не меняется от положения.** Свитч называет опцию действием в On-состоянии («Показывать проценты») и не переименовывается при выключении («Скрыть проценты»). Словарь `DS_SPLIT_SWITCH_LABELS` — статичная строка или `{ label, on? }`, но не `{ on, off }`; переключение свитча не должно менять текст его подписи (правило Switch, 30.08.2026) |
| К9 | **Свитч в конструкторе с непустой подписью, и это штатный `pg-toggle`.** (а) Бинарный селект, из которого сделан свитч, обязан иметь подпись в `.lbl` (не `.ds-label` — docs-split.js читает только `.lbl`); свитч с пустым текстом — блокер (урок NavTile). (б) Кастомная кнопка-тумблер `button.toggle` с `aria-pressed` в конструкторе — блокер: бинарная опция должна быть бинарным селектом, который docs-split.js конвертирует в `pg-toggle` (урок «свитчи ДС») |
| К10 | **В `<style>` страницы нет остатков старой (до docs-split) flex-раскладки конструктора.** `.pg__controls { … flex-wrap / flex:1 1 … / grid-template … }`, `.pg__controls .ctl { flex:1 1 … }`, `.pg__widthctl { flex:1 1 … }` — в колонке `.ctl-col` растягивают поля по высоте (огромные отступы). При раскатке такие правила удаляются; остаются только живые page-стили контролов (урок Pagination) |
| К11 | **Групповые заголовки конструктора (`.pg__grouphead`) следуют за своими контролами.** Они не должны оставаться прямыми детьми `#pg-controls` стопкой вверху без содержимого: docs-split.js переносит в `.ctl-col` все прямые дети в исходном порядке; заголовок группы предшествует её контролам (урок ReadOnlyField) |
| К12 | **Главная таблица экрана занимает всю свободную высоту** (правило каркаса Layout/Table). Если таблица — единственный/основной блок страницы (реестр): на `.screen` стоит `.screen--app`, на `.dtable` — `.dtable--fill`; тело таблицы ограничено по высоте и скроллится внутри (`flex:1; min-height:0` у контейнера и тела), тулбар/футер закреплены. Таблица высотой «по числу строк» на реестре-экране — отклонение от правила (кроме случаев с тайлами над/под, разбираемых индивидуально) |
| К14 | **Дефект прошёл мимо сторожа, который обязан был его поймать — сначала проверь, ВИДИТ ли сторож нужные данные.** Правило может существовать, быть верным и не срабатывать, потому что его вход срезан: `ds-lint.js` вырезал `<script>` из разметки, и классы, которые страница рисует своим `*.page.js`, правилу A2 были не видны — так прожил урок Л41 (`.dvd` при неподключённом `divider.css`). Это отдельный класс: не «правила нет» (К13/Л42) и не «копии разошлись» (Л43), а **«правило есть, вход усечён»** (Л48). Процедурное правило «проверять руками», написанное вместо починки входа, маскирует дефект инструмента и обрекает класс дефектов на повтор |
| К13 | **Заявленное спека-правило подтверждается реализацией в рантайме ДС, а не только наличием в документации/разметке.** Если спека/чит-шит обещают поведение «из коробки» (крестик очистки по значению, свёртка чипов «+N», тултип усечённой подписи, маска даты), а в `scripts/ds-*.js` реализации нет — это дефект «правило записано, кода нет» (Л42): компонент живёт дефолтным, демо может иллюстрировать несуществующее. Поиск реализации — `grep` по `scripts/ds-*` на класс/механизм. Также: одно правило не должно иметь несколько владельцев-копий (Л43) — почти одинаковые реализации в двух рантаймах — NEEDS-WORK. Дефект общего механизма чинится в слое, а не точечно в компоненте (Л44) |

## Журнал уроков (обязательно к чтению)

Перед приёмкой прочитай `references/lessons.md` рядом с этим файлом — это
журнал выявленных дефектов (симптом → причина → правило). Все правила выжимки
применяются как блокеры, даже если они не продублированы в чек-листах выше.
Диапазон номеров здесь не перечисляется — состав читается по самому файлу
(перечисление уже разъезжалось с фактом: тут стояло «Л42–Л45», в выжимке —
«Л42–Л47», а Л46 и Л47 в неё не входили).

**Новый дефект, которого нет в журнале, — опиши в отчёте форматом «урок»**:
`симптом → причина → правило/блокер` **плюс строка «Закрепление»** — во что
урок должен превратиться. Уровни закрепления, выбор между ними и форма якоря
(`линтер:B11`, `сенсор:Б24`, `чек-лист:К3`, `аудит:4`) описаны в скилле
`lessons` (`.opencode/skills/lessons/SKILL.md`) — единственном владельце
процедуры. Здесь их не перечисляют: второй список расходится с первым молча,
и это ловит `lessons-cli check` находкой `Л-ВЛАДЕЛЕЦ`.

Самый сильный уровень закрепления **проверяется откатом**, а не наличием
строки в файле: правило, которое не падает на воспроизведённом дефекте, —
это Л42 («правило записано, кода нет») в новом обличье. Проверяет это команда:

```bash
node .opencode/skills/screen-review/tooling/lessons-cli.mjs verify
node .opencode/skills/screen-review/tooling/lessons-cli.mjs coverage
```

`verify` гоняет пары фикстур «дефект/эталон» (`tooling/fixtures/`): закрыл урок
сторожем — заведи пару, иначе закрепление не засчитано. `coverage` показывает,
чем закрыт каждый пункт этого чек-листа: сторожем, суждением (с причиной,
почему статикой не ловится) или «посильно, но не написано» — последний список
и есть очередь работ, он обязан уменьшаться.

## Проверка страниц документации (паттерн `docs-split`)

Ряд **К** (каскад раскатки) проверяет не сенсор, а линтер — правилами ряда `R`
(`ds-lint.js`). Причина в предмете: сенсор принимает экран, страницу
документации он отвергает на каркасных проверках Б1/Б5, и до К-правил дело не
доходит (урок Л71). Чем закрыт каждый пункт — печатает `lessons-cli coverage`,
здесь это не перечисляется.

Страницы `DS-IBP/pages/**` (организмы/молекулы/атомы), переведённые на паттерн
«сплиттер + табы», проверяются по `screen-review` с учётом особенностей:

- **Механику не перечитывать — прогони `node DS-IBP/scripts/ds-check.mjs <страница>`**
  (линтер + структурные проверки + headless-живость; для не-docs-split страниц —
  только линтер). Токены на механикy тратить не надо: она вся в команде.
  Глазами — только суждение (композиция, смысл, контент, отклонения);

- подключения: явные `splitter.css`, `segment-control.css`, `tab.css`,
  `docs-split.css`; рантаймы `ds-splitter.js`, `ds-tabs.js`, `docs-split.js`;
  НЕ должно быть `ds-toc.js`, `ds-toc.css`, `pg-kit.js`;
- `main.page` обязан иметь класс `ds-split`; без него общий слой не активируется;
- три таба (Документация/Конструктор/Код) — на едином контейнере `.docs-layout`
  (одинаковая ширина и центрирование); `.constructor-panel`/`.code-panel-wrap`
  в разметке паттерна быть не должно;
- конструктор: бинарные параметры → свитчеры `pg-toggle`, остальные — селекты;
  SegmentControl в конструкторе — блокер (конвенция 29.08.2026);
  **у свитча не должно быть отдельного лейбла сверху** — подпись свитча
  самодостаточна («Показывать тулбар», не «Тулбар» + «Показывать»);
  правило компонента Switch (29.08.2026);
  **подпись свитча статична** — не меняется от положения (К8): свитч
  называет опцию действием в On-состоянии и не переименовывается при
  выключении; словарь `DS_SPLIT_SWITCH_LABELS` — строка или `{ label, on? }`;
  **подпись свитча не пуста, источник подписи — `.lbl`** (К9);
  **в `<style>` нет остатков `.pg__controls { flex-wrap/flex:1 1 … }`** (К10);
  **`.pg__grouphead` следует за своими контролами** (К11);
  **две колонки**: справа (`.toggles`) — свитчи/чекбоксы/радио/слайдеры,
  слева (`.ctl-col`) — селекты/инпуты; только один тип — в левой колонке;
  группы (`.ctl-group`) сохраняются, правила внутри каждой группы;
  слайдер — без `ctl--span` (не на всю ширину);
- вкладка «Код»: исходники статично в `<script type="text/plain" id="src-code-*">`,
  подсветка `tk-*` применена;
- **`src-code-css` сверен с файлом стилей диффом, а не «по наличию блока»** (урок
  Л24): после любой правки `styles/*.css` компонента `src-code-css` обязан быть
  перегенерирован тулчейном `docs-split.mjs inject <page> --css DS-IBP/styles/<файл>.css`
  и совпадать с файлом по содержимому (новые правила футера/состояний — в эталоне);
- `html { scrollbar-gutter: stable }` на страницах паттерна — стабильная ширина
  при переключении табов (иначе скачок ~15px).

## Полнота относительно ТЗ

Если путь к ТЗ известен — пройди по нему пункт за пунктом и заполни:

- реализовано;
- реализовано с допущением (какое именно допущение);
- **не реализовано** (почему).

Ненайденный в экране пункт ТЗ — это не мелочь: он идёт в отчёт отдельной
строкой. Молча сузить объём нельзя.

## Формат вывода

```
ВЕРДИКТ: PASS | NEEDS-WORK

БЛОКЕРЫ
1. <строка N> — <что не так> → <как чинить>

ЗАМЕЧАНИЯ
1. ...

ПРОПУЩЕНО ИЗ ТЗ
- ...
```

Пустые разделы не выводить. Каждая претензия — с номером строки и цитатой.
Претензия без цитаты дефектом не считается.
