# Журнал уроков — выжимка (curated)

Читать ПЕРЕД каждой приёмкой и перед сборкой/раскаткой. Каждая запись —
`симптом → причина → правило/блокер`. Накопленные правила применяются как
блокеры, даже если не продублированы в чек-листах SKILL.

## Механизм двухуровневого журнала (решение 31.08.2026)

- **`lessons-raw.md`** — архив всех уроков (append-only). Новый дефект
  описывается форматом «урок» в отчёте ревьюера → ai-designer дописывает
  его в **raw** сразу, ничего не отбрасывая.
- **этот файл** — кураторская выжимка. Раз в неделю ai-designer выбирает
  из raw самые важные по **весу**: тяжесть (блокер > замечание),
  повторяемость, не закрыт ли уже сенсором/чек-листом (закрыт — из выжимки
  убирается). Минимум 1, максимум не ограничен. «1 правило в неделю» из
  плейбука Harness Engineering — описание зрелости, а НЕ квота: сигнал
  зрелости — замедление прироста, когда основные failure-классы закрыты.
- Стоп-маркеры «принято, не переоткрывать» остаются в выжимке всегда.

## Правила-блокеры (применять при приёмке)

### Л1. Свитч без подписи (К9)
- **Симптом:** свитч в конструкторе без текста.
- **Причина:** подпись контрола создана через `.ds-label__text`, а `docs-split.js` читает подпись свитча только из `.ctl > .lbl` → `labelName=''`.
- **Правило:** подпись бинарного селекта — ОБЯЗАТЕЛЬНО `.lbl`. Свитч с пустой подписью — блокер.

### Л2. Остатки старой flex-раскладки в `<style>` (К10)
- **Симптом:** поля левой колонки конструктора разъехались с огромными промежутками.
- **Причина:** в `<style>` остались `.pg__controls .ctl { flex:1 1 180px }`, `.pg__controls { flex-wrap }`, `.pg__widthctl { flex:1 1 260px }` — в колонке `.ctl-col` `flex-grow:1` растягивает каждое поле на всю высоту.
- **Правило:** при раскатке удаляются ВСЕ остатки старой раскладки конструктора; остаются только живые page-стили контролов.

### Л3. `.pg__grouphead` не следует за своими контролами (К11)
- **Симптом:** заголовки групп стопкой вверху `#pg-controls`, под ними пусто; контролы уехали в `.ctl-col`.
- **Правило:** `docs-split.js` переносит в `.ctl-col` ВСЕ прямые дети `#pg-controls` в исходном порядке; заголовок группы предшествует контролам своей группы.

### Л4. Кастомные кнопки-тумблеры вместо свитчей (К9)
- **Симптом:** самописные `button.toggle` с рамкой и `aria-pressed` в конструкторе.
- **Причина:** легаси-хелперы page.js (`sw`/`toggle`/`ctlToggle`).
- **Правило:** бинарная опция — бинарный селект (`['no','Нет']/['yes','Да']`), `docs-split.js` конвертирует его в штатный `pg-toggle`. Кастомный тумблер — блокер.

### Л8. `toggles labels` пусто, хотя свитчи созданы
- **Причина:** харнесс брал первый вложенный `.toggles` группы «Опции», маскирующий правую колонку.
- **Правило:** в диагностике искать `:scope > .toggles`. Исправлено в diag-harness.js.

### Л9. Ложные FAIL при параллельном `ds-check`/`verify`
- **Причина:** headless Chrome с общим `--user-data-dir` — профиль блокируется первым процессом.
- **Правило:** `ds-check`/`verify` — ТОЛЬКО последовательно.

### Л10. Диагностика вне папки страницы ломает относительные пути
- **Причина:** копия в другую папку ломает `../../DS-IBP/styles/…`.
- **Правило:** временная копия — ТОЛЬКО в ту же папку (как делает `verify`); chrome-путь через `DS_CHROME`; зависшие headless-процессы чистить перед прогоном.

### Л11. Общий слой устойчив к вариациям страниц
- **Правило:** `docs-split.js`, харнесс и тулчейн проектируются под вариации (подпись из `.lbl` или `.ds-label`, групповые заголовки, вложенные контейнеры), а не под один эталон.

### Л12. pg-kit.css не нужен страницам docs-split
- **Правило:** на docs-split странице pg-kit.css не подключается вовсе; живые правила контролов — в `docs-split.css`; `.icnpick`/`.readout`/`.seg`, если нужны, — локально в `<style>`. pg-kit.css остаётся только для НЕ раскатанных страниц.

### Л13. Раскатка тулчейном требует ручного дозаполнения
- **Правило:** каждый атом после `scaffold` требует: словарь `DS_SPLIT_SWITCH_LABELS`, `src-code-js` (иначе code-out js=0 — блокер приёмки), проверку отсутствия легаси `.toggle`/`.seg`; мёртвые легаси-стили в `<style>` удалять (К10).

### Л14. Пилот не освобождает от полного цикла
- **Правило:** пилотная страница проходит ТУ ЖЕ приёмку, что и батч; конвенция конструктора проверяется одинаково.

### Л23. Страничный CSS не переопределяет состояния компонентов
- **Симптом:** подложка выделения пропала у пункта — `button.<класс>{background:none}` (0,1,1) перебил `.<класс>--selected` (0,1,0).
- **Правило:** собственный `<style>` экрана — только раскладка; без `button.<класс>`/`a.<класс>`/`input.<класс>` и сбросов background/display/color у класса компонента. Состояние задаётся данными, а не параллельным CSS. (Б21 + сенсор layout-check Б21; ds-rules §4.)

### Л24. src-code-css вкладки «Код» обновляется только тулчейном
- **Симптом:** после правки `styles/*.css` вкладка «Код» показала старый CSS (новых правил нет).
- **Правило:** после любой правки `styles/*.css` раскатанной страницы — `docs-split.mjs inject <page> --css …` и сверка диффом по содержимому (не «по наличию блока»). (Приёмка docs-split.)

### Л25. Бандл витрины живёт своей копией page.js
- **Симптом:** карточка в `index.html` (через `_ds_bundle.js`) показывала старое имя пункта после переименования в `*.page.js`.
- **Правило:** при изменении `*.page.js` страниц витрины пересобирать `_ds_bundle.js`/`_ds_manifest.json` тем же заходом; компилятор недоступен — зафиксировать остаток в отчёте (не блокер).

### Л26. Экран обязан сбрасывать body { margin: 0 }
- **Симптом:** белая рамка 8px по периметру (UA-дефолт `body{margin:8px}`), панель/контент разъехались, вклад в горизонтальный скролл.
- **Правило:** любой экран начинается с копии `templates/screen/Screen.html` (body-reset уже есть); при ручной сборке — обязателен `body { margin: 0 }`. (Б22 + сенсор layout-check Б22.)

### Л27. Классы документационного слоя на экране мертвы
- **Симптом:** `<p class="desc tight">` на экране не стилизуется (дефолтный `<p>`).
- **Правило:** только классы, доступные через `ds.css` (компоненты + фундамент); `.desc`/`.tight`/`.panel`/`.masthead`/`.lead`/`.eyebrow`/`.claim`/`.note`/`.bullets`/`.rules`/`.guide`/`.subhead` — док-слой, на экран не переносить. (Б23 + сенсор layout-check Б23.)

### Л28. Обёртка рантайма отключает усечение у правильной разметки
- **Симптом:** текст в ячейке идёт в одну строку без многоточия и уезжает под соседнюю колонку, хотя `.tc__text--truncate` стоит и CSS верен.
- **Правило:** обёртка, которую рантайм вставляет ВОКРУГ свёрстанного элемента (`.tip-anchor` у `ds-tooltip.js`), обязана быть раскладочно прозрачной: `max-width: 100%` и, для flex, `min-width: 0`. Дефект не виден по разметке экрана и чинится только в ДС — правки на экране бесполезны. Ловится линтером (B9). (Tooltip 2.005.)

### Л29. Компонент с усечением подписи, который не умеет сжиматься
- **Симптом:** чип обрывается посреди слова без многоточия, ровно по границе соседней ячейки.
- **Правило:** это не «узкая колонка», а несжимаемый элемент. Компонент с усекаемой подписью обязан высказаться: `min-width: 0` (сжимается), `flex: none`/`flex-shrink: 0` (не сжимается намеренно) или запись в `SHRINK_OK` с причиной. Ловится линтером (B8). (Chip 1.010.)

### Л30. Правило, поставленное ради одного варианта, действует на все
- **Симптом:** в таблице на треках `fr` колонка растягивается под самый длинный текст, усечение не срабатывает, хвост колонок недостижим.
- **Правило:** `min-width: max-content` нужен только строке прокручиваемой таблицы (`.tbl--scroll .tbl__row`, `.dtable__body .tbl__row`) — там он держит скролл-диапазон для закрепления колонок; на всех строках он ломает доли-треки. Правка ради одного варианта компонента проверяется и на остальных. (TableCell 2.011.)

### Л31. Идентификатор — не число
- **Симптом:** «Номер сделки» свёрстан с `tc--numbers` (правый край, tabular-nums).
- **Правило:** идентификатор (номер сделки, ИНН, № договора, код) выравнивается по ЛЕВОМУ краю — его не сравнивают по столбцу и не суммируют. `tc--numbers` — только для величин: суммы, доли, количества, проценты. Уточняет З4 `screen-review` и таблицу выравниваний `layout-composition/references/tables.md`. (Инвариант TableCell 2.010.)

## Стоп-маркеры (принятые отклонения — не переоткрывать)

### Л5. `data-pg-keep-select` — инертный маркер
- Оставлен как смысловая метка, нигде не обрабатывается. НЕ полагаться; при раскатке новых страниц не добавлять. Существующие вхождения не удалять.

### Л6. Нативные segctrl в конструкторе (ReadOnlyField)
- НЕ блокер: page.js строит конструктор на нативных SegmentControl'ах компонента; конвенция «без segctrl» запрещает КОНВЕРТАЦИЮ селектов, здесь селектов нет.

### Л7. Чекбоксы `.cb` и слайдеры в левой колонке
- Задокументированное отклонение, не блокер: `docs-split.js` конвертирует в свитчи только бинарные селекты. Улучшение правой колонки — отдельная задача общего слоя.
