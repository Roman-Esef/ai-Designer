# Корпус фикстур линтера — экраны

**Не удалять.** Это не проба и не заготовка: файлы здесь — вход для
доказательства правил линтера откатом (`lessons-cli verify`). Удаление папки
означает, что пять правил (A7, F6, L4, L5, L6) перестают быть доказанными, а
`verify` начинает падать.

Почему корпус лежит вне `DS-IBP/`: линтер считает экраном путь, начинающийся с
`pages/screens/` или с `../` — то есть файл **вне** дерева `DS-IBP/`. Эти пять
правил внутри `DS-IBP/fixtures/` не срабатывают никогда, и доказывать их там
значило бы доказывать на входе, который им не вход.

Почему здесь, а не в `Concepts/` или `Projects/`: это оснастка, а не экран
продукта и не концепт. До 15.09.2026 корпус лежал в песочнице `Projects/test/`,
которую удалили. Имя папки `fixtures` в пути обязательно — по нему журнал
прогонов (`runlog.mjs`) не пишет фикстуры. Корпус сенсора в соседних файлах
папки `fixtures/` эту подпапку не читает: `verify` обходит каталог без
вложенных.

| Файл | Что доказывает |
|---|---|
| `_base.ok.html` | эталон: ни одно из пяти правил не срабатывает |
| `A7.bad.html` | рантайм подключён мимо `ds.js` |
| `F6.bad.html` | таблица на экране без `.th__resize` |
| `L4.bad.html` | экран переопределяет `padding` у `.screen__content` |
| `L5.bad.html` | порог раскладки на `@media` |
| `L6.bad.html` | экран задаёт `margin` блоку ДС в своём `<style>` |

Каждая пара отличается от эталона ровно одним дефектом. Прогон:

```bash
node .opencode/skills/screen-review/tooling/lessons-cli.mjs verify --corpus lint
```

Правила ведения корпуса — `.opencode/skills/lessons/SKILL.md`, раздел
«Закрепление доказывается откатом».
