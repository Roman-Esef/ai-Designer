# Реестры и таблицы

Композиция здесь — это **порядок и ширина колонок**, плотность строки и то, что
стоит над таблицей.

## Порядок колонок

Слева направо — по убыванию значимости для решения:

1. **Идентификатор строки** — то, по чему пользователь узнаёт запись (код, номер,
   наименование). Всегда первым, при горизонтальном скролле закрепляется.
2. **Колонки принятия решения** — то, по чему сравнивают и оценивают строки
   (статус, сумма, дата, ответственный).
3. **Метаданные** — служебное, что смотрят редко (кем создано, когда изменено).
4. **Действия по строке** — последними, справа.

Колонка, которую никто не сортирует и не читает, — кандидат на удаление или
перенос в карточку записи, а не в таблицу.

## Выравнивание

| Тип данных | Выравнивание | Почему |
|---|---|---|
| Текст, наименования | по левому краю | читается сверху вниз одним столбцом |
| Числа, суммы, проценты | **по правому краю** | разряды выстраиваются друг под другом, размеры сравнимы взглядом |
| Даты | по левому краю (при фиксированном формате) | |
| Статусы-чипы, иконки | по левому краю | |
| Действия | по правому краю | |

Числа — моноширинные цифры и единый формат разрядов внутри колонки.

## Ширина колонок

- Ширина по ожидаемому содержимому, а не поровну: короткая дата не должна
  занимать столько же, сколько наименование.
- Длинный текст в ячейке — обрезка с многоточием и тултипом, а не перенос в
  несколько строк (иначе строки таблицы разной высоты и сканирование ломается).
- Горизонтальный скролл допустим только внутри тела таблицы, не у всего экрана.

## Над таблицей

Порядок сверху вниз: заголовок и счётчик записей → фильтры → действия над
выборкой. Не смешивать фильтрацию и действия в одну строку, если их больше
двух-трёх.

Фильтры, применяемые часто, — на виду; редкие — за кнопкой «Ещё фильтры».
Применённые фильтры показывать чипами, чтобы было видно, почему список короткий.

## Плотность

Плотная строка (компактный режим) — по умолчанию для реестров, с которыми
работают много часов: больше строк на экран, меньше скролла. Просторный режим —
когда в строке несколько уровней информации или превью.

## Пустые состояния

Различать:
- **нет данных вообще** — объяснить, как завести первую запись;
- **ничего не найдено по фильтрам** — предложить сбросить фильтры.

Это разные сообщения; общая заглушка «Нет данных» на оба случая — ошибка.
