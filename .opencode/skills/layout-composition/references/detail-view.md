# Карточка сущности (detail view) — режим чтения

Сводный экран по одному объекту: сделка, клиент, инструмент, договор.
Пользователь **сканирует**, а не заполняет. Правило «форма в одну колонку»
здесь **не действует** — оно про ввод.

## Раскладка

- Поля внутри тайла — **в несколько колонок** (2–4 по ширине тайла). Одна колонка
  только в узком тайле (3–4 колонки сетки).
- Цель — уместить ключевое **без скролла**; вертикальный поток не нужен.
- Длинные поля (описание, комментарий) — на всю ширину тайла, обычно последними
  в своём тайле, чтобы не разрывать сетку коротких полей выше.

## Структура экрана

| Зона | Содержание |
|---|---|
| Шапка | название объекта, его код, статус, метка последнего изменения, главные действия |
| Ряд 1 | идентификация и состояние: стороны (клиент/эмитент/контрагент), текущая стадия |
| Середина | условия и параметры по возрастанию детализации: коммерческие → технические |
| Далее | связанные наборы: платежи, транши, инструменты — обычно таблицей на 12 колонок |
| Низ | сопровождение: команда, документы, история |

## Типовые ошибки

| Ошибка | Признак | Что делать |
|---|---|---|
| Все тайлы на 12 колонок | экран — длинная лента, много скролла, справа пусто | раздать 4/6/8 по объёму контента |
| Все тайлы одинаковой ширины «для порядка» | в одном пусто, в другом тесно | ширина от объёма, а не единообразия |
| Поля в одну колонку по привычке от форм | половина тайла пустая справа | 2–3 колонки |
| Длинный текст в ряду с короткими полями | текст обрезан или соседи уехали | на всю ширину |
| Порядок блоков скопирован из ТЗ | важное для роли внизу, служебное вверху | пересобрать по частоте обращения |

## Действия блока

- **Стрелка-переход** — на отдельный экран сущности (полный список, карточка).
- **Карандаш** — редактирование блока (открывает форму → режим ввода, см.
  `forms.md`).
- Нет ни того, ни другого — блок только для чтения.

Иконка перехода **во внешнюю систему** отличается от перехода внутри продукта
(диагональная стрелка против прямой).
