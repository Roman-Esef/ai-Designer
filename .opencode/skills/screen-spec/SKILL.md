# Спецификация экрана — `<Имя>.screen.md`

Шаблон целиком: `.opencode/skills/screen-spec/references/template.md` — прочитай
его инструментом `read` и заполняй по нему.

## Кто это читает

Не человек, а следующий агент — разработчик, который свяжет HTML с боевой ДС
корпоративного контура и её токенами и отдаст в разработку. Поэтому файл пишется
как **данные, а не как проза**:

- таблицы вместо абзацев;
- явные имена компонентов ДС так, как они называются в `DS-IBP/specs/_index.md`;
- явные классы и токены, а не описания «серый фон», «крупный заголовок»;
- одно утверждение — одна строка таблицы.

## Правила заполнения

1. **Файл лежит рядом с HTML** и называется так же:
   `Projects/test/DealRegistry.html` → `Projects/test/DealRegistry.screen.md`.

2. **YAML-шапка обязательна** — по ней экран находят автоматически.
   Поле `components` перечисляет все использованные компоненты ДС.

3. **Каждый блок контента описан строкой таблицы**: что за блок, каким
   компонентом собран, сколько колонок из 12 занимает, что внутри.

4. **Каждая колонка таблицы описана строкой**: ключ, заголовок, тип данных,
   ширина, выравнивание, сортируемость, участие в фильтре.

5. **Поведение описывается парой «триггер → результат»**, без ссылок на код.
   Пример: «Двойной клик по строке → открывается модальное окно
   «Редактирование заявки» (`.modal--w6`) с данными этой строки».

6. **Раздел «Открытые вопросы» не удаляется никогда.** Если вопросов нет —
   строка «Открытых вопросов нет». Всё, что было принято допущением, а не
   взято из ТЗ, попадает сюда явно, с пометкой «допущение».

7. **Не выдумывать предметную область.** Если из ТЗ неясно, что означает поле,
   откуда берётся значение или какие бывают статусы, — это строка в «Открытых
   вопросах», а не придуманное описание. Придуманное описание неотличимо от
   факта и уедет в разработку как требование.

8. **Тексты интерфейса выписываются отдельно** — заголовки, подписи кнопок,
   плейсхолдеры, пустые состояния, тексты ошибок. Русский, без англицизмов,
   в инфинитиве для действий («Добавить», «Выгрузить», не «Добавление»).

## Что не пишется в screen.md

- CSS и JS-код — он в HTML;
- рассуждения о том, почему выбран компонент;
- пересказ содержимого ТЗ своими словами без структуры;
- React/Vue/Angular API — спецификация не привязана к фреймворку.
