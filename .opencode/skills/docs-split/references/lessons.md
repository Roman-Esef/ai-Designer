# Уроки раскатки docs-split

Читать перед раскаткой страницы документации и перед её приёмкой. Записи
целиком, с историей, — в архиве `screen-review/references/lessons-raw.md` под
теми же номерами.

---

### Л9. Ложные FAIL при параллельном `ds-check`/`verify`
- **Причина:** headless Chrome с общим `--user-data-dir` — профиль блокируется первым процессом.
- **Правило:** `ds-check`/`verify` — ТОЛЬКО последовательно.

### Л10. Диагностика вне папки страницы ломает относительные пути
- **Причина:** копия в другую папку ломает `../../DS-IBP/styles/…`.
- **Правило:** временная копия — ТОЛЬКО в ту же папку (как делает `verify`); chrome-путь через `DS_CHROME`; зависшие headless-процессы чистить перед прогоном.

### Л11. Общий слой устойчив к вариациям страниц
- **Правило:** `docs-split.js`, харнесс и тулчейн проектируются под вариации (подпись из `.lbl` или `.ds-label`, групповые заголовки, вложенные контейнеры), а не под один эталон.

### Л12. pg-kit.css не нужен страницам docs-split
- **Правило:** на docs-split странице pg-kit.css не подключается вовсе; живые правила контролов — в `docs-split.css`; `.icnpick`/`.readout`/`.seg`, если нужны, — локально в `<style>`. pg-kit.css остаётся только для НЕ раскатанных страниц.

### Л13. Раскатка тулчейном требует ручного дозаполнения
- **Правило:** каждый атом после `scaffold` требует: словарь `DS_SPLIT_SWITCH_LABELS`, `src-code-js` (иначе code-out js=0 — блокер приёмки), проверку отсутствия легаси `.toggle`/`.seg`; мёртвые легаси-стили в `<style>` удалять (К10).

### Л14. Пилот не освобождает от полного цикла
- **Правило:** пилотная страница проходит ТУ ЖЕ приёмку, что и батч; конвенция конструктора проверяется одинаково.

### Л24. src-code-css вкладки «Код» обновляется только тулчейном
- **Симптом:** после правки `styles/*.css` вкладка «Код» показала старый CSS (новых правил нет).
- **Правило:** после любой правки `styles/*.css` раскатанной страницы — `docs-split.mjs inject <page> --css …` и сверка диффом по содержимому (не «по наличию блока»). (Приёмка docs-split.)
