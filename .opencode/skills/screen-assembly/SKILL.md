# Сборка экрана на IBP DS

Готовые куски разметки лежат рядом:

- `.opencode/skills/screen-assembly/references/skeleton.html` — каркас файла целиком,
  начинай с копии;
- `.opencode/skills/screen-assembly/references/patterns.md` — рецепты: крошки, шапка,
  ряды тайлов, таблица, модалка, пустое состояние;
- `.opencode/skills/screen-assembly/references/runtime-hooks.md` — какие атрибуты
  ставить, чтобы компоненты работали, а не просто выглядели.

Прочитай их инструментом `read` перед тем, как писать код.

## 1. Каркас: что где лежит

Любой экран продукта состоит из трёх зон:

```
.nav-layout
├── nav.nav.nav--rail          боковое меню, фиксировано, 56px
└── .screen                    рабочая область (контейнер для @container-запросов)
    ├── nav.crumbs             крошки, залипают сверху, высота 44px
    └── main.screen__content   контент, поля 24px по бокам и снизу, зазор блоков 24px
        ├── .phead             PageHeader — всегда первый блок
        └── ...                дальше блоки контента в один поток
```

Инварианты, которые нельзя нарушать:

- отступов между меню и рабочей областью нет, между крошками и контентом нет;
- поля 24px задаёт `.screen__content` — экран их не переопределяет;
- зона крошек (44px, поля 24px) принадлежит компоненту Breadcrumbs;
- скроллится **только контент**: вертикальный скролл экрана получается сам,
  ничего для него писать не нужно;
- **горизонтального скролла у экрана не бывает никогда.** Элемент, вылезший за
  правую границу, — дефект. Скролл внутри себя допускается только у тела
  таблицы и у отдельного тайла.

## 2. Порядок сборки

1. Скопируй `references/skeleton.html` в `Projects/test/<Имя>.html`.
2. Замени `<title>`.
3. Заполни крошки путём из ТЗ.
4. Собери PageHeader: заголовок, статус, действия.
5. Собери контент: ряды тайлов и/или таблицу.
6. Допиши модальные окна, если они есть в ТЗ, — в конец `body`, с `hidden`.
7. **Проставь хуки рантаймов** по `references/runtime-hooks.md` — без них экран
   выглядит собранным, но не работает.
8. Прогони скилл `screen-review`.

## 3. Крошки

Последний элемент — текущая страница, не ссылка. Путь берётся из ТЗ; если в ТЗ
пути нет — спроси, не выдумывай иерархию разделов.

## 4. Шапка страницы (PageHeader)

Собирается из независимых опциональных частей: иконка слева, заголовок, кнопка
переименования, чипы статуса, кнопка возврата, подзаголовок с мета-данными,
действия.

Правила:

- заголовок — `h1`, единственный на экране;
- **статус экрана — это чип в `.phead__chips`**, не текст и не бейдж;
- действий максимум 3 кнопки размера M; главное действие — `btn--accent`,
  остальные — `btn--outline`; четвёртое и далее уезжают в кнопку «Ещё действия»
  (`btn--icon-only` с глифом `more-dots`);
- заголовок никогда не усекается многоточием.

## 5. Сетка: сколько колонок занимает блок

Контентная область — **12 резиновых колонок, зазор 16px**. Раскладка ряда — `.tile-row`
(это готовый grid на 12 колонок), ширина блока — `style="grid-column:span N"`.

Как выбрать N:

| Что в блоке | N | Раскладка ряда |
|---|---|---|
| Таблица, широкая форма, длинный список | 12 | один блок в ряду |
| Основной блок + боковая панель | 8 + 4 | два блока |
| Два равнозначных блока | 6 + 6 | два блока |
| Три карточки-показателя | 4 + 4 + 4 | три блока |
| Четыре метрики | 3 + 3 + 3 + 3 | четыре блока |

Сумма `span` в одном ряду = 12. Если в ТЗ размеры не заданы — считай по
количеству полей: блок на 2 поля в строке — 4 колонки, на 3 поля — 6, форма
на 4 поля в строке — 8 или 12.

**Тайлы в одном ряду равны по высоте** — это делает сам `.tile-row`, руками
ничего дописывать не нужно. Если два тайла должны стоять друг под другом в одной
колонке ряда — оберни их в `.tile-stack`.

Перестроение на узком окне считается **от ширины рабочей области**, не окна
(закреплённое меню отнимает 216px, не меняя вьюпорт):

```css
@container screen (max-width: 1240px) { .col-4 { grid-column: span 6 } }
```

## 6. Тайлы

Тайл = TileHeader + необязательный Alert + контент.

- Заголовок тайла — `h3.tile__title`; подзаголовок и чипы — опции.
- Действия тайла — 1–3 штуки в `.tile__actions`, обычно IconButton размера M.
- Поля внутри тайла — компонент ReadOnlyField (`.rof`) в сетке `.tile__grid`.
- Тайл без шапки — `.tile--headless`; сворачиваемый — `.tile--accordion`
  (работает сам, нужен только `.tile__toggle`).
- **Собственных hover-состояний у тайла нет.** Тайл не кликается целиком.

## 7. Таблицы

Table — это обёртка: тулбар сверху, прокручиваемое тело с липкой шапкой, футер
с пагинацией. Строки и ячейки строит TableCell.

Что нужно понять из ТЗ и отразить:

| Требование ТЗ | Как собирается |
|---|---|
| Заголовок и счётчик записей | `.dtable__toolbar-left`: `.dtable__title` + `.dtable__count` |
| Фильтр | компонент TableFilter в `.dtable__toolbar-right` + модалка фильтра |
| Сортировка колонки | `.th` с `aria-sort` и кнопкой `.th__sort`; активна максимум одна колонка |
| Настройка колонок | Modal `--w4`; ширину тянет ручка `.th__resize` — ставится в каждой `.th` всегда, работает из коробки (`tbl-resize.js` в `ds.js`) |
| Выбор строк | колонка с Checkbox, классы `.th--select`/`.tc--select`; при выборе — панель `.pgn-bulk` |
| Действия в строке | отдельная колонка «Действия»; кнопки видны всегда, если это основное действие, или в `.tc__hidden`, если появляются по наведению |
| Кнопка в строке открывает окно | `data-modal="<id скрима>"` на кнопке — модалка откроется по-настоящему |
| Двойной клик по строке открывает окно | двойной клик рантайм не отслеживает: повесь `data-modal` на кнопку действия в строке, а само правило опиши в `<Имя>.screen.md`, раздел «Поведение» |
| Пагинация | `.dtable__footer` → `.pgn-row` |
| Числа | `.tc--numbers` — даёт и правое выравнивание, и моноширинные цифры |

Высота строки фиксирована — 48px. Каждая строка начинается и заканчивается
служебной ячейкой-разделителем `.tc--separator` (в шапке `.th--separator`).
Ширины колонок задаются на строке: `style="grid-template-columns:8px 2fr 1fr 96px 8px"`
— **одинаково у шапки и у всех строк**, иначе колонки разъедутся.

Состояния hover/focus/selected живут **на строке** (`.tbl__row--selected`), не на
ячейке.

## 8. Модальные окна

- Ширина — шагами колонок: `.modal--w3` (подтверждение), `--w6` (форма, фильтр),
  `--w4` (настройка колонок).
- Обязательны шапка с заголовком и крестиком и подвал с главной кнопкой справа.
- Варианта в одну колонку не существует.
- В статичном мокапе модалку кладут в конец `body` с атрибутом `hidden`, а
  триггер помечают `data-modal="<id скрима>"` — рантайм `ds.js` свяжет их сам.
  Если надо показать модалку открытой на мокапе — убери `hidden`.

## 9. Контент: рисуем, а не заглушаем

- Таблица — минимум 6–8 строк правдоподобных данных.
- Суммы — `1 240 500,00`, разряды неразрывными пробелами; даты — `ДД.ММ.ГГГГ`.
- Названия — реальные по форме: «ООО «ЮгСтрой»», «ПАО «Газпром»», «D-007».
- Никаких `Lorem ipsum`, `TODO`, `здесь будет`.
- Пустое состояние рисуется компонентом EmptyState, а не пустым `div`.

## 10. Интерактив: макет должен работать

Экран — не скриншот. Подключённый `DS-IBP/scripts/ds.js` оживляет компоненты сам, если
в разметке стоят хуки: поповер риск-метрики раскрывается, панель навигации
сворачивается и закрепляется, тайл-аккордеон складывается, модалка открывается
и закрывается по Esc, таблица сортируется, колонки тянутся, табы переключаются,
тултипы всплывают.

Полная таблица «что работает само / что требует атрибута / что только из кода» —
в `references/runtime-hooks.md`. Проставь хуки и пройдись по экрану списком:
каждый интерактивный компонент → его строка в таблице → атрибут на месте?

**Свой JavaScript при этом не пишется.** Исключение одно: в задании явно
попросили поведение, которого в рантаймах ДС нет. Тогда — отдельным тегом сразу
после `ds.js` и как можно короче.

Чего рантаймы не дают вообще (это модель данных, а не ДС): реальная фильтрация
строк, пересчёт пагинации, сохранение, переходы между экранами. Такое
показывается вёрсткой в нужном состоянии, а правило описывается словами в
`<Имя>.screen.md`.

## 11. Компоненты в flex-раскладках (общие правила)

Уроки реальных приёмок (29.08.2026): компонент «выглядит собранным», но его
ломает контекст раскладки. Проверяй перед сдачей:

| Ситуация | Правило |
|---|---|
| Пара панелей со сплиттером | **Не использовать `.splitpane--app`**: его правило (`splitter.css`) переводит `.splitpane__a/b` в `display:block` и ломает flex-раскладку — нет скролла, центрирования, якорей. Если нужна тень — своя, отдельным правилом; панели — `display:flex!important` |
| SegmentControl в flex-колонке | `align-items:stretch` растягивает трек на всю ширину (серый хвост за сегментами). Ставить `align-self:flex-start` на `.segctrl` |
| Переключение вьюх/табов в одном скролл-контейнере | Скроллбар документа то появляется, то исчезает — ширина контента прыгает (~15px). Стабилизируется `html { scrollbar-gutter: stable }` |
| Скролл-контейнер | Обязан быть ограничен по высоте: `flex:1; min-height:0; overflow-y:auto`. Если панель растянулась на контент (`scrollHeight == clientHeight` у контейнера) — flex-цепочка сломана |

Порядок скриптов на страницах с общим слоем: рантаймы (`ds-*.js`) → `page.js`
страницы → общий слой (например, `docs-split.js`). Обработчик, читающий
состояние рантайма в момент события, регистрируется при парсинге и срабатывает
раньше рантайма — читает устаревшее значение. Переключение табов/панелей делай
по `data-`-атрибуту кнопки, клавиатуру — через `setTimeout(0)`.

Для страниц, открываемых двойным кликом (`file://`): не полагаться на `@import`
внутри CSS — подключать `DS-IBP/styles/*.css` явными `<link>`; `fetch` по `file://` с
не-ASCII путём не работает — данные вставлять статично в страницу.

## 12. Чего в файле быть не должно

- `<svg>` в разметке экрана (только `<i data-icon>`);
- `#rrggbb`, `rgb()`, `px` в цветах и типографике;
- подключение `DS-IBP/styles/*.css` и `DS-IBP/scripts/ds-*.js` поштучно;
- самописные обработчики того, что уже умеет рантайм ДС;
- классы, которых нет в чит-шите;
- **селекторы вида `button.<класс>` / `a.<класс>` / `input.<класс>` и любые сбросы
  `background`/`display`/`color` у класса компонента** — они по специфичности
  перебивают состояния компонента (`--selected`/`--disabled`/`:hover`/`[aria-current]`),
  подложка выделения и ховер пропадают. Разметку и состояние бери из чит-шита
  дословно и задавай данными, а не параллельным CSS (правило ds-rules.md §4).
