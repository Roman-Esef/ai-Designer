# Хуки рантаймов — чтобы макет работал

Экран подключает `DS-IBP/scripts/ds.js` одним тегом. Он догружает **все** рантаймы ДС.
Каждый рантайм ищет свою разметку сам и молча ничего не делает, если её нет.

Значит вопрос не «подключить ли скрипт», а **«поставил ли я атрибут»**.

Свой JavaScript при этом не пишется. Ты ставишь хук — поведение приходит из ДС.

## Работает само, хук не нужен

| Компонент | Что работает | Условие |
|---|---|---|
| NavPanel | бургер сворачивает и разворачивает панель, пин переключает drawer ↔ fixed, подписи в rail всплывают тултипом | есть `.nav` |
| Tile · аккордеон | сворачивание и разворачивание, `aria-expanded`, событие `tiletoggle` | `.tile--accordion` + кнопка `.tile__toggle` |
| Table · тень липкой шапки | тень-разделитель под шапкой, когда тело проскроллено вниз (`.dtable--scrolled`) | есть `.dtable__body` |
| TableCell · ширина колонки | перетаскивание правой границы шапки, минимум 96px, стрелки ← → шагом 16px | `.th__resize` последним ребёнком **каждой** `.th` (кроме `.th--separator`) — ставится всегда, это базовое поведение таблицы |
| TableCell · порядок колонок | перетаскивание колонки за подпись шапки, место вставки — линия `--primary` | есть `.th__label` — работает само, маркер не нужен (исключаются только разделители; закреплённые переносятся) |
| Tab | roving tabindex, стрелки, Home/End внутри группы | есть `.tab` |
| ButtonGroup · toggle | эксклюзивное или независимое переключение | `.btn-group--toggle` + `.btn[aria-pressed]` |
| AllocationBar | подсветка связанных сегментов и строк | `.albar__seg` / `.albar__row` + `[data-hover]` |

## Нужен атрибут

| Что должно работать | Хук | Куда ставится |
|---|---|---|
| Модальное окно открывается и закрывается | `data-modal="<id скрима>"` | на кнопку-триггер; сам скрим лежит в конце `body` с `hidden` |
| Кнопка закрытия внутри модалки | `data-modal-close` | на кнопку |
| Модалка с несохранённым вводом (клик по скриму не закрывает) | `data-modal-guarded` | на скрим |
| Диалог поверх открытой модалки | `data-modal-nested` | на вложенный скрим |
| Поповер раскрывается по клику | `data-popover="<id поповера>"` | на триггер |
| Риск-метрика: чип + поповер собираются сами | `data-riskmetric` + `data-risk` `data-zone` `data-rating-date` `data-zone-date` `data-segment` `data-profile` | на пустой `<span>` — рантайм строит содержимое |
| Сортировка колонок, выбор строк, дерево, тултип усечения | `data-table` на `.tbl` + `data-sort` на кнопке сортировки | на таблицу и на кнопки `.th__sort`. Тултип рантайм вешает сам на `.tc__text--truncate`, `.th__label` и `.chip__label` внутри ячейки — своей разметки тултипа на экране не пишут (Table 1.009) |
| Закрепление колонок (тогл + нативный `position: sticky`: left у левого края, right-хвостовой блок у правого; сепаратор прилипает) | клик по `.th__pin`; классы `.th--pinned`/`.tc--pinned`; закреплённые перетаскиваемы | делегирование `tbl-pin.js` + `tbl-reorder.js` (в `ds.js`); разметить `.th__pin` в шапке и `.th--pinned`/`.tc--pinned` на закреплённых — поведение само |
| Раскрытие дерева в таблице | `data-node` / `data-parent` | на строки |
| Пагинация строится сама | `data-pagination data-total="800" data-page="3" data-page-size="50"` | на пустой `<div>` в футере |
| Табы и сегмент-контрол переключаются | `data-tabs` или `data-segctrl` | на контейнер группы |
| Переполнение горизонтальных табов уходит в меню «Ещё» | `data-tabs-overflow="menu"` | на контейнер табов |
| Тултип по наведению | `data-tooltip="Текст"` | на любой элемент |
| Тултип только при обрезанном тексте | `data-tooltip` + `data-tooltip-truncated="only"` | на элемент с усечением |
| Длинный текст в тултипе переносится, а не усекается повторно | `data-tooltip-multiline="yes"` | на ту же цель; без него тултип шире `--tip-max` (280px) сам уходит в многоточие (Tooltip 2.005) |
| Контекстное меню и MenuButton | `data-menu="<id меню>"` | на триггер; меню — `.menu.menu--floating` с `hidden` |
| Крошки сворачиваются в «…» при нехватке ширины | `data-breadcrumbs` | на `.crumbs` |
| Лишние кнопки шапки уходят в меню «Ещё» | `data-actions-overflow` | на `.phead__actions` |
| Сплиттер тянется | `data-splitter` + `data-min` `data-max` `data-initial` | на `.splitpane` |

Тонкая настройка поповера, меню и тултипа — атрибутами `-placement`, `-align`,
`-gap`, `-flip`, `-boundary` (например `data-popover-placement="bottom"`).
Точные значения — в блоке компонента в чит-шите.

## Инициализируется только из кода

Эти компоненты из разметки сами не поднимаются. На макете они рисуются
**в нужном состоянии вёрсткой**: выпадающий список — отрисованным открытым,
уведомление — отрисованным на своём месте.

| Компонент | Почему |
|---|---|
| DropdownList, Select, автокомплит | нужен `DSDropdownList.bind(field, {...})` со списком данных |
| Toast, SnackBar | показываются вызовом `DSToast.show(...)` / `DSSnack.show(...)` |
| Chart | строится из данных вызовом рантайма |
| Копирование значения в ReadOnlyField | `DSCopy.write(...)` на обработчике |

Если в задании прямо просили, чтобы такой компонент работал, — это тот редкий
случай, когда допустим свой короткий скрипт **отдельным тегом сразу после
`ds.js`**. По умолчанию — вёрстка в нужном состоянии.

## Чего рантаймы не делают вообще

Это модель данных потребителя, а не дизайн-системы:

- реальная фильтрация и поиск по строкам;
- пересчёт страниц при смене фильтра;
- сохранение изменений, отправка форм, переходы между экранами;
- подгрузка данных.

Такое показывается вёрсткой в нужном состоянии, а поведение описывается словами
в `<Имя>.screen.md`, раздел «Поведение».

## Частая ошибка

Поставить компонент правильно и забыть хук. Внешне экран выглядит собранным,
а при клике ничего не происходит — и это не видно, пока не откроешь в браузере.

Поэтому после сборки пройди по своему экрану списком: каждый интерактивный
компонент → его строка в таблицах выше → атрибут на месте?
