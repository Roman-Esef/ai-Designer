# ai-designer — агент-дизайнер для opencode

Что это: настройка **opencode** (агентный CLI для корпоративного контура,
работает на DeepSeek / Qwen и любых других моделях), которая превращает ТЗ
в собранный на дизайн-системе IBP экран.

Собирать ничего не нужно — opencode сам находит эти файлы, когда запускается
из корня репозитория.

---

## 1. Как это устроено

Вы работаете **с одним агентом — `ai-designer`**. Он выбирается один раз и
дальше сам решает, кого из специалистов подключить под задачу. Переключать
агентов вручную не нужно.

```
                    ВЫ
                     │
              ┌──────▼──────┐
              │ ai-designer │   ← единственный агент, который выбирается вручную
              │  (primary)  │     говорит с вами, задаёт вопросы, отвечает за итог
              └──┬───┬───┬──┘
                 │   │   │        вызывает субагентов инструментом task
     ┌───────────┘   │   └───────────┐
     ▼               ▼               ▼
┌──────────────┐ ┌──────────────┐ ┌────────────────┐
│ ux-researcher│ │screen-builder│ │screen-reviewer │
│  (subagent)  │ │  (subagent)  │ │   (subagent)   │
│ база знаний  │ │ сборка экрана│ │ приёмка, PASS  │
└──────────────┘ └──────────────┘ └────────────────┘
```

Три маршрута, которые `ai-designer` запускает сам:

| Маршрут | Что происходит |
|---|---|
| Собери экран | вопросы вам → `screen-builder` → `screen-reviewer` → результат |
| Исследуй и собери | `ux-researcher` → показ выжимки вам → дальше как выше |
| Проверь экран | `screen-reviewer` → вердикт |

**Почему субагентам нужны подробные задания.** Субагент не видит ваш разговор
с `ai-designer` — он получает только текст задания и начинает с нуля. Поэтому
в промпте `ai-designer` отдельно прописано, что в задание обязательно кладутся
пути к файлам, принятые решения и границы работы. Если субагент делает не то,
почти всегда дело в задании, а не в самом субагенте.

## 2. Что где лежит

| Файл | Что делает | Кто читает |
|---|---|---|
| `.opencode/opencode.json` | конфигурация: права на файлы и команды, подключение правил. Модели здесь нет — см. раздел 4 | opencode при старте |
| `AGENTS.md` (в корне репозитория) | короткие правила проекта и карта `.opencode/`; открытый формат, читается и другими агентными CLI | opencode при старте |
| `.opencode/rules/ds-rules.md` | подробные правила ДС: карта репозитория, запреты, каталог компонентов | подключается через `instructions`, попадает в контекст всегда |
| `.opencode/agents/ai-designer.md` | **ведущий агент** — маршрутизация и разговор с вами | opencode |
| `.opencode/agents/screen-builder.md` | субагент: собирает экран | вызывается `ai-designer` |
| `.opencode/agents/screen-reviewer.md` | субагент: приёмка, ничего не правит | вызывается `ai-designer` |
| `.opencode/agents/ux-researcher.md` | субагент: выжимка из базы знаний продукта | вызывается `ai-designer` |
| `.opencode/commands/screen.md` | команда `/screen` | opencode |
| `.opencode/commands/screen-check.md` | команда `/screen-check` | opencode |
| `.opencode/commands/research.md` | команда `/research` | opencode |
| `.opencode/commands/concepts.md` | команда `/concepts` — несколько концептов текстовыми спеками | opencode |
| `.opencode/commands/handoff.md`, `resume.md` | команды `/handoff` и `/resume <Задача>` — перенос контекста между сессиями через `Concepts/<Задача>/<Задача>.handoff.md` | opencode |
| `.opencode/skills/ds-lookup/` | как искать компоненты в ДС, не сжигая контекст | агент, по своему решению |
| `.opencode/skills/screen-assembly/` | пошаговая сборка; в `references/` — каркас, рецепты разметки, **хуки рантаймов** | агент |
| `.opencode/skills/screen-spec/` | формат `<Имя>.screen.md` + шаблон | агент |
| `.opencode/skills/screen-review/` | **чек-лист приёмки** и оснастка: сенсор `layout-check.mjs`, `lessons-cli.mjs` (журнал уроков, фикстуры, итоговая проверка `gate`) | агент |
| `.opencode/skills/layout-composition/`, `composition-review/` | композиция и сетка экрана, её приёмка | агент |
| `.opencode/skills/concept-design/` | шкала «консервативно ↔ концептуально» и формат `<Имя>.concept-<A\|B\|C>.md` | агент |
| `.opencode/skills/lessons/` | самообучение: урок → закрепление → доказательство откатом | агент |
| `.opencode/skills/docs-split/` | раскатка страниц документации ДС под «сплиттер + табы» | агент |
| `.opencode/skills/knowledge-lookup/` | путь к базе знаний, карта её папок, правила поиска и подключения | агент |
| `.opencode/skills/session-plan/` | смета контекстного окна до старта (`ctx-budget.mjs`), паспорт этапов, границы сессий | агент, в начале крупной задачи |
| `Concepts/<Имя>/` | сюда складываются готовые экраны (папка концепта) | — |
| `index.html`, `hub.js` (корень) | хаб проектов и его реестр: одна точка входа в ДС, проекты и концепты | человек, агент дописывает запись реестра |

**Почему конфиг в `.opencode/`, а не в корне.** opencode читает проектный
конфиг из обоих мест: `opencode.json` / `opencode.jsonc` в корне и те же
файлы в `.opencode/` (проверено на 1.18.30). Слой `.opencode/` грузится
позже и перекрывает корневой. Вся настройка агентов держится в одной папке,
поэтому конфиг один — `.opencode/opencode.json`. Второй файл в корне не
заводить: права начнут складываться из двух слоёв, и запрет, снятый в одном
из них, никто не увидит. Гейт это ловит (шаг `agent-config`).

Относительные пути в `instructions` opencode ищет от папки запуска вверх, а
не от места конфига, поэтому `.opencode/rules/ds-rules.md` записан от корня
репозитория.

**Разница между агентом, скиллом и правилами.**
*Правила* (`ds-rules.md`) — в контексте всегда, поэтому короткие.
*Агент* — роль и порядок работы, загружается при выборе или вызове агента.
*Скилл* — инструкция, которую агент подгружает сам, когда доходит до нужного
шага; так тяжёлые детали не занимают контекст всё время. Это важно для
DeepSeek и Qwen с их окном контекста.

## 3. Как запускать

```bash
cd "путь к репозиторию ДС"
opencode
```

Дальше:

| Способ | Как |
|---|---|
| Выбор агента | `Tab` → выбрать `ai-designer`. Он единственный в списке — остальные субагенты и вручную не выбираются |
| Собрать экран | `/screen DS-IBP/uploads/ТЗ-реестр-сделок.md` |
| Исследовать, потом собрать | `/research DS-IBP/uploads/ТЗ-реестр-сделок.md` |
| Проверить готовое | `/screen-check Concepts/DealRegistry/DealRegistry.html` |
| Несколько концептов до сборки | `/concepts DS-IBP/uploads/ТЗ-реестр-сделок.md` |
| Посчитать смету захода | `node .opencode/skills/session-plan/tooling/ctx-budget.mjs --stage build --tz <ТЗ> --cheat Table,Modal --out-lines 900` — строка `ВЕРДИКТ:` |
| Посмотреть состав этапов | `node .opencode/skills/session-plan/tooling/ctx-budget.mjs --stages` |
| Сверить смету с фактом захода | `node .opencode/skills/session-plan/tooling/ctx-budget.mjs --calibrate --stage build --fact <токенов>` + аргументы сметы |
| Сохранить контекст / продолжить в новой сессии | `/handoff` · `/resume DealRegistry` |
| Закрыть заход | `node .opencode/skills/screen-review/tooling/lessons-cli.mjs gate` — строка `ВЕРДИКТ:` |
| Проверить хаб проектов | `node .opencode/skills/screen-review/tooling/projects-hub.mjs` — реестр `hub.js`, страницы вне реестра и ссылки на хаб, строка `ВЕРДИКТ:` (в гейте — шаг `projects`) |
| Просто спросить | пишите словами: «есть ли в ДС компонент для…», «чем Chip отличается от Badge» |

Скриншот макета прикладывается в сообщение как файл — если выбранная модель
умеет смотреть картинки. DeepSeek-Chat картинки не понимает; в этом случае
описывайте макет текстом или используйте мультимодальную модель.

Результат: папка концепта `Concepts/<Имя>/` — `<Имя>.html` открывается
двойным кликом в браузере (или с хаба `index.html`), `<Имя>.screen.md` уходит
агенту-разработчику.

**Как посмотреть, что делает субагент.** Когда `ai-designer` запускает
субагента, создаётся дочерняя сессия. Войти в неё — `Leader + Down`, дальше
переключаться стрелками, вернуться наверх — `Up`.

## 4. Как подключить модель

Модель в `.opencode/opencode.json` намеренно не задана — её выбирают под
контур. Провайдер и имя модели на каждой машине свои: дома — публичный API, на
рабочем контуре — корпоративная копия у другого провайдера. Если в репозитории
записать пару «провайдер/модель», которой на машине нет, opencode не
переключится на модель по умолчанию, а остановится с ошибкой
`Model not found`. Поэтому гейт краснеет на ключах `model`, `small_model`,
`provider` и `agent.<имя>.model` в конфиге репозитория (шаг `agent-config`).

**Куда писать модель — в глобальный конфиг машины**:
`~/.config/opencode/opencode.json`. Точный путь на своей машине печатает
`opencode debug paths` (строка `config`). Этот файл грузится первым, проектный
конфиг его дополняет, а модель не перекрывает — её там нет.

Если модель не задана нигде, opencode берёт последнюю выбранную командой
`/models` (запоминает её между сессиями), а если такой нет — модель
провайдера по умолчанию. Итоговую конфигурацию показывает
`opencode debug config`.

**Публичный DeepSeek или Qwen:** авторизоваться командой `opencode auth login`,
затем дописать в глобальный конфиг:

```json
{
  "model": "deepseek/deepseek-chat"
}
```

**Внутренний шлюз корпорации** (OpenAI-совместимый API — самый частый случай),
тоже в глобальный конфиг:

```json
{
  "provider": {
    "corp-gateway": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Внутренний шлюз",
      "options": {
        "baseURL": "https://llm.corp.local/v1"
      },
      "models": {
        "deepseek-v4-flash": { "name": "DeepSeek V4 Flash" }
      }
    }
  },
  "model": "corp-gateway/deepseek-v4-flash"
}
```

Идентификаторы моделей должны совпадать с тем, что возвращает
`GET /v1/models` вашего шлюза. Другие модели шлюза (Qwen, GLM) — ещё строки в
`models`, переключение командой `/models`. Ключ — в переменной окружения или
через `opencode auth login`.

**Разные модели под разные роли.** Субагент без своей настройки работает на
модели того агента, который его вызвал. Чтобы развести — допишите в тот же
глобальный конфиг `"agent": { "screen-reviewer": { "model": "corp-gateway/…" } }`.
Не в шапку файла агента: `.opencode/agents/` уезжает вместе с репозиторием, и
модель, которой нет на другой машине, остановит роль. Разумная раскладка:
сборку (`screen-builder`) отдать более сильной модели, приёмку
(`screen-reviewer`) — дешёвой и быстрой.

## 5. Права: что агент может, а что нет

В `.opencode/opencode.json` прописано:

- **писать** без подтверждения агенты `ai-designer` и `screen-builder` могут
  только в `Concepts/**` (плюс `hub.js` у ведущего агента) — любая попытка
  тронуть `DS-IBP/styles/`, `DS-IBP/scripts/`, `DS-IBP/specs/`, страницы компонентов вызовет запрос
  подтверждения. Это защита ДС от модели, которая «решила подправить токен»;
- **читать** разрешено всё в репозитории, но **только в нём**: пути вне
  рабочей директории закрыты. Ключ `external_directory` оставлен пустым — это
  заготовленная точка для будущего репозитория базы знаний (см. раздел 6);
- **вызывать субагентов** (`task`) разрешено — без этого оркестрация не
  работает;
- **удалять файлы** (`rm`) и `git push` запрещены полностью;
- **интернет** (`webfetch`) отключён — для закрытого контура;
- безопасные команды (`ls`, `grep`, `sed -n`, `cat`, `find`) разрешены без
  подтверждения, остальные спрашивают;
- `"share": "disabled"` — выгрузка переписки на opencode.ai запрещена,
  `"autoupdate": false` — обновления не тянутся из интернета. Оба пункта под
  корпоративный контур; на личной машине их можно снять.

Если подтверждения мешают на потоке, запускайте `opencode --auto` — тогда
разрешается всё, кроме явных запретов (`rm`, `git push`, `webfetch` и запись
вне `Concepts/`).

## 6. Как это дорабатывать

**Появился новый компонент в ДС.** Ничего править не нужно: агент читает
`DS-IBP/specs/_index.md` и `DS-IBP/specs/_cheatsheet.md`, которые вы и так обновляете.
Разве что дописать имя в каталог в `.opencode/rules/ds-rules.md`, раздел 6, —
это ускоряет подбор. Если у компонента есть рантайм с хуком — добавьте строку
в `.opencode/skills/screen-assembly/references/runtime-hooks.md`.

**Появились локальные компоненты проекта** (тайл «КНР», «Финансовые метрики»).
Заведите отдельный скилл: `.opencode/skills/local-components/SKILL.md` с
`name: local-components` (имя папки и поле `name` обязаны совпадать) и опишите
там, где эти компоненты лежат и когда их брать вместо общих. Агент подхватит
скилл автоматически — в код агента лезть не нужно.

**Появился репозиторий базы знаний.** Он живёт **отдельно от этого
репозитория** — в ДС её материалов нет и не будет. Чтобы подключить, нужны две
правки, обе описаны в `knowledge-lookup/SKILL.md`, приложение «Как подключить
репозиторий»:

1. `.opencode/opencode.json` → `permission.external_directory` — сейчас там пустой
   объект, это заготовленная точка расширения:

   ```json
   "external_directory": { "~/ibp-knowledge/**": "allow" }
   ```

   Путь пишется абсолютным или от домашней папки; относительный `../…` здесь
   не разворачивается.

2. `knowledge-lookup/SKILL.md` → строка `KB = <путь не задан>` в начале файла.

Больше нигде путь не зашит. Требования к самим файлам базы (YAML-шапка, одна
тема — один файл, пометка «факт / гипотеза», запрет на проценты при выборке
1–5 человек) — там же, в приложении «Требования к файлам».

**Нужен новый специалист** (например, агент UX-копирайтинга). Добавьте файл
в `.opencode/agents/` с `mode: subagent` и внятным `description` — по нему
`ai-designer` поймёт, когда звать. Затем допишите строку в таблицу «Твоя
команда» в `ai-designer.md` и, если нужно, новый маршрут.

**Агент делает что-то не так.** Правится текстом, не кодом:
- путает компоненты → дополните «Частая путаница в именах» в `ds-lookup/SKILL.md`;
- халтурит с контентом → усильте «Контент: рисуем, а не заглушаем» в
  `screen-assembly/SKILL.md`;
- макет не кликается → проверьте `references/runtime-hooks.md`;
- пропускает проверку → добавьте пункт в блокеры `screen-review/SKILL.md`;
- субагент делает не то → почти всегда виновато задание: усильте раздел
  «Главное про субагентов» в `ai-designer.md`.

Правило то же, что и в самой ДС: разобрали инцидент — тем же заходом впишите
класс ошибки в чек-лист, иначе он повторится.

**Проверить, что opencode всё увидел:** `/agents` покажет список агентов,
`/skills` — список скиллов. Скилла нет — проверьте, что файл называется
`SKILL.md` заглавными и что `name` в шапке совпадает с именем папки.

## 7. Известные ограничения

- **Макет живой, но не приложение.** Штатное поведение компонентов работает:
  поповеры, модалки, аккордеоны, сортировка, табы, тултипы, сворачивание
  панели навигации. Не работает то, что относится к данным: реальная
  фильтрация строк, пересчёт пагинации, сохранение, переходы между экранами.
  Такое описано словами в `<Имя>.screen.md`.
- **Репозитория базы знаний ещё нет.** Маршрут «Исследуй и собери» вернёт
  честный пустой результат. Это задумано: выдумывать пользователей по
  интерфейсу агенту запрещено. Когда репозиторий появится — две правки из
  раздела 6, кода трогать не нужно.
- Слабые модели плохо держат длинные файлы. Если экран получается очень
  большим — просите собирать его частями (сначала каркас и шапка, потом
  таблица, потом модалки).
- Точность вёрстки по скриншоту у DeepSeek/Qwen ниже, чем у топовых моделей.
  Приёмка для них не формальность, а необходимый шаг — поэтому `ai-designer`
  и не имеет права её пропустить.
