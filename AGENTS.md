# IBP — правила для opencode

Этот файл читает **opencode** из корня воркспейса `aiDesigner`. Он намеренно
короткий: подробные правила вынесены в `.opencode/rules/ds-rules.md`
(подключается через `instructions` в `.opencode/opencode.json`).

`AGENTS.md` — открытый формат файла правил, его читают и другие агентные CLI.
Поэтому здесь только то, что верно для любого инструмента; всё, что специфично
для opencode, живёт в `.opencode/opencode.json`. Модель там не задаётся — она
своя на каждом контуре и прописывается в глобальном конфиге машины.

## Папка `.opencode/` — обязательное чтение для любого агента

Настройка лежит в `.opencode/`, но правила ДС, роли и чек-листы в ней **не
зависят от инструмента**. Не читать их — значит работать по догадкам.

| Что | Где | Когда читать |
|---|---|---|
| Подробные правила ДС | `.opencode/rules/ds-rules.md` | всегда, в начале задачи, целиком |
| Роли и порядок работы | `.opencode/agents/*.md` | по роли текущей задачи |
| Сценарии команд | `.opencode/commands/*.md` | когда пользователь пишет `/screen`, `/screen-check`, `/research`, `/concepts`, `/handoff`, `/resume` |
| Пошаговые инструкции | `.opencode/skills/*/SKILL.md` | когда дошёл до соответствующего шага |
| Самообучение | `.opencode/skills/lessons/SKILL.md` | когда в заходе что-то сломалось и починилось |
| Права и границы | `.opencode/opencode.json` | перед записью файлов |

## Самообучение

Заход, в котором что-то сломалось и починилось, заканчивается уроком с полем
**«Закрепление»** — во что урок превратился: сторож, пункт чек-листа или
«неизмеримое» с указанием, что именно требует рендера. Закрепление уровня
«исполняемое» доказывается откатом (`lessons-cli verify`), а не наличием
строки в файле, а форму записи проверяет `lessons-cli check` (БЛОКЕР 0).
Процедура — скилл `lessons`, здесь она не пересказывается.

Проверки в конце захода — одна команда `lessons-cli gate`: гоняет только
сторожей того, что изменилось, строка `ВЕРДИКТ:` идёт в отчёт. Контекст между
сессиями — `/handoff` и `/resume <Задача>` (файл `Concepts/<Задача>/<Задача>.handoff.md`).

Если инструмент не подключает агентов и скиллы из `.opencode/` сам — роль и
скилл берутся **чтением файла**, а не выбором в интерфейсе.

## Структура воркспейса

```
aiDesigner/
├── index.html          ← хаб проектов: одна точка входа в ДС, проекты и концепты
├── hub.js              ← реестр хаба: одна запись на проект или концепт
├── .opencode/          ← агенты, скиллы, команды, правила (этот файл рядом)
├── DS-IBP/             ← дизайн-система: токены styles/, спеки specs/, страницы pages/
├── Projects/           ← файлы, соответствующие настоящей системе; строго на ДС
│   └── post/           ← проект направления Post (локальные компоненты — в post_local_components/)
└── Concepts/           ← концепты на ДС; сюда же агент кладёт собранные экраны
    └── <Имя>/          ← папка концепта: <Имя>.html + <Имя>.screen.md
```

**Projects или Concepts.** В `Projects/` — только то, что соответствует
настоящей системе, строго на компонентах ДС. В `Concepts/` — концепты: тоже на
ДС, а кастомные решения допустимы, только когда ТЗ прямо их просит. Проверки
одинаковы для обеих папок; осознанное отклонение от ДС по ТЗ записывается в
«Открытые вопросы и допущения» спеки экрана.

**Новый проект или концепт — запись в `hub.js`**, а строка пользователя в
футере меню его экранов ведёт на хаб. Оба правила проверяет гейт (шаг
`projects`); формат записи — шапка `hub.js`.

## Что это за репозиторий

Дизайн-система IBP: **ванильный HTML/CSS, без React**. Источник истины — токены
в `DS-IBP/styles/*.css`, классы компонентов и страницы документации в
`DS-IBP/pages/`.

## Главное правило

Ничего не выдумывать. Цвет, размер, отступ, радиус, шрифт, класс, имя иконки —
только из дизайн-системы. Нет нужного — спросить, а не изобрести.

## Агенты

Ведущий агент — **`ai-designer`** (единственный, который выбирается вручную).
Он говорит с пользователем и распределяет работу по субагентам:
`ux-researcher` (база знаний продукта), `screen-builder` (сборка экрана),
`screen-reviewer` (приёмка). Субагентов вручную не выбирают.

Команды: `/screen` — собрать экран, `/research` — сначала исследование,
`/screen-check` — приёмка готового, `/concepts` — несколько концептов
интерфейса текстовыми спеками (скилл `concept-design`), `/handoff` — сохранить контекст задачи,
`/resume <Задача>` — продолжить задачу в новой сессии.

Если инструмент не показывает этих агентов списком — прочитай файл
`.opencode/agents/<роль>.md` и работай по нему сам, в той же сессии. Субагент
запускается только по прямой просьбе пользователя.

Результат сборки — папка концепта `Concepts/<Имя>/`: `<Имя>.html` +
`<Имя>.screen.md` и запись в `hub.js` (`group: 'concepts'`).

## Макет живой

Экран подключает `../../DS-IBP/scripts/ds.js` — все рантаймы ДС работают, если в
разметке стоят их хуки (`data-table`, `data-modal`, `data-tabs`, `data-popover`,
`data-riskmetric` и т.д.). Свой JavaScript вместо рантайма ДС не пишется.
Таблица хуков — `.opencode/skills/screen-assembly/references/runtime-hooks.md`.
